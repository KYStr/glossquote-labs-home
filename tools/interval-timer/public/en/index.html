    How the schedule and timer work

    The schedule starts with a prepare segment (when prepare seconds are above 0), then each round's work segment and rest segment in order; a rest segment appears only when rest seconds are above 0 and the round is not the last one, or the final-rest option is set to include. Zero-length segments are always omitted. Total time equals prepare seconds plus rounds times work seconds, plus the number of rest segments times rest seconds.

    The timer core only consumes active milliseconds: paused time never counts, and resuming continues from the paused reading. Remaining seconds are always shown rounded up, so a segment never shows 0 early; a reading exactly on a boundary belongs to the next segment. The downloaded report is always named interval-timer-report.json and holds the result as compact JSON, with object keys sorted recursively by UTF-16 code units and one trailing newline.

    Frequently asked questions

    Do I rest after the final round?
    That is decided by the “Rest after the final round” option, skipped by default; choose “Include” to add one more rest segment after the final round.
    Does the timer keep running while paused?
    No. The timer core only consumes active milliseconds, so paused time never counts; resuming continues from the paused reading.
    Are segment changes announced?
    Yes. A segment change shows and announces the new segment name, and plays a short cue tone when the device allows audio; the program-end tone is longer.
