Encoding and merging rules and limits
  • The target URL is required, at most 2048 characters; each UTM value is at most 200 characters raw and at most 100 characters after trimming. Lengths are counted in UTF-16 code units.
  • Source, medium and campaign are required; term and content are optional and are omitted when blank after trimming. Values are not lowercased or slugified; case is kept as typed, then encoded.
  • Each value is encoded with encodeURIComponent semantics: a space is always %20, never +; the only unencoded characters are A–Z a–z 0–9 - _ . ! ~ * ' ( ); everything else is percent-encoded, including / → %2F, ? → %3F, & → %26, = → %3D, # → %23, + → %2B; non-ASCII characters are UTF-8 encoded first, with uppercase hex digits; a % in a value is encoded as %25 without pre-decoding.
  • An existing query string is kept verbatim first, with UTM parameters appended after & in the fixed order source, medium, campaign, term, content; an empty existing query leaves no empty segment. An existing fragment is kept verbatim after the UTM parameters. No slash is added and no case normalization is applied.
  • A target URL that already contains any utm_* parameter is rejected, never overwritten. The URL must be http or https, have a host, and carry no username or password; this tool does not visit or verify the target URL.
  • Data stays in the current page draft only; leaving or switching language discards it. Nothing is stored or uploaded.

FAQ

Are spaces encoded as +?

No, spaces are always encoded as %20.

What if the target URL already has query parameters?

They are kept verbatim first, with UTM parameters appended; if it already contains a utm_* parameter the build is rejected instead of overwriting it.

Does this shorten the URL or track performance?

No, it only builds the link; it sends no request, shortens nothing and records nothing.

Does a preset overwrite my campaign name?

No, a preset only fills source and medium and clears term and content; campaign is left untouched.
