How it is calculated, and the input formats

The simple lumen method: total lumens = area × target illuminance. Total lumens are rounded half-up (exactly 0.5 always rounds up) to a whole number; the bulb count rounds up from that rounded total, so the total lumens, lumens per bulb and bulb count shown can be checked against each other; installed lumens = bulb count × lumens per bulb; achieved illuminance = installed lumens ÷ the exact, unrounded area, rounded to one decimal place; the displayed area is rounded to two decimal places. Area and illuminance are computed throughout with exact fractions and rounded only for display.

1 ping = 400/121 m², about 3.3058 m²; the tool computes with the exact fraction. Target illuminance: living room 100, bedroom 75, kitchen 100, bathroom 100, study / office 300 lx from the general-activity values in Table 5.1.1 of GB 50034-2013, and corridors 100 lx from EN 12464-1:2021. The downloaded report is always named lighting-lumen-report.json and holds the compact JSON of the result, with object keys sorted recursively by UTF-16 code unit and one trailing newline.

Frequently asked questions

Is this a professional lighting design?
No. It is a simplified lumen-method estimate without utilisation or maintenance factors; luminaire distribution, surface colours and ceiling height all change real needs.
Why is the achieved illuminance above the target?
Bulbs come in whole units, so the count is rounded up and the installed lumens exceed the requirement.
How is a ping converted to square metres?
1 ping = 400/121 m², about 3.3058 m²; the tool computes with the exact fraction and rounds only for display.
Where do the target values come from?
Mainly the general-activity values in Table 5.1.1 of GB 50034-2013, with corridors from EN 12464-1:2021; standards differ, and this is one pinned source.
