Design Spacing Token Audit

Match measured pixel spacing to the nearest design token and check which differences exceed your tolerance. Everything stays on this page; nothing is uploaded or stored.

Switching language or leaving the page discards your draft.

One row per token: “name, tab, pixels”, 1–64 rows. Example: large⇥12

One row per measurement: “name, tab, pixels”, 1–100 rows. Example: gap⇥10

A number from 0 to 2048 with at most three decimal places. Default 1.

Input format

Each row is a name and a pixel value separated by a single tab. A name starts with an ASCII letter and may contain ASCII letters, digits, underscores, and hyphens, up to 32 characters; names must be unique within the same table. Pixels are unsigned decimals from 0 to 2048 with at most three fractional digits — no units, spaces, commas, or exponents. Each table holds at most 8,192 characters.

Each measurement is matched to the token with the smallest absolute difference. On a tie, the smaller pixel value wins; if the values are still equal, the earlier-listed token wins. The delta is the measurement minus the token: zero is “Exact”, an absolute value within tolerance is “Within”, otherwise “Outside”.

The report is always named spacing-token-audit-report.json and contains the result as compact JSON with keys sorted by UTF-16 code units and one trailing newline.

FAQ

Which token wins a tie?
It picks the smaller pixel value, then the earlier listed token.
Does this edit measurements?
The report shows matches and deviations alongside the original values.
