Fixed rules

Unit auto-detection looks at the absolute integer part: ≥ 10¹² is milliseconds, < 10¹¹ is seconds, and values in between need an explicit unit. Seconds accept 1–3 decimal digits (0.5 s = 500 ms); milliseconds accept integers only. Negative timestamps are before 1970; the convertible range is 0001-01-01 to 9999-12-31. Leap seconds are not counted in Unix time, so 23:59:60 has no timestamp. Around daylight-saving changes, a local time that does not exist is an error; a local time that occurs twice uses the earlier occurrence and is flagged. Time-zone offsets come from the device's built-in IANA time-zone database and do not follow the device's host time zone.

Results always show UTC and Asia/Taipei, plus one selected time zone; the selected zone is not repeated when it matches one of the first two. The downloaded report is the result as JSON, always named unix-timestamp-report.json.

Frequently asked questions

How are milliseconds and seconds told apart?
13-digit values are usually milliseconds and 10-digit values seconds; values in between need an explicit unit choice.
How are leap seconds handled?
Unix time does not count leap seconds, so 23:59:60 has no timestamp of its own.
Can I convert dates before 1970?
Yes, negative timestamps are before the epoch.
