How the calculation works

Total energy in Wh = mAh × V ÷ 1000; usable energy is total energy times depth of discharge; runtime in hours is usable energy divided by load in watts. For a pack, total voltage is cell voltage times the series count and total capacity is cell capacity times the parallel count, and both routes to total energy agree. Solve mode first computes the required energy, then converts it to required capacity and rounds up to the next whole mAh. All computation uses exact rational arithmetic, never floating point; displayed values are rounded half-up once, at output only, and runtime and solve results always use the unrounded exact value. Runtime is shown both as hours with one decimal and as hours/minutes, with the hours/minutes split taken from a single total-minutes figure. Inputs accept ASCII digits and at most one decimal point (at most 6 decimal places); series and parallel counts accept whole numbers only. Commas, spaces, signs, exponents and full-width digits are format errors — the tool never guesses. The downloaded report is always named battery-runtime-report.json and holds the result as compact JSON with object keys sorted by UTF-16 code units, recursively, ending in one line feed.

Frequently asked questions

How is Wh calculated?
Wh = mAh × V ÷ 1000.
Why is real-world runtime shorter?
Temperature, ageing, discharge rate and conversion losses all reduce usable energy; this tool gives an estimate and the depth-of-discharge input can approximate them.
Why does a 0 W load show unlimited runtime?
With no load the model draws no energy, so runtime has no finite limit; this is a status, not an error.
Is the Peukert effect included?
No. Effective capacity drops at high discharge rates, especially for lead-acid batteries; this tool does not model that effect.
