## 目標照度表的來源與驗證

釘版表（SPEC scope）主要取自《建築照明設計標準》GB 50034-2013 表 5.1.1「居住建築照明標準值」，逐列以兩份獨立轉載核對一致：

- TACHYON Light 轉載的英文版住宅照明標準值表：起居室一般活動 100、書寫閱讀 300、臥室一般活動 75、床頭閱讀 150、餐廳 150、廚房一般活動 100、衛生間 100（均 Ra 80、參考平面 0.75 m）。
- 深圳市團體標準 T/SZSA 024.2-2024《室內健康照明設計規範 第 2 部分：家居照明》表 1（2024-10-14 發布），其住宅各功能區域照度值與 GB 表相同：起居室一般活動 ≥100、書寫閱讀 ≥300、臥室一般活動 ≥75、床頭閱讀 ≥150、餐廳 ≥150、廚房操作台 ≥150、衛生間 ≥100。

取捨與揭露：

- 只取「一般活動」列（客廳 100、臥室 75、廚房 100、浴室 100）。作業列（廚房操作台 150、床頭閱讀 150）不採用，列為非目標。
- 書房／辦公無獨立列，取同表起居室「書寫、閱讀」300 作為閱讀書寫作業值，已在 SPEC 表中註明來源列。
- 走廊不在 GB 住宅表中。取 EN 12464-1:2021 室內流通區域與走廊的維持照度 100（經 Glamox 轉載表核對 "Circulation areas, corridors — 100"；瑞士 SIA 500 住宅無障礙附件引用 SN EN 12464-1 亦為走廊 100）。此列的來源與其餘五列不同，已在 SPEC 表與 FAQ 揭露。
- GB 50034-2013 已由 GB/T 50034-2024 接替（2024-08-01 實施）。多篇 2024 版摘要一致指出客廳 100、臥室 75、廚房一般活動 100 不變，但作業值摘要彼此不一致（床頭閱讀有作 200 亦有作 150、廚房操作台有作 300 亦有作 150），無法逐列核實 2024 全表；本案因此釘版可完整查證的 2013 表一般活動值，並在 SPEC scope 揭露此取捨，日後獨評可決定是否改釘 2024 版。
- 其他標準多以區間發表（IES 住宅一般照明、CIBSE 住宅表），彼此不同；SPEC FAQ 已揭露「各標準建議值不同，本表為單一釘版來源」。

## 設計決定

- 利用係數／維護係數：列為非目標。簡單流明法（面積 × 照度）是家用估算的通行做法；若硬塞一個無來源的預設折減係數，反而是捏造精度。簡化揭露常駐結果旁與 FAQ。
- 天花板高度修正：依概念備註的「釘版或省略」選擇省略，列為非目標並揭露高度會影響實際需求。
- 燈泡顆數以「已捨入的總流明」進位，而非未捨入的精確流明：使畫面上的總流明 ÷ 每顆流明 → 顆數可被使用者自行驗算，三個顯示數字永遠互相一致。差異只可能出現在精確流明的小數部分跨越整數倍邊界的極窄區間，已在 SPEC inputsOutputs 第 4 點寫明規則。
- 實際照度（achievedLux）取小數 1 位；面積顯示取小數 2 位；兩者都除以／取自未捨入的精確面積，只在輸出時捨入一次。捨入全為 half-up（floor(x + 1/2)），非 banker's rounding；`bedroom-half-up-tie` 專門釘住 112.5 → 113。
- 容量上限 8 個 UTF-16 code units 只適用數值欄位：列舉值 `dimensions` 本身長 10 單位，若對列舉欄位套同一上限，合法預設值會被自己的規則擋下。列舉欄位改為非列舉值即 ENUM、不設容量，此偏差已寫入 SPEC。
- 面積下限（長寬模式 0.25 m²、m2 模式 0.25、ping 模式 0.08 坪 ≈ 0.264 m²）配合最低照度 75 lux，保證 totalLumens ≥ 19，不會出現 0 流明或 0 顆的退化結果。
- 坪換算沿用同批 ping-area-converter 的精確常數 1 坪 = 400/121 m²，避免同批工具常數不一致。

## 案例推導（兩種方法）

方法一（手算，依 SPEC 釘版規則，先於任何程式）：

| 案例 | 手算 |
| --- | --- |
| `living-dimensions-basic` | 面積 4.0 × 3.5 = 14；14 × 100 = 1400 lm；ceil(1400/800) = 2 顆；裝設 1600 lm；1600/14 = 114.2857… → 114.3 |
| `bedroom-area-m2` | 12.5 × 75 = 937.5 → half-up 938；ceil(938/800) = 2；1600/12.5 = 128 |
| `study-ping-area` | 面積 6 × 400/121 = 2400/121 ≈ 19.8347 → 19.83；流明 2400/121 × 300 = 5950.41… → 5950；ceil(5950/1600) = 4；裝設 6400；6400 × 121/2400 = 322.66… → 322.7 |
| `kitchen-exact-bulb-multiple` | 5.0 × 4.0 = 20；20 × 100 = 2000；2000/1000 恰 2 顆不進位；2000/20 = 100 |
| `bedroom-half-up-tie` | 1.5 × 1.0 = 1.5；1.5 × 75 = 112.5 → half-up 113；ceil(113/60) = 2；120/1.5 = 80 |
| `bathroom-min-dimensions` | 0.5 × 0.5 = 0.25；0.25 × 100 = 25；1 顆；800/0.25 = 3200 |
| `study-max-area` | 10000 × 300 = 3,000,000；/100000 = 30 顆；3,000,000/10000 = 300 |
| `corridor-ping-min` | 面積 0.08 × 400/121 = 32/121 ≈ 0.26446 → 0.26；流明 26.44… → 26；1 顆；800 × 121/32 = 3025 |
| 錯誤案例 ×6 | 依欄位順序與每欄檢查順序逐案推定第一個錯誤：lengthM 小數 2 位 → DECIMAL_FORMAT；widthM 空 → EMPTY；areaValue 0.10 < 0.25 → RANGE；roomType `garage` → ENUM；bulbLumens `0` → RANGE；未啟用 areaValue 9 單位 → INPUT_LIMIT |

方法二（獨立重算）：另以 Python `fractions.Fraction` 精確有理數撰寫一份與 SPEC 規則獨立的驗算程式（不共用產品程式，本來就沒有產品程式），先對 8 個成功案例比對手算值，全數一致；再把驗算程式擴充為含完整驗證順序（容量→UNICODE→EMPTY→文法／列舉→範圍、未啟用欄位規則）的第二份程式，直接讀取已提交的 fixtures.json 深度比對全部 14 個核心案例，全數一致。驗算過程中發現並修正了一個釘版疏漏：初稿曾對所有欄位套 8 單位容量，會誤擋合法列舉值 `dimensions`（10 單位）；修正為容量只適用數值欄位，並已寫入 SPEC 與本文件。
