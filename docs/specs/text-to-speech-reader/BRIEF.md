# Text-to-Speech Reader — preparatory BRIEF v0.1

Specification documentation only; no product claim, readiness event or implementation. Full normative contract is SPEC.md.

## 1. Goal
People who proofread by ear, study languages, live with low vision, or simply rest their eyes need a page to read pasted text aloud — a contract draft, a story for a child, a vocabulary list — without uploading the text to a cloud TTS service. Success: the user pastes text, picks from the voices the browser actually offers, and hears it read with play/pause/resume/stop that behave predictably, the currently spoken sentence highlighted so they can follow along, and rate/pitch controls whose values are stated. The tool is honest about the platform: some browser voices are served locally and some are remote, so the SPEC requires surfacing each voice's local/remote nature where the platform reports it, and never claiming "fully offline" for a voice that is not.

## 2. Scope and functional distinction
Web Speech API `speechSynthesis` only. Text input up to a stated character limit, automatic segmentation at sentence boundaries with a stated long-text chunking rule (desktop Chrome's long-utterance cutoff is a known platform behaviour the chunking exists to defeat), voice list populated from `getVoices()` with language tags shown and localService voices labelled 本機/local; voices that report `localService === false` are labelled as network voices. Rate 0.5–2.0 and pitch 0–2 in stated steps. Transport: play from start or from a clicked sentence, pause, resume, stop; current-sentence highlight synchronised by utterance boundaries per chunk; a progress readout (sentence n of N, characters spoken of total). No SSML (the API does not offer it portably — stated), no audio file export/recording (the API cannot capture its own output — stated plainly rather than faked), no voice cloning, no translation, no text fetching from URLs. If `speechSynthesis` is absent, the page shows a clear unsupported message instead of dead controls.

Existing tools: Subtitle Bilingual/Shift handle subtitle files and timing, not speech synthesis; the media saver downloads media; no catalog tool speaks text aloud. Initial catalog/spec/task scope contains no TTS reader; fresh registry/path/draft check remains mandatory before admission. Fixtures use short synthetic sentences in zh-TW and English; no fixture requires an actual audible check by the reviewer beyond the stated browser smoke evidence — assertions that can be automated (segmentation, chunking, state machine) are separated from the one manual listening check, which is labelled as such honestly.
