## Revision addendum (2026-11-02, responding to independent review)
Independent document review by local-codex:01a0c75e-24c2-76e1-8c70-536ae1ad1fbf (oversight package 2026-11-02), candidate `a2e9a467213ff47a78b976a672e693efae1cce8a`, verdict **revision** (inputsOutputs 65, acceptance 78, tests 75). The author applied every blocking fix to the same task/spec IDs; this addendum is not a self-review and assigns no scores.
1. **Prosign collisions resolved by tagged form, not lookup order.** The author re-derived the collision set from the shipped table by script: the character table is internally collision-free, and exactly three prosign run-together forms collide with characters — AR `.-.-.` = `+`, AS `.-...` = `&`, KN `-.--.` = `(`. The old grammar let both readings live on one bare token, so the §6 "all five prosigns round-trip" and §7 "every punctuation round-trip" promises could not both hold. SPEC §2(b) and §4 now support prosigns **only in tagged form**: `<AR>` encodes to the tagged token `<.-.-.>` and decodes back to `<AR>` exactly (all five prosigns round-trip this way); a bare colliding token decodes to the punctuation character, with the alternative prosign reading attached as an annotation note that is never part of the decoded text; a bare non-colliding prosign run (`...---...`) is an unknown token whose warning names the prosign and its tagged spelling as a hint. §6 and §7 were rewritten so the character bijection and the prosign promise are jointly satisfiable and both are tested (fixture 8 places the tagged round-trip beside its bare twin `S+S` + note; fixture 4 now uses the tagged `<...---...>`, 23 units re-verified element by element).
2. **Validation order pinned.** The old text uppercased the input before validation, which silently expands `ß` to `SS`. SPEC §4 now pins: validate the RAW input's characters first (supported set stated exactly); unsupported characters are refused and listed by 1-based position with nothing encoded; the only normalisation afterwards is `a–z` → `A–Z` on already-validated letters, and no whole-input Unicode case mapping is ever applied. Fixture 7 (`AßB` → ß refused at position 2; `ß` alone at position 1) and a mixed-ordering test were added; the author confirmed the hazard directly (`'ß'.toUpperCase()` === `'SS'`).
3. **Validity state for playback/copy pinned** (the review's userFlow note): §3 now states Play is enabled only when the Morse pane is fully valid and not stale, with the reason shown otherwise; copy rules never launder an invalid decode into a clean-looking string.
Product checks remain NOT_RUN; the author does not mark this specification ready.
