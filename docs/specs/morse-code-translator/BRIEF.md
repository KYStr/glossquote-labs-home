# Morse Code Translator — preparatory BRIEF v0.1

Specification documentation only; no product claim, readiness event or implementation. Full normative contract is SPEC.md.

## 1. Goal
Radio hobbyists, scouts, students, puzzle and escape-room makers, and the simply curious meet Morse as a wall of dots and dashes with no way back. Success: the user types ordinary text and gets correct International Morse (ITU) for letters, digits and a closed punctuation set — shown as dots/dashes with letter and word spacing made visible — plays it as audio at a stated speed (WPM by the PARIS standard) and tone, sees the total signal duration computed from the timing model before pressing play, and pastes Morse back to decode it into text, with malformed tokens reported by position instead of silently dropped. A closed list of prosigns (SOS, AR, AS, KN, SK) is handled as single run-together signals when written `<SOS>`, because in real Morse those are not three letters but one sign.

## 2. Scope and functional distinction
Encoding table pinned to ITU-R M.1677: A–Z, 0–9, and exactly these punctuation marks: `. , ? ' ! / ( ) & : ; = + - _ " $ @` — anything else is an error naming the character, never a silent skip. Timing is data, not vibes: dot 1 unit, dash 3, intra-character gap 1, letter gap 3, word gap 7; speed 5–60 WPM with unit = 1200/WPM ms; tone 400–1000 Hz (default 600). Decoding grammar is pinned: tokens separated by single spaces are letters, ` / ` (or a standalone `/` token) separates words, runs of 2+ spaces also decode as a word gap (pasted Morse is messy), and unknown tokens are reported with their index and kept visible as `�` placeholders in a warning list — the decoded text never pretends they were not there. Playback is WebAudio scheduled from the same timing table the duration display uses (the metronome specification's scheduling discipline applies by reference: times accumulate on the audio clock, stop silences promptly), and playback highlights the character currently sounding. Excluded: American (railroad) Morse, code-practice random generators / Koch training, receiving or decoding audio from the microphone, keying hardware, Farnsworth timing (stated as a later scope decision), images of keys/antennas, and saving texts.

Existing tools: my own UTF-8/Base64 codec specification encodes text as bytes for machines (data interchange, strict byte rules) — Morse is a human signalling code whose essence is timing and sound, with a decode direction tolerant of pasted spacing. Text-to-Speech Reader speaks rendered language; this tool emits timed tones, not speech. No catalog entry, reserved specification or registry task at admission time translates Morse; fresh registry/path/draft check remains mandatory before admission. Fixtures are computed in the SPEC and re-derived during drafting (PARIS = 50 units is the standard's own calibration word and is verified element by element; SOS = 27 units = 1,620 ms at 20 WPM).
