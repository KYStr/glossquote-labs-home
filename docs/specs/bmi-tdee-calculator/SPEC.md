# BMI and TDEE Calculator — full preparatory specification v0.1

Specification documentation only; no product claim, readiness event or implementation. This document is the normative contract a future production task must satisfy exactly; where it says MUST, a differing behaviour is a defect, not a variation. Health-adjacent arithmetic fails in predictable places — a boundary rounded the wrong way, a formula nobody names, a maintenance estimate quietly presented as a diet prescription. This specification pins the formulas, judges categories on unrounded values, and forbids eating targets outright.

## 1. Goal
Primary audience: adults checking where their weight sits for their height, people estimating daily energy needs before talking to a professional, students learning the standard equations, and anyone who wants the numbers with the formulas shown instead of a black box. The recurring problem: most calculators hide which BMR equation they use, round BMI before categorising it (so a person at 24.96 is told "overweight 25.0" or vice versa), attach weight-loss calorie targets with no safety framing, or upload the user's body measurements to a server. Success is observable: the user enters sex, age, height and weight in metric or imperial units, picks an activity level described in ordinary words, and receives — BMI with its WHO category, the healthy weight range for that height, BMR by the named Mifflin-St Jeor equation, and a five-row TDEE table. A permanent statement above the results says these are population-level estimates, not medical advice, and that the tool deliberately gives no calorie target for gaining or losing weight. Non-goals: diagnosis (category labels are band names, never findings about the user), body-fat estimation, pregnancy or athlete adjustments, children's growth charts, and saved profiles.

Assumptions: a modern desktop browser; the adult-derived equations are applied within the input ranges of section 2; no network at runtime.

## 2. Scope and functional distinction
Included: (a) inputs — sex (female / male, used only by the BMR constant), age in whole years, height and weight in a toggleable unit system: metric (height cm, weight kg) or imperial (height feet + inches, weight lb); (b) outputs — BMI (one decimal), WHO category, healthy weight range for the height, BMR in kcal/day, and TDEE for all five activity levels with the selected level highlighted; (c) the formulas and constants printed on the page itself (Mifflin-St Jeor named, the five multipliers listed, the WHO bands listed), so the page is self-auditing; (d) an information-only line giving the Asia-Pacific public-health action points (BMI 23.0 and 27.5) explicitly labelled as information, not as a second category verdict. Accepted ranges (post-conversion for imperial): age 10–120 years; height 50–272 cm; weight 10–635 kg. An age under 18 adds a visible note that the equations were derived on adults and the results are rough orientation only. Excluded: any calorie target other than maintenance TDEE, deficit/surplus suggestions, meal or diet content, waist or body-fat inputs, unit systems beyond the two named, and persistence.
Distinction from existing work: no catalog entry, reserved specification or registry task computes BMI, BMR or TDEE. The Mortgage Amortization and Compound Interest specifications are financial time-series; the shared content is arithmetic only. The admission check MUST be re-run against the fresh registry before production, and a collision stops the task for coordinator decision rather than a rename.

## 3. User flow and lifecycle
Initial state: metric units, female, age 30, height 175 cm, weight 70 kg, activity "moderate" — results already computed, so the layout and the not-medical-advice statement are visible before the user types anything. Every edit recomputes all outputs together; switching the unit toggle converts the current height and weight into the other system (values re-derived from the unrounded metric store, displayed rounded per section 4) rather than clearing them.
Error states are per-field and specific: non-numeric input; age not a whole number; a value outside its accepted range (the range is named). While any field is invalid, all outputs freeze at the last valid state marked "out of date" — a BMR must never appear to describe inputs it was not computed from. The activity selector uses behavioural descriptions ("desk work, little exercise", "exercise 3–5 days a week", …) beside the multiplier, never the multiplier alone. Nothing persists across reload; body measurements never appear in the URL or title.

## 4. Computation rules (normative)
Units and conversion: internally everything is metric, stored unrounded. Imperial → metric uses exactly 1 inch = 2.54 cm and 1 lb = 0.45359237 kg; total imperial height = 12 × feet + inches (inches may be 0–11; a value ≥12 is a field error telling the user to fold it into feet — stated, so no silent normalisation). Metric → imperial display: height as feet + inches with total inches rounded to the nearest whole inch (half away from zero); weight in lb to one decimal. All computation uses the unrounded metric values regardless of the display system.
BMI: BMI = weight_kg ÷ (height_m)², height_m = height_cm ÷ 100. Display: rounded to one decimal, half away from zero. Category: judged on the **unrounded** BMI — underweight < 18.5; normal [18.5, 25); overweight [25, 30); obese class I [30, 35); obese class II [35, 40); obese class III ≥ 40. The page states in one sentence that the category uses the unrounded value, so a displayed 18.5 can still be underweight (fixture below) and a displayed 25.0 can still be normal (24.96) — both directions are deliberate.
Healthy weight range: [18.5 × h², 25 × h²) kg, h in metres. Displayed: lower bound rounded to one decimal as "from X kg"; upper bound rounded to one decimal and labelled "stay below Y kg" (the upper value is the exclusive threshold, and the wording must say so). In imperial display the same bounds are shown converted to lb (one decimal).
BMR (Mifflin-St Jeor; w = kg, h = cm, a = years): men: 10w + 6.25h − 5a + 5; women: 10w + 6.25h − 5a − 161. Computed from unrounded values; displayed rounded to the nearest whole kcal (half away from zero).
TDEE: TDEE = unrounded BMR × multiplier; displayed rounded to the nearest whole kcal. Multipliers and labels (normative): sedentary 1.2 (desk work, little or no exercise); light 1.375 (exercise 1–3 days/week); moderate 1.55 (exercise 3–5 days/week); active 1.725 (hard exercise 6–7 days/week); athlete 1.9 (physical job plus training, or twice-daily training). The table shows all five TDEE values for the current inputs; the selected row is highlighted. No other calorie figure (deficit, surplus, "goal weight intake") may be shown anywhere on the page.
Worked fixtures (normative, re-derived by script during drafting):
- M1: male, 30 y, 175 cm, 70 kg → BMI 22.857… displays **22.9**, normal. BMR = 700 + 1093.75 − 150 + 5 = 1648.75 → **1649 kcal**. TDEE: sedentary 1978.5 → **1979**; light 2267.03 → **2267**; moderate 2555.56 → **2556**; active 2844.09 → **2844**; athlete 3132.63 → **3133**.
- F1: female, 30 y, 175 cm, 70 kg → BMI **22.9**, normal. BMR = 1482.75 → **1483 kcal**; moderate TDEE 2298.26 → **2298**.
- Boundaries at 200 cm (h² = 4 exactly): 74 kg → BMI exactly 18.5 → **normal**; 100 kg → 25.0 → **overweight**; 120 kg → 30.0 → **obese I**; 140 kg → 35.0 → **obese II**; 160 kg → 40.0 → **obese III**; and the trap case 73.9 kg → BMI 18.475, displays **18.5** but category **underweight**.
- Imperial: male, 30 y, 5 ft 9 in (69 in = 175.26 cm), 154 lb (= 69.8532… kg) → BMI **22.7**, normal; BMR 1648.907… → **1649 kcal**.
- Healthy range at 160 cm: [18.5 × 2.56, 25 × 2.56) = [47.36, 64.0) → displayed "from **47.4 kg**, stay below **64.0 kg**".

## 5. Implementation and safety
Architecture (future production): a pure core (unit conversion, BMI + category, healthy range, BMR, TDEE table) with zero DOM access; a controller; a thin DOM layer. All constants (conversion factors, WHO band edges, Mifflin coefficients, multipliers) appear once as auditable data matching section 4. Runtime dependencies: none.
Privacy/security: body measurements are health-adjacent data — no network, no storage, no analytics, no sharing affordance; values never appear in the URL or title; inputs render as text only; no eval/Function; no external resources.
Honesty and safety rules (normative, testable): the not-medical-advice statement is present above the results in both languages and cannot be dismissed; the words used for categories are the WHO band names only; no text on the page may promise an outcome, recommend eating any amount, or describe a category as a diagnosis; the Asia-Pacific line is labelled information-only; the under-18 note appears exactly when age < 18.
Bilingual and accessibility: full zh-TW (default) and English UI, including the statement, the unrounded-category sentence, activity descriptions and band names. Results are text and a real table; category is text, never colour alone; all inputs native, labelled; keyboard-complete flow.
Performance bounds: trivial arithmetic, recompute per keystroke with no debounce requirement. Toolchain: Node 24, zero npm dependencies, house layout (public/, public/en/, core modules, node:test suites, build/check/serve scripts); runs offline from file:// or any static host.

## 6. Independent nine-aspect product rubric
Each aspect is scored 0–100 by a reviewer who is not the author, against the same fixed candidate commit; every aspect MUST reach ≥90 with all mandatory checks complete, otherwise the verdict is revision. Unrun checks stay NOT_RUN and block acceptance.
- functionality: both languages and both unit systems; all outputs (BMI, category, healthy range, BMR, five-row TDEE table with correct highlight) match section 4 for every fixture; unit toggle converts rather than clears.
- boundaries: the six 200 cm boundary weights judged exactly (edges belong to the upper band; the trap case displays 18.5 but is underweight); range edges age 10/120, height 50/272, weight 10/635 accepted and one step beyond refused; imperial inches = 12 refused with the fold-into-feet message.
- privacy: zero network after load; no storage; measurements absent from URL/title; no share or save affordance exists.
- security: field text containing markup renders inert; no external resources; no eval/Function.
- usability: a first-time user gets their numbers without instructions and can state, from the page alone, which equation produced the BMR and what the multipliers mean (spot-check).
- accessibility: category and figures as text, never colour alone; TDEE is a real table; labelled native inputs; keyboard-complete; error text associated with its field.
- localization-seo: zh-TW and en pages complete and equivalent (including the not-medical-advice statement, the unrounded rule sentence and activity descriptions); correct lang attributes, titles, descriptions and same-language home links.
- toolchain-provenance: zero-dependency build reproduces byte-identical output on Node 24; constants appear once as auditable data matching section 4 (a reviewer can point at the single place each multiplier lives).
- compatibility: current Chrome/Edge/Firefox/Safari desktop; identical outputs for the fixture corpus across browsers.
Additionally (page-honesty gate, cross-cutting): the reviewer verifies by reading the rendered page that no deficit/surplus calorie figure or eating recommendation appears anywhere, and that the not-medical-advice statement is present and non-dismissible; failure of this gate caps usability at <90 regardless of other evidence.

## 7. Required tests and timing
Core unit tests with independently derived expectations: (a) fixtures M1 and F1 in full (BMI display + category, BMR, all five TDEE values for M1); (b) the six 200 cm boundary weights with exact category assertions, including the trap case's display/category split; (c) the imperial fixture end-to-end (conversion, BMI, BMR) and a unit-toggle round trip (metric → imperial → metric returns the same computed outputs); (d) healthy-range fixture at 160 cm and the exclusive-upper-bound wording present; (e) validation: each range edge and refusal, non-integer age, inches ≥ 12, non-numeric input; (f) rounding: a constructed BMI of x.x5 rounds half away from zero in display while its category uses the unrounded value.
GUI/evidence tests (desktop, real browser): fixtures entered through the real UI in both languages and both unit systems; stale-state behaviour on an invalid field; the under-18 note appearing and disappearing as age crosses 18; a full-page text read confirming the honesty gate (statement present, no eating target anywhere). Timing: full core suite under 60 seconds; no network in any test.
Explicitly NOT_RUN at specification stage: all product tests above; this document claims document completeness only.
