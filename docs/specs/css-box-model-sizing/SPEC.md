# CSS Box Model Sizing Explorer — complete preparatory specification v0.2

Status: DRAFT_FOR_INDEPENDENT_DOCUMENT_REVIEW. Prepared 2026-11-01 UTC. No product implementation or claim exists for this draft.

## 1. Goal and successful user outcome
Help a CSS learner or site maintainer understand why an explicitly sized empty rectangular box occupies more room than its declared width/height. The user compares content-box and border-box using the SAME dimensions, four padding values and four border widths, and obtains exact content/padding/border dimensions plus deterministic CSS. Success: without developer tools, explain the effect of switching sizing and the zero-content floor when border plus padding exceeds a declared dimension. This is a usefulness hypothesis, not user research.

## 2. Scope and non-overlap
One empty, non-replaced block; physical horizontal/vertical axes, px units, independently entered four sides. Both sizing modes displayed side-by-side. Each panel contains a normal native CSS box plus numerical dimension table, with a separate labeled scaled diagram when needed. Borders are solid, fixed color; no margin. Width/height are explicit, not auto. No arbitrary HTML/CSS parsing, custom content, fonts, images, percentage units, flex/grid, min/max constraints, aspect-ratio, transforms, overflow content, collapsed margins, border radius, shadow, layout diagnosis of another site or download.

Not Box Shadow Builder: that tool edits blur/spread/offset/color/inset/layers and its box size is merely a preview aid. Here border/padding/content dimension accounting is the sole product outcome; no shadow is generated. Not Box Fit (packing three-dimensional physical items), image resizer/print-size (raster images or DPI), object-fit (replaced image fit/crop), elliptical corners (radius overlap scaling), or CSS Grid/Flex Shrink (multi-item layout). We do not reuse their task/owner/spec IDs. De-duplication was checked against the fixed catalog and registry references in AUTHOR-CHECK.md; newly discovered ownership overlap must be resolved before admission.

## 3. User flow and states
Initial page shows editable defaults W=200,H=120,padding T/R/B/L=10/20/10/20,border T/R/B/L=2/2/2/2 with both result panels already generated and a visible example label. Controls in order: width, height, padding fieldset, border fieldset, Generate, Reset; then two result tables, selectable CSS for each mode, explanation and same-language home link. CSS uses readonly labeled textarea; selecting text is manual, no clipboard API.

1. Edit one or many fields. Preserve raw strings; immediately mark state dirty, remove/hide previous preview/table/CSS and announce once that Generate is required. Dirty is not an error until Generate.
2. Generate validates all fields in fixed DOM order and reports every error with field association and a summary linking to the first invalid field. No partial result. On failure focus first invalid field; on success keep Generate focus and polite status says updated. Numeric input changes do not auto-steal focus.
3. Success atomically displays one snapshot in BOTH modes, tables and output. Repeated Generate with no edits is idempotent. The page explains if border-box actual border dimension exceeds declared size due to zero-content floor.
4. Reset immediately restores defaults and generated output, clears errors/dirty state; focus remains Reset. No confirmation needed because no private document is held. Language switch keeps raw/snapshot/state and focus on the corresponding language control; no transient old-language result. A client-side bilingual toggle updates document lang/title and matching-language navigation without storing state. Direct entry in either language starts defaults.
5. Reload starts defaults. Back/forward with BFCache may restore an internally coherent state only; pageshow recomputes if necessary. Without BFCache defaults are acceptable. No promise to persist session state.

## 4. Input, mathematics and output contract
Inputs are text controls with inputmode=decimal, not browser-dependent number parsing. Trim ASCII space/tab/CR/LF at both ends only. Raw limit 16 UTF-16 code units per field BEFORE trim. Grammar after trim: `[0-9]+(?:\.[0-9]{1,2})?`. Leading zeroes accepted; plus/minus, scientific notation, comma, Unicode digits/whitespace, percent, hex, empty, `.5`, `5.` and more than two decimal places rejected. Width/height range 0..600 inclusive; padding each 0..100; border each integer 0..20 (fractional borders excluded because native used-width quantization varies). Validity order per field: length, grammar, precision/integer restriction, range. No clamp or silent rounding. Store dimension/padding as integer hundredths; border scaled to hundredths. Canonical serialization strips leading/trailing zeroes, uses ASCII dot, zero as `0`, and has no exponent.

For each axis let D be declared dimension; P the sum of its two paddings; B the sum of its two borders. content-box: content=D, paddingBox=D+P, borderBox=D+P+B. border-box: content=max(0,D-P-B), paddingBox=content+P, borderBox=content+P+B. Width and height computed independently. This restricted model follows [W3C CSS Sizing §3.3](https://www.w3.org/TR/2026/WD-css-sizing-3-20260904/#box-sizing); it does not implement general layout. Fixed integer arithmetic makes the model exact; browser layout is separately observed with tolerance.

Output tables per mode: declared W/H, content W/H, padding-box W/H, border-box W/H and warning if either borderBox exceeds declared. Each table row carries px labels. CSS is fixed LF text, no final ambiguity: `.sample {` newline, two-space indented `box-sizing: MODE;`, `width: Wpx;`, `height: Hpx;`, `padding: Tpx Rpx Bpx Lpx;`, `border-style: solid;`, `border-width: Tpx Rpx Bpx Lpx;`, `border-color: #334155;`, `margin: 0;`, then `}` and terminal LF. Exact order as listed. Modes are fixed enum values, never user text. No color or diagram labels enter serialized code.

Native preview: actual empty `div.sample` uses these declarations inside a separately scrollable labeled stage; stage must not flex-shrink the sample. No transform is allowed on native sample or ancestors used for measurement. Give sufficient in-stage room for largest border box (840x840), retaining scroll rather than shrinking the CSS geometry. Diagram may scale uniformly to 300x300 available area but must show scale and be labeled schematic, not native size. The numeric table remains authoritative and readable at narrow widths. Native box itself has no text/min-size/hidden intrinsic content. Padding color may be shown by a fixed background-clip layer; distinguish all layers also by labels/line styles. Zero-area content remains representable by text without inventing positive area.

Independent exact fixtures (all unspecified side values zero):
- Defaults: content-box content 200x120,padding 240x140,border 244x144; border-box content 156x96,padding 196x116,border 200x120.
- W=20,H=0,padding L=15,R=15,T=1,B=2,borders all2: content-box 20x0 -> padding50x3 -> border54x7; border-box content0x0 -> padding30x3 -> border34x7. Both border-box axes show floor warning.
- W=0,H=0, all sides0: all table dimensions zero in both modes; no floor warning because actual equals declared.
- W=1.25,H=2.5,padding L=.25 is INVALID; use 0.25. With L=0.25,R=0.5,T=0.75,B=1,borders0: content-box border2x4.25; border-box content0.5x0.75 and border1.25x2.5.
- W=600,H=600,padding all100,border all20: content-box border840x840; border-box content360x360 and border600x600.
- Border-box W=44 with P=40,B=4 gives content0,actual44,no warning; W=43.99 gives content0,actual44,warning. Distinguish equality from exceeding.

### Timing measurement protocol (F1 clarification)
The <=100ms bound measures application completion to a presentation opportunity, NOT physical paint, GPU completion or user-perceived latency. Use the foreground visible tab, no CPU/network throttling, no open modal, and record browser/OS/hardware, viewport, DPR and zoom without imposing a new hardware class. Fixed maximum-work input: W=H=600, every padding100, every border20, both sizing modes. For each trial make a valid edit to mark dirty (retain the fixed fixture values before Generate), then record t0=performance.now() at the start of the Generate handler, before validation. After synchronous validation/derivation and all result DOM updates have completed, enqueue one requestAnimationFrame and record t1=performance.now() inside its callback. Duration=t1-t0. Run five complete unrecorded warm-up trials, then twenty measured trials sequentially; do not start the next edit/generate until the previous callback has completed. Retain all twenty raw durations, maximum and pass/fail; every measured trial must be <=100ms. Hidden-tab, throttled or interrupted trials are invalid observations, retained with reason and rerun under the defined visible condition, not silently discarded for slowness. A slow valid trial is a failure, not an excuse to redefine the budget. No timers/RAF are claimed to prove actual raster paint; native appearance remains the separate screenshot/geometry matrix. If performance.now/rAF observation is unavailable, mark this required check NOT_RUN and do not replace it with Node CPU timing.
