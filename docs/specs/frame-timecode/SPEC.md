# Integer-rate Frame Timecode Calculator — full preparatory specification v0.2

Status DRAFT_FOR_INDEPENDENT_DOCUMENT_REVIEW; prepared2026-11-01UTC. No implementation or claim. Product tests NOT_RUN, scoresnull.

## 1. Goal and outcome
Help a video editor or animation learner count frames and apply a known integer-frame offset at an explicitly selected integer frame rate. Convert between an absolute frame index and HH:MM:SS:FF within one24-hour day, and see exact elapsed seconds as a rational number. Success: at25fps identify00:00:59:24 asframe1499, add1frame and obtain00:01:00:00 without confusing milliseconds with the frame field. No claim to diagnose real media or synchronise playback.

## 2. Scope and de-duplication
Only rates24,25,30,50,60 frames/second, exact integers. Two input modes(timecode/frame index), one signed frame offset, no wrap across day. Output source and shifted index/timecode plus exact elapsed-second fraction. No fractional rates23.976/29.97/59.94, drop-frame numbering, semicolon delimiter, wall clock, timezone, duration range, playback, subtitles, media/file import, export, clipboard, batch jobs or automatic frame-rate conversion. Unsupported formats explicitly rejected, never approximated to nearby integer rate.

Existing Subtitle Shift accepts an entire bounded SRT document and changes all cue milliseconds by a common seconds offset; it does not expose an integer-rate frame numbering calculator. Audio Cue Notes records timestamps against actual audio, while Event Timeline and Work Hours schedule/total human times. This new tool reads no media or SRT and preserves no cue text. Existing Integer Representation and Rational Arithmetic are mathematical domains, not frame/timecode conventions. Functional boundaries checked against initial catalog56/spec82/task88 and the existing fixed Subtitle Shift specification at be197ea30d909b1353e7f77bdf16b1811ac41f71, coordination/local/2026-10-29/specs/36-subtitle-shift/SPEC.md. Current registry/path check remains mandatory before admission.

[Adobe XMP Timecode documentation](https://developer.adobe.com/xmp/docs/xmp-namespaces/xmp-data-types/timecode/) distinguishes formats including integer and fractional/drop variants. This product deliberately supports only its closed integer-rate subset below, not full SMPTE/XMP compliance or media metadata interchange. Rate must be selected by the user; a colon string alone does not identify rate.

## 3. User flow and lifecycle
Initial generated example rate25,mode timecode,rawtimecode00:01:00:00,rawframes1500,offset0. Controls: rate selector, mode radios, active source field, offset, Calculate, Reset; then two labeled source/shifted result rows and exact-seconds explanation. Inactive source field is hidden/disabled but raw string preserved; only active field validated. Switching modes exposes its previous raw string and clears result; it does NOT convert the last result into the new input. Help states this behavior.

Source controls (timecode, frame index, offset) are native input type=text, never type=number. Timecode/offset use inputmode=text to allow colon/minus; frame index may use inputmode=numeric as a keyboard hint only. Store the exact .value string received on input in the raw-state record. Never use valueAsNumber, automatic parsing/reformatting on blur, beforeinput filtering, maxlength truncation or silently corrected digits. Invalid strings received by the controller remain visible until edited or Reset.

Native single-line text inputs remove CR/LF during browser value sanitization, including pasted line breaks. On-page help must disclose that line breaks are not preserved before the controller receives .value; do not claim byte-for-byte preservation of the original clipboard text. Core-only ASCII end trimming of CR/LF applies to directly supplied strings and is not a promise that the UI retains those characters. Other received characters are not silently normalized. No clipboard read API is used.

Every raw/rate/mode/offset change immediately removes all old outputs and marksdirty. Rate change preserves literal inputs, not elapsed time; Calculate reinterprets at new rate. Calculate validates enums, active source thenoffset, reports errors with field association and summary, focuses first invalid field. Source/shift overflow error has no partial output; original raw remains. Success keeps Calculate focus and updates all rows/summary atomically. RepeatCalculate is idempotent. Reset restores defaults/generatedexample and clearserrors, focus staysReset.

Bilingual in-memory toggle preserves raw/enums/state/snapshot, updates static/dynamic copy, lang/title and same-language home link; focus stays toggle. Both language entry pages have static help. Reload resets defaults. BFCache Back/Forward may restore coherent state only; pageshow recomputes or invalidates stale output. No storage, URL query/hash state, history of calculations or autosave. UnsupportedJS shows static help and honest inability to calculate.

## 4. Exact inputs, algorithm and output
Core exact own-data schema: rate(enum number),mode(timecode|frames),timecodeRaw,framesRaw,offsetRaw(strings); reject extra/missing/inherited/accessor fields or wrong types. No JSON UI. Each active raw field maximum16 UTF-16 units before trimming only ASCIIspace/tab/CR/LF at ends. Inactive raw strings are preserved without validation or truncation; only the active source is subject to the16-unit gate on Calculate. Inactive inputs are hidden/disabled, so they cannot accept new user edits until activated. No maxlength silent truncation.

Timecode grammar exactly `[0-9]{2}:[0-9]{2}:[0-9]{2}:[0-9]{2}` after trim; HH0..23,MM/SS0..59,FF0..F-1. Thus FF24 invalid at24fps, valid at25fps. Frames grammar `[0-9]+`,offset `-?[0-9]+`; leadingzeroes/-0 accepted, canonicalzero0. No plus,decimal,exponent,comma,Unicode digits/space,colonvariants or semicolon. Frames0..86400*F-1. Offset in[-86400*F,+86400*F], inclusive. Validation order schema/type/length,empty,grammar,fieldrange,then shiftedrange. Source field must be independently valid before adding offset; never rescue invalid source byoffset.

N=((HH*60+MM)*60+SS)*F+FF, or parsed sourceframes. R=N+offset. Reject ifR<0 orR>=86400*F. No modulo24h or silentclamp. For eitherN/R convert by integer quotient/remainder: FF=value%F; wholeSeconds=floor(value/F); SS=wholeSeconds%60; MM=floor(wholeSeconds/60)%60; HH=floor(wholeSeconds/3600). Format every component exactlytwoASCII digits separatedbycolons. Maximum intermediate magnitude<10400000, exact safeinteger; Number arithmetic is sufficient AFTER strict parsing/range. Do not use Date APIs or floating seconds to deriveframes.

Exact elapsedseconds text is n/F reduced by gcd(n,F), denominatorpositive; integer only ifdenominator1,zero0. It represents time fromframe0 to the frame start, not totalclipduration/inclusiveframecount. No decimalmilliseconds output. Source andshifted frame index are zero-based; frame0 is00:00:00:00. Outputlabels say frameindex notframecount.

Readonly plain summary exactASCII keyorder with LF/terminalLF: `rate-fps: F`, `source-index: N`, `source-timecode: HH:MM:SS:FF`, `offset-frames: signedOffset`, `result-index: R`, `result-timecode: HH:MM:SS:FF`, `source-seconds: reducedFraction`, `result-seconds: reducedFraction`. Each keycolononeASCIIspacevalue. Invariant betweenlanguages. No automaticclipboard/download. Selectabletext exact,nottruncated.
