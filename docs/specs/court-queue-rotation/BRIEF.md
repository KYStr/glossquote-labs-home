# 單場散打輪轉板 / Drop-In Court Queue 製作簡報

預案 `spec-court-queue-rotation-20261109` · 文件待獨立審查

單場球類散打活動的負責人需要跟著現場已完成場次更新候場，讓勝方可連打但連打有上限，並讓晚到與先走的隊伍離開現場輪轉。

在場邊大一點的畫面上看到目前上場、場間留場、候場與下一對，逐次追加實際事件。

用手機記下開打、完場、加入或離開，下一對維持明顯文字。操作失誤可刪去最後一筆再重算。

主要操作「更新球場輪轉 / Update court queue」。工作區採 Product App。頁面中優先呈現以下工作物。

```text
寬畫面
隊伍／事件順序   |   現在上場、留場、候場、下一對

窄畫面（由上而下）
隊伍設定 → 事件 → 更新輪轉 → 上場／候場
```

首個貫通案例用 `court-queue-rotation.cap`。A 連勝兩場達上限，在 D、B 已候場時，A 和剛上場的 C 加到尾端。下一對是 D、B。

2–12 個已知隊伍、單場地、最多 120 筆按發生序事件。勝方保留最多指定連場數，平手兩隊排回尾端。以已發生事件重演隊列。

產品界線與輸入、算法、九面向、測試、交接以 [規格](SPEC.md) 為準。起手先將 [字面案例](fixtures.json) 固定在 Node 24 離線測試，再接兩語操作。完成後固定 `tools/court-queue-rotation/` 候選及 open PR head，將真實檢查結果交主責。這份簡報的產品、瀏覽器、正式站 gate 全為 `NOT_RUN`。
