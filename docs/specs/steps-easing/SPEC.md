## 1. Goal, scope and non-duplication

A frontend author needs to distinguish discrete timing jumps from smooth easing, identify the value exactly at a jump and obtain a reproducible timing-function declaration. Normal success is choose N and position, Generate, inspect one endpoint and one interior boundary with before=false/true, explain the difference using visible text/table, repair invalid input and manually select CSS. No animation is required to complete this task.

Scope: interval count N1–100; jump-start/end/none/both; unit-interval input progress only; explicit Boolean before flag; decimal progress with at most6 decimals or exact boundary k/N; bilingual Traditional Chinese/English, one staircase/table, static linear and eased markers, manual selectable CSS. N>=2 for jump-none. Limit100 is this app's resource boundary, not a CSS limit. Output is one declaration, not an animation/keyframe stylesheet.

Excluded: autoplay and all playback (the BRIEF's optional demonstration is deliberately omitted), duration/delay/fill/reverse/iterations simulation, easing composition, domain extrapolation, cubic control points, arbitrary CSS parser/selector/import, sprite sheets, files/images/fonts/audio/video, accounts, downloads, clipboard APIs, URL input state, persistence, telemetry, remote services/dependencies, gestures/drag required to operate. Do not infer the mathematical before flag from time direction or browser animation phase.

Known-scope comparison: registry397/registered original61 responsibilities, catalog56, PR2–16 and saved CSS specifications showed no dedicated steps tool. Cubic SPEC at8553231a365de4eafb964f620ea530850b4fbab0 explicitly excludes steps: it solves continuous Bézier inversion, not discrete integer intervals or before-flag boundaries. Transform-Origin manipulates spatial transforms; Flex Shrink allocates widths; Fluid Typography interpolates font size; Elliptical Corners normalizes radii; Gradient/Shadow/Grid produce styling/layout. Existing owners remain untouched. Unregistered unpublished local work is UNKNOWN, not absent; check current collisions before production. This is a bounded provenance comparison, not a global uniqueness claim.

Semantic source: [CSS Easing Functions Level1, 13 February2023 CR Draft, §2.3–2.3.1](https://www.w3.org/TR/2023/CRD-css-easing-1-20230213/#step-easing-functions), read2026-11-01. It is a dated draft, not browser certification. §2.4 browser serialization may omit jump-end; this app intentionally emits the explicit canonical four-position spelling. start/end aliases and step-start/step-end are explanatory help only, not extra accepted enum values.

## 2. User flow, state and normal desktop accessibility

Initial state: N4, position jump-end, progress mode decimal, decimal raw0.25, boundary selector k1, before unchecked. Show scope/help and controls, no generated output. Mode is a native select decimal/boundary; position is a native select of four enum values; before is a native checkbox. N and decimal progress are text inputs with inputmode numeric and decimal respectively, autocomplete off, spellcheck false, no maxlength and no numeric coercion. N remains editable while boundary mode is selected. The boundary k select is rebuilt only on successful Generate from valid N, not while parsing partial raw. It is disabled and no valid boundary selection is assumed before the first successful Generate in boundary mode; see generation rule below.

Generate validates a snapshot. Form uses novalidate and prevents navigation; Enter submits once unless composing. On success focus stays on the source control (input Enter stays input; button activation stays button); do not move pointer focus programmatically. On error show associated inline errors and an error summary, focus the first invalid field in order N, position, mode, active progress, before. Raw input stays visible, including overlong text. Do not trim/clamp/rewrite on blur or success. Describe allowed values permanently, not only placeholders. Hidden inactive decimal raw is retained but not validated or used in boundary mode.

Boundary mode bootstrapping and changes: first successful boundary Generate with no selector built uses k0, displays selector0..N and explicitly announces boundary0/N. Selecting any available k invalidates prior outputs and requires Generate; it does not compute on change. Editing N or changing mode clears generated output and discards the prior boundary selector/options; the next boundary Generate starts at k0. This prevents stale k>N and silently relabelled fractions. Merely editing decimal progress does not rebuild k. Position/before changes invalidate results but retain a currently valid k selector. All selection updates use stable field IDs and native keyboard behavior. A disabled k field has adjacent text explaining that Generate creates its options; no focus is moved into it automatically.

Any numeric input/compositionstart or relevant select/checkbox change immediately clears generated table/graph/markers/CSS/status, disables Select CSS, and drops the result snapshot before further work. If focus is inside removed output, move it to Generate; otherwise preserve focus. A composition Enter does nothing, and compositionend does not auto-generate. Editing cannot leave selectable stale CSS. Generate twice replaces the prior snapshot and creates no duplicate nodes/listeners. Failed generation also leaves no old output. A successful snapshot includes N, position, exact rational p, chosen mode/k, before, output, all boundary rows and CSS; every view derives solely from it.

Two example buttons: Defaults sets initial raw/control defaults; Both endpoints sets N4, jump-both, decimal1, before=false. Both discard boundary selector/output/errors and remain focused on their button. Reset restores defaults and focuses N. Language switch preserves raw fields, selector/model and error codes, translates presentation and lang/title/description; it never reparses dirty values or changes CSS/numbers. Both language pages must expose the same whole interface and help. If navigation to another language page is used instead, this same in-memory contract must be preserved without URL/storage; therefore implement language as an in-page toggle with normal static alternate-page links separately marked “opens defaults”. Static homepage links match language. No background fetch on language toggle.

Select CSS is available only for a valid result: focus/select a readonly textarea, announce “selected; copy manually”, never “copied”. User can Tab and select manually if programmatic selection is unavailable. No clipboard reads/writes or download. All graph and marker information has a table/text equivalent. The visual is not the only way to distinguish values or included/excluded points.

On pagehide or document.hidden clear result and boundary selector; preserve raw fields but no valid generated output. Returning does not auto-generate. pageshow.persisted also clears generated state/options; a fresh load uses defaults. Reset/locale navigation/reload rules are distinct. No claim to erase browser history or memory. Unsupported BigInt/SVG capability shows a finite explanatory unavailable message and disables Generate; static help remains accessible. JS-disabled notice is static and controls are initially disabled until initialization succeeds. No unbounded retry/polling/animation loop.

Use native labels, fieldsets/legends, buttons/selects/checkboxes; no invented spinbutton role on text inputs. Table caption, column headers and ID-based graph descriptions explain before and after values. Announce generation/errors only, not every character. All text contrast>=4.5:1 on its actual opaque sRGB background; control-identifying boundaries and focus indicators>=3:1 against directly adjacent colors. Include default/focus/hover/invalid/generated states and both languages, record computed colors/unrounded ratios. Disabled controls are separately described, their explanation still meets text contrast. Use solid backgrounds; no color-only coding. At1280×800 and320×800 CSSpx and200% zoom, ordinary fields/buttons/help reflow without page-level horizontal scrolling; graph/table/code may have labelled keyboard-scrollable wrappers. ## 3. Inputs, exact output and formatting

Only app-owned strings/enums/Boolean enter the pure core; no JSON import or property getters. The pure entry receives an ordinary object of exactly five own data fields N, position, progress, mode, before, plus k only in boundary mode; reject arrays/null/accessors/Symbol/extra/missing keys before reading field values. DOM adapter constructs this object itself. Numeric controls' input.value is raw state; never valueAsNumber/parseFloat or browser validity as the parser.

N raw:1..16 UTF-16 code units, full-match ASCII `[1-9][0-9]*`, then integer range1..100, then reject N1/jump-none. Progress decimal raw:1..16 code units, full-match ASCII `(?:0|1)(?:\.[0-9]{1,6})?`, then exact range0..1 (so1.000001 is range error,2 is format error under this closed grammar). No whitespace, signs, exponents, leading zeros, empty decimal fraction, Unicode digits, comma, units, NaN or Infinity. Require the matched text equals the complete raw; do not rely on JavaScript $ accepting a final newline. Check length before grammar before numeric range. No HTML maxlength truncation. Raw means value exposed by the single-line text control, not original clipboard bytes: HTML strips CR/LF; a paste containing line breaks may be concatenated before the app sees it. Pure-parser newline rejection and native sanitization observation are separate tests. No clipboard access is added to recover unavailable bytes.

Position must be exactly one of jump-start/jump-end/jump-none/jump-both; mode exactly decimal/boundary, before actual Boolean. In boundary mode k is an integer supplied only from the generated native selector or bootstrap0, inclusive0..N; pure core rejects noninteger/outside k rather than clamping. For decimal mode no k key is allowed. Parse decimal p to integer millionths P by right-padding fractional digits; retain rational P/1000000 reduced. In boundary mode p=k/N exactly, never from displayed decimal. Exact boundary mode can represent1/3; decimal0.333333 is slightly below it, decimal0.333334 above. UI labels the mode on every result and never claims these values are equal.

Outputs include normalized N/position, input mode and exact p, before flag, integer floor/current step, jump denominator J, exact output fraction y, rounded p/y percentages, static markers, every boundary k/N with both before values, CSS. Endpoint clipping in the official unit-domain rule is explained; before at p0 is not an outside-domain left-limit request.

Use reduced BigInt rational arithmetic. All core equality/integrality/comparison is exact, with positive denominator. Fractions display integer without /1; otherwise numerator/denominator. Display p/y as percentages with exactly4 decimal digits, nearest with half-away-from-zero and retained trailing zeros; zero unsigned0.0000%. Every decimal labelled rounded; exact fractions remain adjacent. Example1/3→33.3333%,2/3→66.6667%,1/32→3.1250%. Numeric display is invariant across language and never feeds the core. Rational products here are bounded but still checked; finite cardinality max101 table rows and100 intervals.

CSS exact UTF-8 string: `animation-timing-function: steps(N, POSITION);` followed by one LF. One space after colon and comma, no BOM/CR/trailing spaces or comments. N is canonical integer and POSITION one of the four exact canonical enums. Initial example yields `animation-timing-function: steps(4, jump-end);\n`. Before flag and selected p do NOT enter CSS; help explains they inspect the function, not CSS parameters. CSS alone does not create an animation. No browser CSSOM serialization equivalence is assumed.

## 4. Implementation, math and fixed toolchain/security interface

Pure modules parse/compute/table/serialize; controller owns immutable snapshots and invalidation; DOM/SVG adapter uses only safe known sinks. No product code accompanies this document. No math from SVG coordinate readback or previous rounded output.

For exact p in[0,1], calculate h=floor(p*N). Let c=h+1 for jump-start/jump-both, otherwise c=h. If before=true AND p*N is exactly an integer, decrement c. Clamp c to at least0 (unit-domain lower rule). Set J=N for start/end, N−1 for none, N+1 for both. J is always positive after validation. Clamp c to at mostJ (unit-domain upper rule). Return y=c/J reduced. Record h, adjusted c and J so interpretation is traceable; do not use epsilon, floating-floor shortcuts or just subtract one at every point when before=true. All per-point work bounded; table calls this exact function2*(N+1) times and graph adds N midpoint evaluations. There is no numerical inversion or iterative root solver.

Graph: viewBox0 0 1000 600, axes input[0,1] horizontal and output[0,1] bottom-to-top. Map p→80+840p; y→520−440y. Safe conversion to finite Number occurs only at final rendered coordinates. Draw one horizontal segment for each open interval(k/N,(k+1)/N) at y from its exact midpoint and before=false. At each boundary draw hollow diamond at before=true output and filled circle at before=false output; when both equal draw one filled circle with label “same”. These marker conventions show the two explicit function evaluations, not necessarily analytic left/right limits outside[0,1]. At p0 label “unit-domain boundary”; the lower clamp means no negative output even with before. Vertical connectors use dashed explanatory lines, not claimed attainable intermediate values. Adjacent help states horizontal interiors are constant; selected exact boundary and decimal point are separately labelled. Visual axes and legend never imply all diagonal connector points are outputs. The table lists all k0..N, exact input, both output fractions/rounded percentages and whether values differ; this is the complete accessible alternative when graph marks overlap at N100.

Static marker tracks: fixed normalized horizontal domain[0,1], labels0%/100%, separate linear p and eased y markers with different shapes and text. Centers computed within usable width after marker radius; no transforms/animations interpolate between samples. Actual small viewport can show a scroll wrapper, not distort p/y. No zero-size/NaN geometry renders misleading markers: show size-unavailable text and retain table/CSS. Resize recomputes visual geometry only, never numeric snapshot or focus.
