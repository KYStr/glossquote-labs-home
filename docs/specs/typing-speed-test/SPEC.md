# Typing Speed Test — full preparatory specification v0.1

Specification documentation only; no product claim, readiness event or implementation. This document is the normative contract a future production task must satisfy exactly; where it says MUST, a differing behaviour is a defect, not a variation. A typing score is only meaningful if the scoring rule is fixed and visible: this specification pins the formulas, the alignment rule and the timing rule, and requires the product to show them on the results screen.

## 1. Goal
Primary audience: job seekers preparing for data-entry or clerical roles, students, and anyone benchmarking a new keyboard. The recurring problem: online typing tests are ad-heavy, each computes its headline number differently, and many treat keystrokes as data worth uploading. Success is observable: the user chooses 30 or 60 seconds and English or Traditional Chinese, types against a bundled passage with live per-character correctness, and receives a result computed by the exact rules of section 4 — gross/net WPM for English, correct characters per minute for Chinese, accuracy, and a review of what was mistyped — then can retry with a different passage. Non-goals: accounts, leaderboards, score history, custom or imported passages, typing tuition/lessons, and competitive anti-cheat (the result is for the user; nothing is certified).

Assumptions: a modern desktop browser and a physical keyboard (touch keyboards are not a scored environment; the page MUST say so); passages are bundled with the tool.

## 2. Scope and functional distinction
Included: (a) two durations (30 s, 60 s) and two passage languages (English, Traditional Chinese) selectable before an attempt; (b) a bundled passage set — at least 6 English and 6 Chinese passages meeting section 4's content rules, drawn without repetition within a session until the set is exhausted; a "new passage" control abandons the current attempt (with confirmation if typing has started); (c) the attempt: first committed character starts the timer; live positional correctness rendering; input locks at expiry or at passage completion; (d) results: the section 4 metrics, a correctness-coloured review of the typed region, and the list of mistyped words (English) or characters (Chinese) with expected-vs-typed pairs; (e) retry (same or new passage). Excluded: pausing, resuming, mid-attempt duration/language changes (controls lock during an attempt), accounts/storage/upload, sound, and per-keystroke analytics of any kind (the attempt exists in memory only and is discarded on retry, navigation or reload).
Distinction from existing work: Focus Timer counts down minutes for work sessions; Text Workbench transforms pasted text. Neither captures timed input against a reference text nor scores positional accuracy. No catalog entry, reserved specification or registry task at admission time measures typing; the admission check MUST be re-run against the fresh registry before production, and a collision stops the task for coordinator decision rather than a rename.

## 3. User flow and lifecycle
Setup state: duration and language selectors, the passage displayed in full (untyped styling), an empty input capturing focus on click/keypress, and the scoring rules summarised in one visible line ("Net WPM = correct characters ÷ 5 ÷ minutes — full rules below") with the full rules in a details section. No countdown runs before the first character.
Attempt state: the first input event that commits a character starts the timer at that moment; a visible countdown shows remaining seconds (and a progress bar). Each character cell of the passage reflects the current typed string positionally: untyped / correct / incorrect, with incorrect also distinguished by underline or symbol, never colour alone. The current position is visibly marked. Backspace works normally (it shortens the typed string; the display follows the string). Paste into the input is prevented (the control rejects paste events and says why, once, non-modally).
End states: (i) time expiry — input locks immediately, results computed from the final string and the full chosen duration; (ii) completion — the typed string reaches the passage length before expiry: input locks, results computed with elapsed time = actual seconds from start to the completing keystroke (shown to one decimal). Results state shows all metrics, the review rendering, the mistyped-units list, the passage's name/source line, and retry controls. Abandoning via "new passage" or changing selectors during an attempt asks for confirmation and discards the attempt.
Nothing persists: reload or navigation returns to setup with a fresh passage. Identical (passage, typed string, duration/elapsed) inputs always produce identical metrics — the formulas have no hidden terms.

## 4. Passages, input model and exact scoring
Passage content rules: English passages are 600–900 characters of plain prose (letters, spaces, and the punctuation set `. , ; : ' ? !` plus capitalisation), no digits, no double spaces, no leading/trailing space, single spaces only; each is public domain or written for this tool. Chinese passages are 300–500 characters, common-use characters only, punctuation limited to `，。、；：？！「」`, no spaces, each public domain or written for this tool. Every passage ships with a source line in `PASSAGES.md` (title/author or "original for GlossQuote Labs", and the public-domain basis where claimed). A test-mode fixture passage set (short, fixed) is used by automated tests; the product passages and fixture passages are distinct files.
Input model: the attempt state is exactly one string (the committed typed text). The input control accepts typed characters up to the passage length; characters beyond are refused. Comparison is strictly positional: position i is correct iff typed[i] equals passage[i] (compared as Unicode code points; the passage sets contain no characters outside the BMP and no combining sequences — content tests MUST verify this, so code-point and UTF-16 indexing coincide). There is no realignment: a missed character makes every later position wrong until the user backspaces and fixes the string — this is the stated, visible rule, and the live display makes it obvious. IME (for Chinese): text being composed is not part of the committed string and is not displayed as scored; composition commits append to the string and start the timer if it is the first commit. (A zhuyin/pinyin user therefore competes on committed characters; the help text states that the clock starts at the first committed character.)
Scoring (normative): let T = typed string length at lock, C = number of correct positions, E = elapsed seconds (chosen duration at expiry, or actual elapsed at completion, one decimal). accuracy = C / T (T = 0 → no result; the results screen is replaced by "no characters typed"). English: grossWPM = (T / 5) / (E / 60); netWPM = (C / 5) / (E / 60) — note netWPM is defined directly from correct characters, not as gross × accuracy, so rounding never disagrees. Chinese: grossCPM = T / (E / 60); netCPM = C / (E / 60), and the headline label is "字元/分鐘 (CPM)" — the letters "WPM" MUST NOT appear in the Chinese results. Display rounding: WPM/CPM values round to the nearest integer, halves away from zero; accuracy displays as a percentage with one decimal (e.g. 93.3%). The unrounded values are used in any further display (there are none — no averages across attempts exist).
Review data: the review rendering colours each typed position; the mistyped-units list groups errors by word for English (word = maximal run between spaces; a word is mistyped if any of its positions is wrong; the entry shows expected word and the typed substring at those positions) and by character for Chinese (expected char, typed char, occurrence count). Untyped passage beyond T is shown as not attempted and is not an error.
Worked fixtures (normative; fixture passage `The quick brown fox jumps over the lazy dog.` — 45 characters including the final period): (1) typed exactly, 30 s duration, expiry end: T=45, C=45, gross = net = (45/5)/(30/60) = 18 WPM, accuracy 100.0%. (2) 60 s, T=50 with exactly 5 wrong positions: gross = (50/5)/1 = 10, net = (45/5)/1 = 9, accuracy 90.0%. (3) Completion: the 45-char passage typed exactly, completing keystroke at 20.0 s: E=20.0, net = (45/5)/(20/60) = 27 WPM. (4) Chinese fixture passage of 10 characters typed with 8 correct in a 30 s expiry: netCPM = 8/0.5 = 16, grossCPM = 20, accuracy 80.0%.

## 5. Implementation and safety
Architecture (future production): a pure core (positional comparison, scoring, review grouping, passage validation) with zero DOM access; a controller owning the timer (monotonic clock), attempt state and lock transitions; a thin DOM layer. Runtime dependencies: none.
Timing integrity: the countdown uses a monotonic clock (performance.now via the controller); the end condition is checked on animation frames or a ≤100 ms interval — input MUST lock within 150 ms of the true expiry so late keystrokes cannot inflate T; characters committed after lock are refused. The displayed remaining time is derived from the same clock, never from counting interval firings.
Privacy/security: no network, no storage; typed text renders only as the passage overlay (built from text nodes); nothing typed is copied, logged or placed in the URL. The passage texts are static assets.
Bilingual and accessibility: the UI is zh-TW and English in both passage languages (a user may take the English test with the Chinese UI and vice versa; all four combinations work). The typing area is operable by keyboard alone (it is a text input); the live correctness rendering is supplemented by the results review, which is fully textual (correct/incorrect lists do not require perceiving the colours); the countdown is not announced every second (a polite announcement at start, 10 seconds remaining, and end only). Reduced-motion: no animated decorations during an attempt.
Toolchain: Node 24, zero npm dependencies, house layout (public/, public/en/, core modules, node:test suites, build/check/serve scripts); runs offline from file:// or any static host. Passage content tests (length, charset, no double spaces, BMP-only) run in the core suite.

## 6. Independent nine-aspect product rubric
Each aspect is scored 0–100 by a reviewer who is not the author, against the same fixed candidate commit; every aspect MUST reach ≥90 with all mandatory checks complete, otherwise the verdict is revision. Unrun checks stay NOT_RUN and block acceptance.
- functionality: both UI languages × both passage languages; both durations; expiry and completion endings; retry and new-passage flows; results and review complete.
- boundaries: T=0 expiry (no-result state); single character; completion at the exact final character; backspace corrections before lock; input beyond passage length refused; paste refusal.
- privacy: zero network after load; no storage; typed text absent from URL/title; attempt discarded on reload.
- security: passage and typed text render as text only; no external resources; no eval/Function.
- usability: a first-time user starts an attempt without instructions beyond the page; the positional rule surprises no one because the live display teaches it; the results screen's formula line matches section 4.
- accessibility: keyboard-only completion; countdown announcements restrained as specified; review fully textual; correctness never colour-only.
- localization-seo: zh-TW and en UI complete across all four language combinations; correct lang attributes, titles, descriptions and same-language home links.
- toolchain-provenance: zero-dependency build reproduces byte-identical output on Node 24; PASSAGES.md sources check out (public-domain claims verifiable); passage validation suite passes.
- compatibility: current Chrome/Edge/Firefox/Safari desktop with a physical keyboard; IME composition behaviour for Chinese verified in at least one real zhuyin or pinyin IME on desktop.

## 7. Required tests and timing
Core unit tests with independently derived expectations: (a) the four section 4 fixtures exactly, including display rounding (a net value of 9.5 → 10; accuracy 2/3 → 66.7%); (b) positional comparison: one early error poisoning later positions until corrected via a shortened string; backspace-then-fix yielding full correctness; (c) passage validators: length windows, charset and punctuation sets, double-space and BMP checks, PASSAGES.md entry per passage; (d) review grouping: word-level for English (multi-error word listed once with its typed substring), character-level counts for Chinese; (e) timing model with an injected clock: start on first commit, lock at expiry ±0, completion elapsed recorded to 0.1 s, IME composition text excluded until commit.
GUI/evidence tests (desktop, real browser, physical or synthetic keyboard events through the real input): a scripted attempt reproducing fixture (2) through actual key events; paste attempt refused; countdown lock timing observed; results screenshotted in both UI languages. Timing: full core suite under 60 seconds; no network in any test.
Explicitly NOT_RUN at specification stage: all product tests above; this document claims document completeness only.
