# Markdown Preview and HTML Export — preparatory BRIEF v0.1

Specification documentation only; no product claim, readiness event or implementation. Full normative contract is SPEC.md.

## 1. Goal
A writer, student or engineer drafting a README, note or document in Markdown needs to see exactly how it will render and to export a single self-contained HTML file they can share — without pasting their draft into an advertising-driven online previewer that ships the text to a server. Success: type or paste Markdown on the left, watch a correctly rendered preview on the right that follows the stated CommonMark-based rule set, spot the constructs this tool deliberately does not support listed honestly, and download one standalone HTML file (inline styles, no external requests) whose rendering matches the preview. Everything is local; the draft never leaves the device.

## 2. Scope and functional distinction
A defined Markdown subset, specified construct-by-construct in the SPEC following CommonMark semantics for: headings 1–6, paragraphs, bold/italic/strikethrough, inline code, code blocks with language label (no remote highlighting themes — a fixed local token colouring for a stated language set, or plain), links and images (with the safety rules below), blockquotes, ordered/unordered/task lists, horizontal rules, tables (pipe syntax with alignment), and hard/soft line breaks. Raw HTML in the source is escaped and shown as text, never executed — this is a deliberate, stated limitation, together with: no footnotes, no math, no Mermaid/diagrams, no emoji shortcodes, no reference-style link definitions beyond the stated subset (the SPEC fixes exactly which). Live split preview with synchronised scrolling (proportional), a rendered-word/character count, copy-HTML button, download of a standalone HTML document built from the preview with inlined house stylesheet, and a plain-text sample document loaded only on explicit user click. No server rendering, no cloud save, no collaborative editing, no PDF export, no syntax-highlighting downloads, no URL fetching for link previews.

Existing tools: Text Workbench cleans and counts plain text but renders nothing; Template Merge substitutes placeholders into a template — a different operation with different output guarantees; the JSON/Text workbenches target data formats. None parses Markdown block/inline structure, sanitises generated HTML, or exports a styled standalone document. Initial catalog/spec/task scope contains no Markdown renderer; fresh registry/path/draft check remains mandatory before admission. The SPEC must pin the subset with positive and negative fixtures per construct so two implementations render identically, and must treat sanitisation as a correctness property: the export must be safe to open even when the source contains hostile markup.
