# 間歇計時器 / Interval Timer — BRIEF

**文件草案，產品檢查 NOT_RUN** · `spec-interval-timer-20261109`

做間歇訓練（Tabata、HIIT、肌力組間休息）的人，需要的不是單段倒數，而是一整份「準備 → 運動 → 休息 → 運動 …」的多段節目：每段幾秒、共幾回合、最後一回合後要不要再休息，都要先算清楚。現成計時器常只給單段倒數，或節目表與實際計時各算各的。本工具先以準備／運動／休息秒數與回合數產生一份逐段列明的完整節目表與總時長（純函數、逐段可核對），再以同一份節目表驅動即時計時核心：核心只吃「已進行的活動毫秒數」，暫停期間不計入，段界規則與提示事件全部釘死。

MVP 範圍。四個整數欄位（準備、運動、休息秒數、回合數）加一個「最後一回合休息」選項；純核心產生段表（段序、種類、所屬回合、起訖秒數）與總時長；狀態機核心以 start／tick／pause／resume／skip／reset 事件推進，輸出目前段、剩餘秒數（ceil 顯示）與 cue 事件（segmentStart／programEnd）。非目標為實際播放聲音或震動（屬 controller／DOM 層，核心只發事件）、系統通知、背景或鎖屏持續計時保證、音訊檔、訓練紀錄或歷史、帳號、跨分頁同步。

與既有 legacy `focus-timer` 的差異（已讀其 README 與核心）：該工具是**單段** 1–180 分鐘倒數（開始、暫停、繼續、取消），沒有段表、回合或段界提示；本工具是**多段節目**（準備＋回合×（運動＋休息）），核心產物先是可核對的節目表，再是逐段推進的狀態機。與 legacy `metronome` 的差異：節拍器是連續等距拍點，無段落、回合與總時長概念。

首個可觀察案例。Tabata 型節目（`tabata-classic`）：準備 10 秒、運動 20 秒、休息 10 秒、8 回合、最後一回合不休息，得 16 段、總時長 240 秒，段表逐段列明起訖。字面資料與預期見 [fixtures.json](fixtures.json)，契約以 [SPEC.md](SPEC.md) 為準。
