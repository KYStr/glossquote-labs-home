# SVG Dash Cycle Explorer — complete preparatory specification v0.2

Status: DRAFT_FOR_INDEPENDENT_DOCUMENT_REVIEW. Prepared 2026-11-01 UTC. No product implementation or claim exists for this draft.

## 1. Goal and successful user outcome
Help a site maintainer understand dash/gap repetition, odd-list duplication and positive/negative phase for a simple SVG line. The user edits a bounded sequence and offset, sees native SVG plus a tabular inventory of visible painted intervals, and manually selects a deterministic SVG snippet. Success: predict where the first visible dash begins, understand a gap-first start, and identify why an odd three-number pattern is six alternating segments. This is a use-case hypothesis, not evidence of user demand.

## 2. Scope, deliberate limits and non-overlap
Exactly one horizontal line from (0,10) to (L,10), stroke width4, butt caps, no fill, fixed solid color. Integer user units only. Dash list1..8 entries, each integer1..100, signed integer offset -1000..1000 and integer line length1..400. A solid-mode checkbox emits stroke-dasharray=none and disables dash/offset controls; raw values are preserved but ignored until reenabled and then revalidated. Native SVG and independent table share one validated snapshot.

No uploaded SVG, paths/curves/circles/closed subpaths, percent units, pathLength, transforms, zero dash/gap, variable stroke width, round/square caps, joins, gradients, animation, clip/mask, code parser, SVG sanitizer, icon editor, drawing app, file/download or clipboard API. Excluding zero entries avoids zero-length cap/segment ambiguities while still teaching ordinary patterns; limitations must be visible, not hidden in source.

Catalog's image-resizer/contact-sheet/overlay work on supplied raster images, not constructed stroke intervals. Clip-path Polygon solves fill geometry, topology and CSS polygon clipping, not stroke segmentation. Linear Gradient Builder handles color stops, not periodic painted/gap intervals. Steps/Cubic easing handle time progression, not spatial dash cycles. Box Shadow and Elliptical Corners do not compute stroke phase. None of the 56 current catalog entries describes an SVG stroke editor; no existing 82 spec/88 task title/scope or inspected cloud-draft collection supplies this same input-output flow. This comparison is bounded to accessible evidence; any new overlapping owner discovered at admission blocks this draft's registration until resolved. Do not treat a different name as adequate de-duplication.

## 3. User flow and state machine
Initial generated example: line length100,dash rows10 and5,offset0,solid false. Controls: length, solid checkbox, numbered dash inputs with Add/Remove buttons, offset, Generate, Reset; then native line, normalized pattern/period/phase summary, interval table and readonly selectable snippet. Numeric edits, checkbox and row changes immediately clear old output and mark dirty. Native preview is not regenerated during partial entry.

Add appends a row value5, up to8; button disabled at8. Remove uses an explicit labeled button on each row, disabled at1; focus moves to next row's input or prior last input. Row sequence order matters; no reorder feature is required (edit values instead). Generate validates active fields in length/rows/offset order; all field errors listed, first invalid focused, no partial output. Success retains Generate focus and announces result. Repeated Generate is idempotent. Solid mode skips validation of preserved dash/offset raw strings, hides their errors, and outputs a solid line; toggling back requires validation and never silently fixes them.

Reset restores defaults immediately and generated output, clears errors, focus stays Reset. A client-side language switch updates all copy/document metadata while retaining raw rows, solid selection, state and identical numerical/SVG result; focus stays corresponding language control. Direct language-page entry and reload start defaults. Back/Forward may retain coherent BFCache state; pageshow verifies snapshot corresponds to active inputs, otherwise clears it to dirty. No persistent storage, URL state or recovery promise.

## 4. Input, algorithm and deterministic output
Text input raw length <=12 UTF-16 code units BEFORE ASCII space/tab/CR/LF trim. Active unsigned grammar `[0-9]+`, offset grammar `-?[0-9]+`; leading zeroes and -0 accepted and canonicalized to plain integers/0. Plus, decimal, exponent, comma, Unicode whitespace/digits, empty, NaN and Infinity rejected. Apply length, grammar, then inclusive numeric range. Retain raw input unchanged until reset; output canonical only. List entries are individual controls, not a comma parser. Reject row count outside1..8 even if forged state reaches core. Solid mode still validates length and boolean enum, ignores (does not export) inactive raw dash values.

Restricted mathematical contract, independently implemented from native SVG: duplicate an odd-length list once to obtain an even sequence A of alternating painted/gap lengths, starting painted. Let P=sum(A), and normalized phase q=((offset mod P)+P) mod P. At distance x along the line, its cycle position is (x+q) mod P. Partition [0,L) at segment boundaries; even-index segments are painted. Intersect each painted segment with [0,L); return sorted positive-length half-open intervals [start,end). Boundary exactly at segment end belongs to following segment. Do not output zero-length intervals. Use exact integer arithmetic. Offset sign follows native SVG stroke-dashoffset semantics; negative offsets delay the initial pattern. Reference [W3C SVG Painting §13.5.6](https://www.w3.org/TR/SVG/painting.html#StrokeDashing). This model intentionally excludes zero segments, non-butt caps and arbitrary paths.

An implementation may advance through bounded positive segments after locating q; loop guard <= 2*L+16 iterations and <=400 painted intervals protects forged input. Given minimum segment1 and L<=400 these bounds exceed valid work. A guard hit is an internal error with no partial output, not silent truncation. Solid mode returns [0,L), period and phase displayed as not applicable and no normalized dash list. Dashed output shows original canonical list, even normalized list, P,q, and each painted start/end/length. All lengths are SVG user units, not claims of physical pixels.

Canonical snippet exact format (LF and terminal LF): `<svg xmlns="http://www.w3.org/2000/svg" viewBox="0 0 L 20" role="img" aria-label="Dashed line preview">` then two spaces and `<line x1="0" y1="10" x2="L" y2="10" fill="none" stroke="#334155" stroke-width="4" stroke-linecap="butt" stroke-dasharray="D" stroke-dashoffset="O" />`, then `</svg>`. D is original canonical list joined by one ASCII space (odd list NOT silently expanded in snippet); O is canonical original signed offset, not q. In solid mode D=none,O=0 and aria-label is `Solid line preview`. Snippet is intentionally language-invariant ASCII with documented English accessibility text; on-page native SVG uses localized accessible label. Original sign/phase equivalence can be inspected rather than hidden. No user-supplied label/markup is accepted.

Native preview uses an actual SVG line with those numeric attributes and original offset. At standard layout set width=L CSS px,height20 CSS px (1 unit=1 CSS px); wrap in a labeled horizontally scrollable region for narrow viewport, no stretch. A separate optional zoomed schematic is out of v1 scope. Fixed ruler outside SVG shows 0 and L; table labels communicate intervals without color dependence. Preview must render dashes through native stroke-dasharray, not by drawing precomputed rectangles: independence is necessary to detect model/native disagreement.

### Timing measurement protocol (F1 clarification)
The <=100ms bound measures application completion to a presentation opportunity, NOT physical paint, GPU completion or user-perceived latency. Use the foreground visible tab, no CPU/network throttling, no open modal, and record browser/OS/hardware, viewport, DPR and zoom without imposing a new hardware class. Fixed maximum-work input: L=400,list[1,1],offset0 (200 painted intervals and table rows). For each trial make a valid edit to mark dirty (retain the fixed fixture values before Generate), then record t0=performance.now() at the start of the Generate handler, before validation. After synchronous validation/derivation and all result DOM updates have completed, enqueue one requestAnimationFrame and record t1=performance.now() inside its callback. Duration=t1-t0. Run five complete unrecorded warm-up trials, then twenty measured trials sequentially; do not start the next edit/generate until the previous callback has completed. Retain all twenty raw durations, maximum and pass/fail; every measured trial must be <=100ms. Hidden-tab, throttled or interrupted trials are invalid observations, retained with reason and rerun under the defined visible condition, not silently discarded for slowness. A slow valid trial is a failure, not an excuse to redefine the budget. No timers/RAF are claimed to prove actual raster paint; native appearance remains the separate screenshot/geometry matrix. If performance.now/rAF observation is unavailable, mark this required check NOT_RUN and do not replace it with Node CPU timing.
