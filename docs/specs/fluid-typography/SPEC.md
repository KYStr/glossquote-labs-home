# Fluid Typography Calculator — complete preparatory specification v0.2

Status: unregistered specification publication candidate, prepared 2026-10-31. Not a product, GitHub claim, formal ready-inventory record, or accepted quality score. Proposed repository path: `docs/specs/fluid-typography/`. Publication and formal admission remain separately authorized steps.

## 1. Brief: goal, audience, non-duplication

A frontend author needs one bounded font-size declaration that grows smoothly between two viewport widths, with a readable lower and upper size. Deliver one deterministic CSS declaration and an explicit numerical explanation, without installing packages, fonts, accounts, network calls, or granting clipboard/download permission. The normal result should take fewer than six numeric edits and one Generate action.

This is not general unit conversion: it solves two endpoint constraints into a CSS sizing rule. It is not Grid layout, Gradient color stops, Box Shadow geometry, or Cubic Bezier animation timing. A bounded comparison against the registered tools, catalog and existing proposals found no matching typography tool at preparation time. This is not proof of unknown unpublished work. Repeat current collision checks before registration/publication; preserve existing ownership.

Product scope: one increasing or constant font-size rule; bilingual Traditional Chinese/English; four endpoint numbers in rem; explanatory reference root size; numerical simulated sample width; safe sample text; selectable CSS output. Out of scope: font hosting/upload, font pairing, modular scales, multiple headings, decreasing sizes, line-height automation, container-query units, arbitrary CSS import, live-site editing, analytics, user accounts, public deployment, clipboard API and downloads. No product code accompanies this draft.

## 2. User journey and UX contract

At first visit show a complete worked example: viewport 20–80 rem, size 1–2 rem, reference root16 px, simulated width800 px. Inputs are labelled with units, not placeholder-only. A persistent explanation says viewport breakpoints are rem-based; 320–1280 px are examples only at root16 px. Never set the host page's root font-size to the reference input.

1. User edits minimum/maximum viewport rem and minimum/maximum font rem. Reference root changes explanatory pixel conversions only. The sample-width input selects a hypothetical viewport for the mathematical preview.
2. Any endpoint edit immediately invalidates generated CSS and disables Select CSS until Generate succeeds. Old successful output must not remain apparently current. Preserve edited values; no hidden auto-correction or endpoint swapping.
3. Generate validates all numeric fields; numeric failure clears output/table/summary/preview and focuses the first numeric error. Sample-text validity is independent: over-limit text shows its associated error and an empty preview but does not block numeric generation or CSS selection. On numeric success show: one declaration, endpoint table, current sample result, limiting state (minimum/fluid/maximum/constant), and the reference-root assumption. A short polite live-region summary announces generation, not every keystroke.
4. Select CSS focuses and selects a read-only textarea; user invokes ordinary OS Copy. No automatic clipboard call. Instruction and selection feedback must work without permission prompts; denied manual OS Copy is outside app control and must not be falsely reported successful.
5. Sample text changes affect preview text only, never CSS; use textContent. If text exceeds 240 Unicode code points, retain the complete raw text in its editor, show a linked length error and clear only the text preview. Preserve existing valid CSS, its selectable state, numerical table and summary. Do not truncate or render the over-limit text. Returning to 240 or fewer code points restores the preview immediately using the current generated numbers, with no Generate needed; if numbers are dirty/invalid, the preview stays empty until numeric generation succeeds. Language changes retain this state and translate the error; Reset clears it. Fixed bilingual default sample is available through Reset. Preview is labelled “mathematical simulation, not this panel's native vw rendering.” Render its computed hypothetical pixel font size in a bounded scrollable sample, without changing UI typography or creating a horizontal page scrollbar.
6. Reset restores exact defaults, removes errors/output and moves focus to first endpoint. Language toggle preserves numeric input and valid generated bytes; translates labels/errors/summary, updates lang, no automatic regeneration or focus loss. Navigation/reload holds no persistent custom input. No local/session storage, URL query state or remote saving.

At 320 CSS-px page width all controls stack; CSS textarea may horizontally scroll internally. Text at200% zoom must remain usable. No drag-only control. Tab order is input order → Generate → Select CSS → Reset → language toggle (place toggle consistently in DOM; actual design may put it first if documented). Every error is programmatically associated; visible focus/contrast and touch target sizes require native independent review. Example controls must say that replacing current entries is intentional. No modal required.

## 3. Input/output and mathematical contract

All numeric fields: trim ASCII outer whitespace; accept ASCII decimal grammar `(?:0|[1-9][0-9]*)(?:\.[0-9]{1,4})?` only. Reject signs, leading zeros except0, exponent notation, comma decimal, units, internal whitespace, Infinity/NaN, hexadecimal and empty values. Retain invalid raw text for correction. Limits are product scope, not claims about CSS limits.

| Field | Inclusive range | Default | Additional relation |
|---|---:|---:|---|
| Vmin, Vmax viewport rem | 6–240 |20,80|Vmax−Vmin ≥0.25|
| Fmin, Fmax font rem |0.5–10|1,2|Fmax ≥ Fmin|
| Reference root R, px/rem |8–32|16|explanation/simulation only|
| Simulated viewport W, CSS px |48–7680|800|does not resize browser|
| Sample text |0–240 Unicode code points|localized fixed text|plain text, no markup; preserve newlines; do not cut surrogate pairs|

Derivation (our design, not quoted from CSS specification): m=(Fmax−Fmin)/(Vmax−Vmin); a=Fmin−m·Vmin; b=100m. Output exactly `font-size: clamp(Fminrem, calc(arem + bvw), Fmaxrem);` with a newline terminator. Here placeholders replace numbers and concatenate to units, not literal identifiers. Negative a is emitted as a signed number, e.g. `calc(-0.5rem + 5vw)`; b is nonnegative. No user selector, property name, unit, or unparsed CSS enters serialization. Round a and b independently to8 decimal places, ties away from zero, strip trailing fractional zeros and dot, normalize negative zero to0; canonicalize each bound by stripping fractional trailing zeros and the now-empty decimal point, retaining the integer digit 0 when needed. Thus 1.0000, 1.0 and 1 all serialize as 1. Compare endpoints by parsed numeric value, never raw strings. Constant endpoints output `font-size: Fminrem;` plus “constant size” explanation rather than a pointless fluid expression. Locale never affects bytes.

Reference simulation evaluates exported rounded coefficients, not a separately rounded slope: S=max(Fmin·R,min(a_export·R+b_export·W/100,Fmax·R)). Let P=a_export·R+b_export·W/100. Limiting-state labels use these exported coefficients and exact parsed decimal arithmetic: constant when Fmin=Fmax; otherwise minimum if P≤Fmin·R, maximum if P≥Fmax·R, and fluid strictly between. Never classify by W/R design breakpoints, displayed rounded values or an epsilon, and never snap S back to a design endpoint. The endpoint table labels Vmin/Vmax as design breakpoints, not necessarily exact exported clamp transition locations. Unrounded ideal is used only for author arithmetic-error checks. Display S and converted endpoints to2 decimals with labels “approx.” while keep full calculation precision internally. Reference R modifies only simulated pixel values and endpoint pixel annotations; exported declaration must remain byte-identical. Real page root/viewport/zoom determine actual CSS behavior. Do not advertise guaranteed WCAG compliance or fixed pixel endpoints on every device.

Default result: `font-size: clamp(1rem, calc(0.66666667rem + 1.66666667vw), 2rem);` followed by newline. At root16: W320→16.000000064px (display16.00, fluid);800→24.00000008px (display24.00, fluid);1280→32px (maximum);1600→32px (maximum). At root20 W400→20.00000008px (display20.00, fluid),1000→30.0000001px (fluid),1600→40px (maximum). This explicitly documents rem breakpoint movement.

Eight-decimal coefficient rounding induces at most 0.5e−8·(R+W/100) px error before clamping within the specified simulation domain: ≤0.000000544px. Clamping cannot enlarge this coefficient error. Browser CSS serialization/layout precision is a separate native observation, not covered by that arithmetic bound.

## 4. Technical construction plan and boundaries

Future authorized implementer should use a pure decimal-validation/calculation/serialization module with no DOM, a small state controller, bilingual dictionaries, semantic HTML and scoped styles. Use the existing repository's actual approved toolchain after reading its instructions; do not invent a new framework, origin, workflow, dependency or package publication. Tests must exercise a pure mathematical oracle independent of serializer output. No implementation begins under this draft alone.

State: pristine → dirty/invalid → generated. Any endpoint/reference/sample-width edit clears the generated result because its table assumptions changed; text-only edit keeps numeric CSS/table/summary valid; it rerenders only a valid-length sample and clears the preview for over-limit text according to §2. Language-only edit keeps result valid. Generate has synchronous bounded computation, no retries, async jobs or network. Repeated Generate is deterministic and may not duplicate result panels or listeners. Sample text length error never injects HTML. When a numeric input invalidates the generated result, clear output, table, preview and summary too. The sample-text length error does not invalidate numeric results; it follows the separate §2 state rule even when Generate is clicked again.

Do not use dynamic style text injection for arbitrary strings. Only validated computed numeric font size reaches preview style; textContent receives text. No file access, network requests after static assets, third-party font/CDN dependencies, telemetry, service workers, storage, clipboard writes, permissions or downloads. Clear/Reset removes input-owned content from current app DOM/state; browser/OS memory erasure is not guaranteed. Pagehide resets ephemeral state; BFCache restoration must show defaults/no custom text (test the finite desktop baseline below). Browser history/local caches are platform-controlled; don't promise forensic deletion. No secrets or personal text belong in test evidence.

Development stages after separate admission: freeze approved spec and rubric; implement pure core; add data-driven bilingual UI/state; add actual responsive/native preview checks; author evidence with exact commit/manifest; independent nonauthor review of same candidate; report unresolved scores null; only later obtain publication authorization. Fixes return to original author, increment candidate, and re-review affected aspects without transferring old scores silently.
