# Placeholder Text Generator (Bilingual Lorem-Style Filler) — full preparatory specification v0.1

Specification documentation only; no product claim, readiness event or implementation. This document is the normative contract a future production task must satisfy exactly; where it says MUST, a differing behaviour is a defect, not a variation. Placeholder text has exactly one virtue — it fills space while meaning nothing — so this specification pins the generator to a seeded, fully reproducible algorithm over inspectable pools, and makes the non-meaning label part of the output contract rather than a marketing line.

## 1. Goal
Primary audience: web and print designers mocking layouts, front-end developers seeding templates and CMS themes, editors reserving space for copy that has not arrived, and teachers demonstrating typography. The recurring problem: filler copied from random websites is unreproducible (the client's mock cannot be regenerated), occasionally turns out to be real text in a language the designer cannot read (with real, sometimes embarrassing, meaning), and arrives in shapes (a wall of words) that do not match the unit the layout needs. Success is observable: the user chooses language, unit, count and seed, and receives filler whose generation they could re-run anywhere and get byte-identical output — paragraphs that look like paragraphs, an exact character count when the layout demands exactly that, and a label on the page stating the text is placeholder with no meaning. Non-goals: generating meaningful content of any kind (this tool must never drift into copywriting), novelty themed pools, lorem images, and layout/design features. Traditional Chinese filler deserves its own honesty note: the zh sentences are neutral everyday statements authored for this tool and assembled at random — individually grammatical, collectively meaningless — and the page says exactly that, instead of passing off scrambled real articles as "filler".

Assumptions: a modern desktop browser; generation is instant at the caps; no network at runtime.

## 2. Scope and functional distinction
Included: (a) two languages: Latin (lorem-style) and Traditional Chinese; (b) units: paragraphs, sentences, characters for both languages, plus words for Latin only (the zh UI disables the words unit with the reason stated: Chinese has no word spaces, so a "word count" would be fabricated); (c) count ranges: paragraphs 1–50, sentences 1–200, words 10–5,000, characters 10–20,000; (d) a uint32 seed (0–4,294,967,295), default 42, editable, with a "new seed" button that increments it by 1 (wrapping at the max to 0); output is a pure function of (language, unit, count, seed, opening toggle) — pressing Generate with unchanged settings yields the identical string, always; (e) Latin-only classic-opening toggle (default on): in paragraph and sentence modes the output begins with the canonical sentence `Lorem ipsum dolor sit amet, consectetur adipiscing elit.`; (f) output views: rendered paragraphs and a raw text view, with copy buttons for plain text (paragraphs joined by a blank line) and HTML (each paragraph wrapped in `<p>…</p>`, text escaped); (g) live facts: actual counts produced (paragraphs, sentences, words for Latin, code points) so the user can verify the request was honoured. Excluded: any other language, themes, per-word randomisation beyond the pinned model, saving, and URLs encoding the settings.
Distinction from existing work: Text Workbench transforms user text and Word Frequency analyses it; neither generates text. The password generator produces secrets with a CSPRNG — this tool deliberately uses a *seeded, reproducible* PRNG, the opposite requirement, and its output is labelled non-secret and meaningless. No catalog entry, reserved specification or registry task at admission time generates placeholder text; the admission check MUST be re-run against the fresh registry before production, and a collision stops the task for coordinator decision rather than a rename.

## 3. User flow and lifecycle
Initial state: Latin, paragraphs, count 3, seed 42, classic opening on — the output for those settings is already generated and shown, with the facts line reading 3 paragraphs and the placeholder label above the output. Changing any control regenerates immediately (generation is deterministic and fast); there is no separate surprise. The seed field always shows the seed that produced the visible output.
Copy actions copy exactly the shown string (plain or HTML form); a "copied" confirmation appears in text. Errors are per-field and specific: count out of range (bounds named), seed not a uint32 (non-numeric, negative, or above max named). While a field is invalid, output freezes at the last valid generation marked "out of date", and copy buttons disable — stale filler must not be copyable as if it matched the visible settings.
The placeholder label is persistent and non-dismissible, in the UI language: "Placeholder text — it has no meaning and is only for filling layout space." / 「填充文字——沒有意義，只用來佔據版面空間。」 In zh mode a second line explains the sentences are neutral samples assembled at random. Nothing persists across reload; generated text never appears in the URL or title.

## 4. Generation rules (normative)
PRNG: mulberry32 over a uint32 state a, seeded with the seed. Each draw: a ← (a + 0x6D2B79F5) mod 2^32; t ← a; t ← ((t XOR (t >> 15)) × (t OR 1)) mod 2^32; t ← t XOR ((t + (((t XOR (t >> 7)) × (t OR 61)) mod 2^32)) mod 2^32); value = ((t XOR (t >> 14)) mod 2^32) / 2^32, in [0, 1). All shifts are logical (unsigned) 32-bit shifts; multiplication is mod 2^32. An index draw for a pool of size n is floor(value × n). Draws are consumed in exactly the order the model below specifies — reordering draws is a defect, because the output is the contract.
Pools (data, shipped in the repository and shown in the product's about/help): the Latin word pool is the vocabulary of the traditional Lorem ipsum passage (the Cicero-derived text in the public domain), each distinct word exactly once, lowercase. The pool MUST ship as a data file transcribed from the canonical passage with its word count and a checksum recorded in the tests; a pool typed from memory inside code — or silently deduplicated/extended — is a defect, and the bijection-style audit in section 7 (no duplicates, count and checksum match) is how a transcription slip fails loudly. The zh sentence pool ships as a data file of at least 24 complete neutral sentences authored for this tool (everyday, content-free statements about weather, errands, rooms and objects, each ending with 。), printed in full in the product help — its content is reviewed as data, and any sentence carrying an opinion, a name, a brand or advice is a defect in the data.
Latin sentence model: a sentence's word count L = 6 + floor(draw × 9) (6–14); then L word draws pick words with replacement from the pool; the sentence is the words joined by single spaces, first word capitalised (first letter uppercase), terminated by `.`. If the classic opening is on, the first sentence of the output is the canonical opening sentence instead of a drawn one (it consumes no draws). Paragraph model: sentence count = 3 + floor(draw × 4) (3–6), drawn when the paragraph starts, before its sentences' draws (the opening sentence, when present, counts as the first sentence of the first paragraph and the paragraph's remaining sentences are drawn normally — the sentence-count draw still happens first, and the count includes the opening). Words unit: generate sentences by the same model until the cumulative word count ≥ requested, then cut the final sentence to land on exactly the requested number of words; the output is those sentences' text with the cut sentence terminated by `.` (if the cut lands exactly at a sentence end, nothing special happens). The words in the canonical opening count toward the total when the toggle is on (toggle applies to words mode too, stated).
zh model: a sentence is one draw from the zh sentence pool (with replacement; the same sentence may repeat — stated, since the pool is small by design). Paragraph = 2 + floor(draw × 3) sentences (2–4), count drawn first. Sentences are concatenated with no separator (each already ends with 。).
Characters unit (both languages): generate by the paragraph model (paragraphs until the cumulative length ≥ N), then truncate the plain-text form (paragraphs joined by a blank line, and the truncation may span the join) to exactly N Unicode code points; the facts line states the output was truncated to N characters and the final character may be mid-sentence. Counts everywhere are code points, never UTF-16 units — an astral character in a copied setting counts once (the pools contain none, but the counting rule is pinned for the join text and future data).
Worked fixtures (normative): (1) PRNG: mulberry32 seed 42's first eight draws are 0.601104, 0.448291, 0.852466, 0.669734, 0.174814, 0.526593, 0.273228, 0.624745 (6 decimals, truncated for display; the test compares full precision against its own implementation of the formula above). (2) Algorithm micro-fixture (test-only micro pool [alpha, beta, gamma, delta], Latin sentence model, seed 42, opening off): the length draw is 0.601104 → L = 6 + floor(0.601104 × 9) = 6 + 5 = **11 words**; the next draws pick floor(0.448291 × 4) = 1 → **beta**, floor(0.852466 × 4) = 3 → **delta**, floor(0.669734 × 4) = 2 → **gamma**, floor(0.174814 × 4) = 0 → **alpha**, floor(0.526593 × 4) = 2 → **gamma** — so the first sentence begins `Beta delta gamma alpha gamma …` (first word capitalised). (3) Determinism: identical settings produce identical output across runs and browsers — asserted as a property over the fixture corpus, with fixture 2 as the concrete anchor. (4) Characters: requesting 10 characters in Latin mode yields an output of exactly 10 code points beginning `Lorem ipsu` when the opening toggle is on (the canonical opening supplies the text), facts line noting truncation.

## 5. Implementation and safety
Architecture (future production): a pure core (PRNG, pools as data, the two language models, truncation, plain/HTML serialisers, counters) with zero DOM access; a controller; a thin DOM layer. Runtime dependencies: none. The PRNG MUST be implemented with explicit 32-bit unsigned arithmetic (Math.imul and >>> in JavaScript) so results are identical in every browser — a floating-point shortcut that changes one draw is a defect.
Privacy/security: settings and output are local; no network, no storage; generated text is rendered as text (the HTML copy format escapes `<`, `>`, `&` in the text before wrapping — the pools contain none, and the rule stands anyway); no eval/Function; no external resources.
Bilingual and accessibility: full zh-TW (default UI language) and English UI; the generator's two content languages are independent of the UI language and labelled in both; controls are native and labelled; the output area is a readable text region with the label always adjacent; keyboard-complete; copy confirmations in text.
Performance bounds: worst case (20,000 characters / 5,000 words) is a few thousand draws — instant; no debounce concerns. Toolchain: Node 24, zero npm dependencies, house layout (public/, public/en/, core modules, node:test suites, build/check/serve scripts); runs offline from file:// or any static host.

## 6. Independent nine-aspect product rubric
Each aspect is scored 0–100 by a reviewer who is not the author, against the same fixed candidate commit; every aspect MUST reach ≥90 with all mandatory checks complete, otherwise the verdict is revision. Unrun checks stay NOT_RUN and block acceptance.
- functionality: both UI languages; both content languages; all units; seed editing and increment; classic opening on/off in every applicable mode; plain and HTML copies byte-equal to the shown generation; facts line counts verified against the output.
- boundaries: every count at min and max and one beyond refused; seed 0 and 4,294,967,295 and one above refused; characters truncation exact at an astral-adjacent case and across a paragraph join; zh words unit disabled with its stated reason; repeated generation with identical settings byte-identical.
- privacy: zero network after load; no storage; settings and output absent from URL/title.
- security: output renders as text; the HTML copy escapes correctly (verified with a test-only pool containing markup characters); no external resources; no eval/Function.
- usability: a designer gets 3 paragraphs for a mock in under ten seconds without instructions; the seed's purpose ("same seed, same text") is understood from the page (spot-check).
- accessibility: labelled native controls; persistent label adjacent to output; copy confirmations as text; keyboard-complete; output readable as plain text region.
- localization-seo: zh-TW and en pages complete and equivalent (including the non-meaning label and the zh random-assembly note in both languages); correct lang attributes, titles, descriptions and same-language home links.
- toolchain-provenance: zero-dependency build reproduces byte-identical output on Node 24; both pools ship as auditable data (Latin pool count + checksum recorded in tests; zh pool printed in help matches the data file); the PRNG constants appear once.
- compatibility: current Chrome/Edge/Firefox/Safari desktop; fixture corpus outputs byte-identical across browsers (Math.imul path exercised).

## 7. Required tests and timing
Core unit tests with independently derived expectations: (a) PRNG fixture 1 to full precision from an independent implementation of the section 4 formula; (b) micro-fixture 2 exactly (length and first five picks, capitalisation); (c) with the production pools: sentence word counts always in 6–14, paragraph sentence counts in range for both languages, opening sentence exact when on and absent when off; (d) words unit lands on exactly N words for N = 10, 100, 5,000 including the cut-sentence termination; characters unit is exactly N code points including a case spanning the paragraph join; (e) determinism: two runs and a re-seeded run reproduce byte-identically; seed increment changes the output (asserted on the fixture corpus, not in general); (f) zh pool audit test: every pool sentence ends with 。, contains no Latin letters or digits, and the pool size is ≥ 24; Latin pool audit: no duplicates, count and checksum match the recorded values; (g) HTML serialiser escaping with a hostile test pool.
GUI/evidence tests (desktop, real browser): the initial state matches the (Latin, paragraphs, 3, seed 42, opening on) generation; settings changed through the real UI in both UI languages; both copy formats pasted into a scratch document and diffed against the raw view. Timing: full core suite under 60 seconds; no network in any test.
Explicitly NOT_RUN at specification stage: all product tests above; this document claims document completeness only.
