# PDF Page Tools: Merge, Split, Extract and Rotate — preparatory BRIEF v0.1

Specification documentation only; no product claim, readiness event or implementation. Full normative contract is SPEC.md.

## 1. Goal
Office workers, teachers, students and applicants constantly need to combine a few PDFs into one file for submission, pull two pages out of a long report, or fix a sideways scan — and the common route is uploading private documents (contracts, transcripts, ID scans) to a free online PDF site. Success: the user drops in local PDF files, arranges them in a list, and merges them into one download; or takes one PDF and splits it by page ranges into separate downloads; or extracts and rotates selected pages — all processed entirely in the browser, with the page counts and order shown before anything is generated, and honest errors for encrypted or damaged files. The documents never leave the device.

## 2. Scope and functional distinction
Four operations on user-supplied local PDFs: (a) merge 2–20 files into one PDF in a user-arranged order (drag or move buttons), showing each file's name and page count; (b) split one PDF by a stated range grammar (e.g. `1-3, 5, 8-`) into one output file per contiguous group or a single combined file, chosen by the user; (c) extract an arbitrary page selection from one PDF into a new PDF, preserving the source order or the listed order per the stated rule; (d) rotate chosen pages by 90/180/270 degrees. Output is generated locally and downloaded; page counts, total pages and output filename are shown before generation. Hard limits are stated in the SPEC (aggregate input size, total pages) with errors that name the exceeded limit. Encrypted/password-protected PDFs are rejected with a clear message (no decryption attempt); malformed files are rejected per-file without discarding the valid ones in merge mode. No OCR, no text editing, no form filling, no compression promises, no e-signature, no cloud conversion, no PDF/A validation claims.

Existing tools: Images to PDF assembles image files into a new PDF — its inputs are images, and it cannot read, reorder or combine existing PDF pages. File Bundler archives arbitrary files into a ZIP without understanding pages. File Checksum only hashes bytes. None parses PDF structure, manipulates page order/rotation, or re-emits a valid PDF. Initial catalog/spec/task scope contains no PDF page manipulation tool; fresh registry/path/draft check remains mandatory before admission. Because a from-scratch PDF writer is disproportionate, the SPEC must fix the implementation strategy: a single vendored, pinned, licence-recorded PDF library file (with source URL and hash) loaded locally, or an in-repo implementation of the stated operation subset — with provenance as a scored aspect either way; runtime network dependencies remain zero.
