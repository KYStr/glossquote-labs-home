## 1. Goal, scope and standards boundary

Help a desktop frontend learner change an ordered polygon, understand its percentage coordinates and visible painted region, repair invalid geometry, and manually obtain deterministic CSS. The normal task is edit a concave example, deliberately cross two edges, understand the reported pair, repair it without automatic sorting, vary the preview width/height and verify unchanged percentage CSS. This is not an SVG editor, CSS parser, image upload service or general computational-geometry library.

Exactly3–12 vertices, one simple closed ring, percentage coordinates0–100 inclusive at hundredth-percent resolution. Preserve entered order, allow either winding and adjacent straight-through collinear vertices, reject duplicate vertices, zero edges, overlapping adjacent edges, nonadjacent crossings/touches/overlaps and zero area. These are tool restrictions, not claims that CSS itself prohibits self-intersecting paths. Fixed nonzero fill; no holes, rounded polygon corners, transforms, animations, shape-outside, masks, arbitrary CSS/HTML/SVG, URL/file/image input, accounts, storage, analytics or clipboard APIs. The preview is one empty HTML block with fixed built-in synthetic pattern, width/height40–800 integer CSSpx, border-box sizing, zero border/padding/margin/radius and no transforms. An external outline identifies the full box without altering its dimensions. No element text is clipped as a substitute for an accessible explanation.

Normative basis, read2026-11-01: [CSS Shapes1 §3/§3.1,12June2025 CR Draft](https://www.w3.org/TR/2025/CRD-css-shapes-1-20250612/#basic-shape-functions) defines basic-shape coordinates and polygon closure. Here x grows right and y down, percentages use the selected reference dimensions and the final point connects to the first. Newer functions/rounding syntax in that draft are outside scope. [CSS Masking1 §5/§5.1,5August2021 CR Draft](https://www.w3.org/TR/2021/CRD-css-masking-1-20210805/#the-clip-path) supplies clip-path and reference-box semantics. The output explicitly selects border-box. Clipping changes paint, not the layout rectangle; the preview and its bounds must demonstrate this distinction. These draft references are not browser test evidence.

Known catalog/registry collision checks distinguish polygon topology from existing2D Transform-Origin,3D Perspective, elliptical radius normalization and Object-fit image fitting. Their owners and artifacts remain unchanged. Unknown unregistered local drafts remain UNKNOWN and must be checked before a separate production claim; this document does not erase that limitation.

## 3. Input, exact data and output contract

Inputs are a trusted UI-shaped object {widthRaw,heightRaw,pattern,vertices:[{xRaw,yRaw}…]}, not user JSON. Pure validation nevertheless rejects wrong types, extra keys, non-array vertices, wrong count, missing/non-string fields, accessors or unknown pattern before arithmetic; do not invoke getters in adversarial fixtures. Internal stable row IDs may exist in the controller, but are not arbitrary text accepted by geometry. Validate number of rows before iterating. Each raw numeric field has at most32 UTF-16 code units checked before trimming; overlong input remains visible, not silently truncated. Trim only U+0009/000A/000D/0020 at either end. Coordinates then match `^(?:0|[1-9][0-9]*)(?:\.[0-9]{1,2})?$`, inclusive0…100. Dimensions match `^[1-9][0-9]*$`, inclusive40…800. Reject leading plus/minus including -0, leading zeros other than0, bare/trailing dot, exponent, hex, comma, Unicode digits/space, interior whitespace, NaN/Infinity and third decimal. Do not use parseFloat acceptance of prefixes.

Parse coordinate digits as integer hundredth-percent q in[0,10000] by padding the fractional part to two digits, never binary floating-point parsing. W/H are integers. Percent canonical text is q/100 written with at most two fractional digits and trailing zeros removed;0.00→0,100.00→100,0.10→0.1. Raw fields are never rewritten. Pixel vertex coordinates are exact fractions X=W*qx/10000,Y=H*qy/10000. Use integer/BigInt numerator calculations and gcd reduction; zero has denominator1. Reversal changes winding but not the enclosed region/absolute area. No sorting/simplification, including redundant valid collinear points; closing edge is implicit and the first vertex must not be repeated at the end.

Result snapshot includes W/H/pattern, ordered canonicalpercent vertices, exact pixel fractions, three-place approximate pixel decimals, exact signed twice-area S in q units, winding, exact area in CSSpx², exact percentage of box covered, and percentage/pixel axis-aligned bounds. The full bounding box of the HTML block remains W×H and is shown separately from polygon bounds. S=sum(qx_i*qy_next−qx_next*qy_i); S>0 is clockwise in the screen y-down coordinate system, S<0 counterclockwise. Pixel area=abs(S)*W*H/200000000. Coverage percentage=abs(S)/2000000. Bounds use min/max q and the same pixel conversion; area is not its bounding rectangle area. Only a valid simple ring receives these geometric conclusions.

All displayed approximate geometry/area/coverage uses exactly three decimal places, half-away-from-zero, with no negative zero. Expose reduced exact fractions adjacent to approximate values (integers shown without /1) so a tiny valid shape with displayed0.000 area is not described as zero. Round an absolute rational n/d by quotient/remainder of1000*n/d, increment if twice remainder≥d, then reapply sign only if rounded integer nonzero. Do not calculate topology, CSS or coverage from rounded values. Labels say “approx.”, units distinguish px, px² and percent of box.

Deterministic CSS consists of exactly one declaration and one terminal LF, UTF-8 without BOM/trailing spaces:

```
clip-path: polygon(nonzero, 0% 0%, 100% 0%, 100% 100%, 0% 100%) border-box;
```

Replace only ordered pairs with canonicalpercent values separated by comma-space. This is a declaration to use on a rectangular CSS layout box, not complete markup/width/height/pattern CSS. W/H/pattern or language changes do not change these bytes. The native preview applies precisely the value after `clip-path: ` and before `;` to its known style.clipPath property, never raw CSS. Tell the user that adopting other padding/borders/reference boxes/content changes context and may clip their own content; no arbitrary cascade guarantee.

The native preview uses actual W/H CSSpx without transform/auto-scale, inside a scrollable labeled region. Checker is a fixed stylesheet two-tone grid; diagonal is a fixed stripe pattern. No external images. An external box outline and label show layout bounds; the clipped block itself has no border/radius/padding or outline, so geometry remains unambiguous. Pattern changes no geometry. A separate SVG schematic maps the same W×H coordinates with viewBox `-16 -16 W+32 H+32`, uses uniform aspect scaling and outlines the unfilled box and ring, labels P0… and edge E_i=P_i→P_(i+1 modN), and shows x-right/y-down arrows. It may scale responsively but must be labeled “schematic, not actual pixel size.” Marks/labels remain readable, with external table resolving overlaps; no clipped label is treated as native content. Numeric table, not visual angle estimation, is authoritative for coordinates. Invalid states show no misleading preview, even for CSS polygons a browser might otherwise accept.

## 4. Geometry, implementation and finite security interfaces

The following is the tool's own exact finite validation model. It is not a standards-prescribed general polygon validator. Use BigInt integer q coordinates; never epsilon tests or browser path hit-testing to decide input validity. Maximum12 vertices gives66 unordered edge pairs; no recursion, triangulation, canvas/WebGL or geometry dependency.

Validation precedence after lexical/count/schema checks: (1) duplicated vertices by lexicographic index pair i<j, numeric q equality, error DUPLICATE(i,j); this includes every zero-length edge and repeated closing vertex. (2) S=0, error ZERO_AREA referencing all vertices. (3) adjacent edge overlap in ascending unordered edge pair; (4) any nonadjacent edge intersection in ascending unordered edge pair. Report the first issue at that precedence, not all unstable overlapping errors. Rejection does not repair or change raw order. A self-crossing zero-shoelace polygon is rejected as ZERO_AREA by this precedence; it is not accepted merely because crossing was not the displayed error. Area sign/coverage output is withheld until every topology check succeeds.

For points A,B,C define orient(A,B,C)=(Bx−Ax)(Cy−Ay)−(By−Ay)(Cx−Ax). Point C lies on closed segment AB iff orient=0 and each coordinate lies in the inclusive axis-aligned interval. Edges E_i=[P_i,P_(i+1 modN)] and E_j are adjacent if j=i+1 or {i,j}={0,N−1}. They already share exactly one vertex after duplicate rejection. For an adjacent pair write it A→B→C with B the shared endpoint, including wraparound. If orient(A,B,C)=0 and (A−B)·(C−B)>0, the two edges overlap a positive length: reject ADJACENT_OVERLAP(i,j). Dot<0 is straight-through collinearity and allowed; dot=0 cannot occur for distinct collinear endpoints, but fail safely if the invariant is violated. Noncollinear adjacent edges intersect only at their permitted shared point.

For nonadjacent AB,CD compute o1=orient(A,B,C),o2=orient(A,B,D),o3=orient(C,D,A),o4=orient(C,D,B). If o1*o2<0 and o3*o4<0, reject CROSS(i,j). Otherwise if all four orientations0, compare the overlapping intervals on x unless AB is vertical, then on y. Disjoint intervals are allowed; equal endpoints reject TOUCH(i,j); positive-length intersection rejects OVERLAP(i,j). Otherwise if any zero orientation has its corresponding endpoint on the other closed segment, reject TOUCH(i,j). Otherwise disjoint. This detects a vertex touching another edge, not just proper crossings. No tolerance or rounding is allowed. The tests include closure-pair adjacency and a nonadjacent collinear disjoint pair.

Only after all checks compute bounding extrema, exact area and canonical CSS, then construct one immutable result object. Pure parse→validate→compute→serialize layers have no DOM or network access. Controller input snapshot IDs guard against stale updates, though computation is synchronous and bounded. On internal exception clear all results and issue a localized internal-error status without exposing raw exception text; do not return partial CSS. No workers, promises, background retry or remote calculation required. Every generation constructs at most12 row outputs,12 labels and12 edge representations, replacing rather than appending prior output.

Safe rendering uses textContent, textarea.value and createElementNS with fixed element/attribute names; numeric SVG attributes and fixed style.width/style.height/style.clipPath receive only canonical validated values. No innerHTML, eval, dynamic import, user URLs, cssText, setAttribute('style'), injected stylesheet text, CSS parser or arbitrary property names. No clipboard, download, file picker, fetch, cookies, local/session storage, IndexedDB, service worker, analytics, permission API or outbound data channel. Existing navigation/assets are distinguished from input transmission in runtime evidence. Zero network dependencies, system fonts only.
