# 多站取件時窗路線 / Pickup Window Route 製作簡報

預案 `spec-pickup-window-route-20261109` · 文件待獨立審查

取件者要同日從一處出發、到多個有營業窗口的取件點，再回出發處。手上已有各方向預估旅時，希望知道可完成的順序和每站須等幾分鐘。

桌面用矩陣抄手上估算的往返分鐘，右側讀固定到達、開始服務、離站及返回時刻。

手機在門口可逐站改窗口，矩陣以來源選單切行。結果依行走次序堆疊，等待和服務時間清楚分開。

主要操作「找出可完成的取件順序 / Find a pickup route」。工作區採 Product App。頁面中優先呈現以下工作物。

```text
寬畫面
站點時窗／有向旅時矩陣   |   取件序與返程

窄畫面（由上而下）
出發／返回 → 站點 → 每個來源旅時 → 順序與時間
```

首個貫通案例用 `pickup-window-route.only-order`。A 的可取件時窗較晚，先去 A 會錯過 B。先 B 再 A，可在 08:50 返回。

1–8 個必訪點、單日出發返回、方向別固定旅時，允許缺邊、早到等待。比較所有可完成順序，取最早返回，平手依站輸入序。

產品界線與輸入、算法、九面向、測試、交接以 [規格](SPEC.md) 為準。起手先將 [字面案例](fixtures.json) 固定在 Node 24 離線測試，再接兩語操作。完成後固定 `tools/pickup-window-route/` 候選及 open PR head，將真實檢查結果交主責。這份簡報的產品、瀏覽器、正式站 gate 全為 `NOT_RUN`。
