# Exact Quadratic Roots — complete specification v0.1

Specification only; product checks NOT_RUN and nine scores null.

## 1. Goal
A learner or worksheet author checks a*x^2+b*x+c=0 with bounded integer coefficients and reads exact real roots, their discriminant classification and algebraic verification. This is educational algebra, not approximate engineering, financial or medical decision support. Success includes understanding that D<0 means no real roots, not absence of complex roots. No product implementation is part of this specification task.

## 4. Exact input, algorithms, result schema and fixtures
### 4.1 Input/error contract
Pure core input exactly {aRaw,bRaw,cRaw}, own data properties with primitive string values. Accept Object.prototype or null prototype; reject null/arrays/other prototypes, missing/extra/symbol keys/accessor properties without invoking accessors. This schema contract concerns ordinary caller-provided data objects, not an adversarial JavaScript Proxy execution sandbox. Whole-schema rejection SCHEMA precedes field validation. Per field priority: LENGTH (>16 UTF-16 units before trim), EMPTY, GRAMMAR, RANGE, then ZERO_A (only a). Type mismatch belongs to SCHEMA. Trim only ASCII space/TAB/CR/LF at both ends. Grammar -?[0-9]+; leading zeros and -0 accepted; normalize numeric zero to0 only in results, raw remains unchanged. Reject plus, decimal point, exponent, commas, underscores, Unicode digits/minus/space, expressions and BigInt suffix. Parse BigInt after grammar; range -10000..10000 inclusive; a=0 invalid, including -0. Error object {code,field}, field a|b|c or null for SCHEMA; UI never exposes internal exception text. One error per field in field order. Internal invariant failure INTERNAL with fieldnull clears output and gives a generic retry/reset message. Error objects are not serialized as successful results.

### 4.2 Normalization and discriminant
Let original canonical numeric tuple (a,b,c). g=gcd(abs(a),abs(b),abs(c))>0. signed divisor m=g if a>0 else -g. Set A=a/m,B=b/m,C=c/m, so A>0 and gcd(A,abs(B),abs(C))=1. Show both tuples and m to explain equivalent equations, not silently rewrite input. D=B^2-4*A*C is exact BigInt; -400000000<=D<=500000000 is a conservative bound. Discriminant shown is the NORMALIZED polynomial's D, not the original tuple's discriminant. This distinction is explicit in both languages.

For D<0: class no-real; roots[]; square decomposition null; verification null. Do not compute sqrt(abs(D)) as a real root or classify the input as invalid. For D=0: class repeated; root -B/(2*A) reduced to p/s, s>0, gcd(abs(p),s)=1; canonical zero0/1; multiplicity2. Decomposition {k:"0",r:"0"}. For D>0: extract D=k^2*r with k>0, r>=1 square-free. One bounded algorithm: n=D,k=1; for integer f=2 while f*f<=n, repeatedly divide n by f*f while divisible and multiply k by f; increment f by1; finish r=n. At most22360 tested factor candidates under the conservative bound, fewer when n shrinks. All operations BigInt, no Math.sqrt or floating decision. Verify k*k*r=D; factor candidate termination and square-free property need documentary proof and independent tests. This is bounded trial square extraction, not a general unbounded factorization service.

If r=1: class rational-pair; roots are fractions (-B-k)/(2*A),(-B+k)/(2*A), separately gcd-reduced with positive denominators, multiplicity1 each. If r>1: class irrational-pair; let h=gcd(abs(B),k,2*A), p=-B/h, q=k/h>0, s=2*A/h>0. Roots ordered (p-q*sqrt(r))/s then (p+q*sqrt(r))/s, each multiplicity1. gcd(abs(p),q,s)=1 and r square-free. Never rationalize away the exact root or produce rounded decimals. Ordering is increasing because A,s,k,q positive; repeated contains ONE entry, not duplicate roots.

### 4.3 Exact verification, serialization and display
Root data uniform {p,q,r,s,multiplicity}; all numeric values decimal strings except multiplicity JSON number1|2. Rational roots use q="0",r="0", reduced p/s. Irrational roots use q negative in first and positive in second, same p,r,s. The represented real value is (p+q*sqrt(r))/s. For each root compute normalized-polynomial numerator coefficients:
constant=A*(p*p+q*q*r)+B*p*s+C*s*s;
radical=q*(2*A*p+B*s).
Both must equal0; denominator s*s is positive. Record both zero coefficients and denominator, not a decimal residual. Any nonzero coefficient yields INTERNAL/noresult. This explicitly verifies the polynomial identity using exact arithmetic, not approximate substitution. Rational r0/q0 follows the same formula. Root multiplicity is stated, not inferred from identical formatted strings.

Result exact own keys in this order: original,normalizationDivisor,normalized,discriminant,classification,decomposition,roots,verification. original and normalized arrays of three canonical signed integer strings; normalizationDivisor and discriminant canonical strings; classification no-real|repeated|rational-pair|irrational-pair. decomposition null or {k,r} string keys in that order. roots array of root objects with key order p,q,r,s,multiplicity. verification null or array in root order of {constant,radical,denominator}, string values. Successful no-real result includes all keys, with roots[] and null verification; it is not an absent result. Serializer JSON.stringify(result,null,2)+oneLF, UTF-8 without BOM, identical across UI languages. BigInt must be converted explicitly to strings before JSON; no BigInt JSON exception or lossy number conversion.

Human rational root: integer p if s1, otherwise p/s. Human irrational root uses literal ASCII '(p - q*sqrt(r))/s' or '(p + q*sqrt(r))/s' with abs(q) in text, retaining p=0, q=1 and s=1 (no ambiguous special-case simplification). For example '(0 - 1*sqrt(2))/1'. The formula's parentheses are mandatory. Labels are localized; mathematical text and JSON aren't. Original raw strings remain in fields; original result tuple is canonical numeric text, not alleged raw echo. Verification explains constant plus radical coefficient times sqrt(r), over denominator; does not mislabel the coefficients as approximate function values.
