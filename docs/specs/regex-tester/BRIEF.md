# Regex Tester and Replacer — preparatory BRIEF v0.1

Specification documentation only; no product claim, readiness event or implementation. Full normative contract is SPEC.md.

## 1. Goal
Developers, students, support engineers and data-entry staff regularly need to check whether a regular expression matches what they think it matches — an email pattern, a log-line extractor, an order-number format — and the usual loop is guessing in production code or pasting proprietary log text into an ad-heavy online tester. Success: the user types a pattern and flags, pastes sample text, and sees every match highlighted in place with its index, full text and capture groups (named groups included), plus a replace preview using the stated substitution syntax — all computed locally with the browser's own JavaScript RegExp engine, so the behaviour they verify is the behaviour their code will get. Pattern errors are reported with the engine's message and a caret position where derivable, not as a silent empty result.

## 2. Scope and functional distinction
JavaScript (ECMAScript) RegExp only — the SPEC must say plainly that this is not PCRE/PCRE2, Python or Java flavour, and list the flavour differences that most often bite (no possessive quantifiers, no atomic groups, lookbehind supported, named groups via `(?<name>…)`). Flags g, i, m, s, u, y as toggles. Match mode: all matches (or first, when g is off) with start/end indices in code points and code units both stated, group table per match, zero-width matches shown explicitly and iteration guarded against infinite loops by the stated advance rule. Replace mode: replacement string with `$&`, `$1…$99`, `$<name>`, `$$`, `` $` `` and `$'` semantics exactly as ECMAScript defines, preview of the full result, and a match-and-replacement count. A small set of bundled preset examples (email-like, date, order number, log timestamp) loaded only on click. Hard input limits in the SPEC (pattern length, text length) with named errors; a plain-language warning that a pathological pattern can still freeze the tab because JavaScript regex cannot be interrupted, with the mitigation being the stated limits — the SPEC must not promise a timeout it cannot enforce. No server evaluation, no saving of patterns to an account, no "AI explains your regex", no multi-flavour engine.

Existing tools: Text Diff compares two texts; Text Workbench transforms text by fixed operations; the JSON workbench validates JSON. None evaluates user-supplied regular expressions, enumerates capture groups, or previews ECMAScript substitution semantics. Initial catalog/spec/task scope contains no regex tool; fresh registry/path/draft check remains mandatory before admission. All sample texts in fixtures are synthetic (fake log lines, fake emails at example domains).
