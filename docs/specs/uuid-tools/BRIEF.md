# UUID Generator and Inspector — preparatory BRIEF v0.1

Specification documentation only; no product claim, readiness event or implementation. Full normative contract is SPEC.md.

## 1. Goal
Developers constantly need a fresh UUID — for a test fixture, a database seed, a correlation id — and just as often need to sanity-check one they were handed: is this even a valid UUID, which version is it, and (for time-ordered versions) when was it minted? Success: the user generates one or a bulk batch of version 4 (random) or version 7 (time-ordered) UUIDs with the format options they need, copies them in one click, and can paste any UUID into an inspector that validates it strictly, names its version and variant, and decodes the embedded timestamp for v1/v7 — all locally, with randomness from the platform CSPRNG only.

## 2. Scope and functional distinction
Generation: v4 (122 bits of CSPRNG randomness, version/variant bits fixed per RFC 9562) and v7 (48-bit Unix millisecond timestamp, version/variant bits, remaining bits CSPRNG) as the two offered versions — the SPEC explains briefly why v1 (privacy: node/MAC) and v6 are not offered for generation while still being recognised by the inspector. Bulk: 1–1,000 per batch with the count validated; format options applying to the whole batch: lowercase (default) or uppercase, hyphens on (canonical) or off (32 hex digits); copy-all and download-as-text (one per line). Inspector: strict validation (canonical hyphenated form and the 32-digit form both accepted for inspection, with the parsed fields shown), version identification (0–15 nibble, with 1–8 named per RFC 9562 and others reported as reserved/unknown honestly), variant identification (RFC 9562 variant vs the legacy Microsoft/NCS variants, named as such), timestamp extraction for v1 (100-nanosecond intervals since 1582-10-15, reconstructed across its three fields) and v7 (Unix ms), shown in UTC and local time; NIL and MAX UUIDs recognised by name. A persistent honesty note: UUIDs are identifiers, not secrets — a v4 is unguessable but the tool must not market generated UUIDs as passwords or tokens.

Existing tools: Password Generator makes secrets and passphrases — different artefact, different rules (a UUID is a fine identifier and a poor password, and the SPEC for each says so). The UTF-8 Base64 codec and JSON Workbench are unrelated text tools. Initial catalog/spec/task scope contains no UUID tool; fresh registry/path/draft check remains mandatory before admission. Fixtures use published RFC 9562 example UUIDs and fixed-clock v7 constructions so timestamp decoding is exactly checkable.
