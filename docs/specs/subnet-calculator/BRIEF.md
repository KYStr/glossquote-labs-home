# IPv4 Subnet Calculator — preparatory BRIEF v0.1

Specification documentation only; no product claim, readiness event or implementation. Full normative contract is SPEC.md.

## 1. Goal
Network administrators, IT support staff and networking students constantly work out subnet facts by hand — what is the broadcast address of 192.168.1.64/26, how many hosts fit, what /27 blocks come out of splitting this /24 — and errors here turn into misconfigured DHCP scopes and unreachable machines. Success: the user types an IPv4 address and a prefix length (or netmask), and sees the complete, exactly-computed picture: network and broadcast addresses, first/last usable hosts, wildcard mask, total and usable host counts, address class and special-range classification (private, loopback, link-local, multicast, public), a binary view of the boundary, and — when splitting — the full list of child subnets for a chosen child prefix. All arithmetic is local integer math on values the user typed; nothing is looked up or sent anywhere.

## 2. Scope and functional distinction
IPv4 only in this version; IPv6 is an explicit exclusion stated on the page (a separate future specification may cover it — the rules, display widths and address classes differ enough that bolting it on would corrupt both contracts). Input as dotted-quad plus prefix (0–32) or dotted netmask (validated as contiguous), with the two kept in sync. Single-subnet analysis as above; special cases /31 (RFC 3021 point-to-point: both addresses usable) and /32 (host route) handled by stated rules rather than the generic minus-two formula, and /0 and /1 computed without overflow. Split mode: choose a child prefix longer than the parent and list every child subnet (network address, broadcast, usable range) with a stated display cap and total count even when the list is capped. A "is this address in this subnet" membership check for a second typed address. No scanning, no ping, no DNS, no DHCP planning beyond the arithmetic, no saving of entered addresses, no geolocation or ownership lookup of public addresses (the classification names the range type only, from the stated IANA special-range table subset).

Existing tools: the integer-representation explorer teaches number bases; the unit converter converts measurement units; neither performs mask arithmetic, range classification or subnet splitting. Initial catalog/spec/task scope contains no networking calculator; fresh registry/path/draft check remains mandatory before admission. All fixture addresses are documentation ranges (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24 per RFC 5737) or RFC1918 classroom examples — never a real network the author operates.
