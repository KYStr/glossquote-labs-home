# CSS Selector Specificity Comparator — admission brief v0.1

## Purpose
Compare two supported CSS selectors and explain their specificity as an ordered triple (A,B,C), with a token-by-token contribution tree. A frontend author can find why a class chain loses to an ID, why :where() contributes nothing, and why :is() or :not() depends on its strongest argument. The result is **specificity comparison only**, not a prediction of which style wins: origins, importance, cascade layers, scope proximity, matching and source order are outside this tool.

## Bounded initial scope
Two independent multiline text fields, each at most 1,024 UTF-16 code units, initially `#card .title` and `.card h2.title`. An explicit Compare action validates both entire fields before producing any result. The future full SPEC must freeze grammar, exact error codes/offset units/priority, raw preservation, dirty/result/error/reset/language state and all output templates before implementation.

The supported language is deliberately smaller than CSS. It accepts ASCII identifier names (letter or underscore, then letters/digits/underscore/hyphen), type/universal selectors, `.class`, `#id`, `[name]` presence attributes, descendant/child/next-sibling/subsequent-sibling combinators, and a finite allowlist of nonfunctional pseudo-classes. Allowlist: hover, focus, focus-visible, focus-within, active, checked, disabled, enabled, root, empty, first-child, last-child, only-child. Terminal double-colon before/after/first-line/first-letter pseudo-elements are permitted only on a top-level selector's final compound. Exact case and whitespace normalization rules must be fixed in the full SPEC. Functional :is(), :not() and :where() accept nested nonempty selector lists of this supported real-selector subset, with no pseudo-elements inside; maximum nesting depth 4 and at most 8 alternatives per function. A top-level comma list is excluded: each of the two inputs denotes one complex selector.

Reject unsupported constructs with an explicit **outside supported subset** result, not a statement that the browser considers them invalid. No CSS escapes, comments, non-ASCII identifiers, attribute values/operators/namespaces, :has(), :nth-*(), :host(), nesting `&`, relative selectors, legacy single-colon pseudo-elements, stylesheets, declarations, !important, imports, URLs or arbitrary HTML. No fallback that silently discards unsupported branches. In particular, this pedagogic subset checks every :is()/:where() argument; it is **not an implementation of the browser's forgiving-list parser**. Valid supported inputs still receive standards-based specificity. The page must disclose the subset before entry and on rejection.

Inputs remain inert text: do not insert them into style elements, CSSOM, querySelector, innerHTML, eval or a document-matching demonstration. No files, accounts, external dependencies, clipboard API, storage, telemetry or data-bearing network requests. Results provide two triples, contribution trees, the first unequal component, and greater/equal comparison. Equal means equal specificity, not a cascade tie resolved by this tool. Optional manual selection of deterministic text is enough; no export download is needed.

## Model and official source
Use the fixed W3C Selectors Level 4 Working Draft dated 22 January 2026, sections 3, 4, 15 and 16: https://www.w3.org/TR/2026/WD-selectors-4-20260122/ . It is a working draft, not a browser support guarantee. The accepted subset uses ID/class-like/type-like component accumulation, lexicographic comparison, zero universal/combinator contribution, strongest-argument replacement for :is/:not and zero for :where including descendants. Do not encode triples as a decimal number such as 100A+10B+C. Ancillary UI/code platform requirements come from the existing repository baseline, not a new package install.

The full SPEC must resolve lexical/structural validity before scoring, bound parsing without a regular-expression approximation of nested syntax, and include literal independent expected trees/triples. Key planned cases: an ID versus eleven classes; universal and repeated simple selectors; strongest argument that is not first; nested :where under :is and vice versa; final pseudo-element; equal triples with different structures; invalid/out-of-subset branches; depth/length/alternative limits; unclosed syntax and combinator placement. These are planned documentary examples, not product tests already run.

## Distinctness and ownership
The known tool collection has no same-purpose selector specificity comparator. Existing CSS tools concern geometry, layout, color or animation; text/regex/HTML tools do not compute selector specificity. The separate nth-child Index Explorer concerns sibling positions and explicitly excludes specificity/cascade; this tool does not calculate sibling positions or resume its work. No known same-purpose owner was found. Unregistered local drafts remain unknown: this is not a universal inventory assertion or a release of another owner's responsibility. No local operation is required by this specification.
