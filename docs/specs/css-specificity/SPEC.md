# CSS Selector Specificity Comparator — full specification v0.1

## 1. Goal
A bounded, zero-dependency educational comparator explains two selectors' specificity and the contribution of their supported syntax. It does not execute selectors or predict the cascade winner. Contract source: fixed BRIEF c0862991b4fe5bcff370e375da8ebe86a3507cf3 and homepage baseline 26525d5f6380915ea95dde879dec769442db0d95. This document describes future implementation and acceptance; no product exists or has passed checks under this specification.

## 2. Scope and user flow
Two routes `/index.html` (Traditional Chinese) and `/en/index.html` share one controller. Initial raw L=`#card .title`, R=`.card h2.title`, no result or error. Main order: scope/help, two labeled textareas, Compare, Reset, language link, status, result. Explain the supported subset and no-cascade warning before Compare; put the complete grammar allowlist in an accessible disclosure, not only a tooltip.

Normal task: edit either field → Compare → inspect triples and first differing component → expand contribution details → manually select the readonly summary. No user HTML/style preview exists. Enter in a textarea inserts LF, not submission. Compare is a normal button; Tab/Shift+Tab and Space/Enter work natively. On successful comparison do not programmatically move focus; on failure focus the first invalid textarea in L then R order, with a linked error summary. Reset restores both exact initial strings, clears error/result, collapses details, keeps focus on Reset. Each textarea has explicit left/right labels, not placeholders alone.

State: `idle` initially/reset; `dirty` on any input; `invalid` after a failed Compare; `result` after success. Every edit immediately clears all old result nodes, summary and errors, before another Compare; no debounce, async parser or speculative score. Comparison with identical text still yields two distinct analyses. Multiple Compare clicks recompute synchronously with bounded work; no duplicate DOM accumulation. Language changes use a same-origin route link intercepted only for an ordinary unmodified activation: preserve both raw strings, state, structured result/error and disclosure-open state; regenerate only localized strings, update path/title/lang/meta, focus the corresponding language control. Normal modified links open a fresh initial page. Never put raw text in URL/history/storage. On `pagehide` clear results/errors and set dirty (retaining in-memory raw); on `pageshow` likewise require a new Compare. This does not promise raw persistence after a full document reload; fresh documents start with defaults. Do not claim `persisted`/visibility events were tested unless actually observed.

Excludes all product behavior in BRIEF exclusions, DOM matching, native-selector execution, browser-compatible full CSS parsing, specificity for styles/inline declarations, selectors outside the subset, downloading and clipboard writes. No training claim or security decision is based on the result. Unknown unregistered drafts remain unknown; no owner is displaced.

## 3. Inputs, outputs and deterministic errors
### Input record and raw policy
Pure entry `compareSelectors(record)` accepts an ordinary object with prototype Object.prototype or null and exactly own data properties `left` and `right`, both primitive strings. Reject arrays, other prototypes, symbols, extra/missing keys and accessor descriptors as `SCHEMA`, without invoking getters/coercions. The UI constructs that record from its state. Core checks schema first, then both raw lengths (L first), then analyzes L completely and R completely; return at most one error for each field, plus first invalid field. If either length exceeds 1024, return just the first `LENGTH` error and do not parse either field. No result when any error exists. Length limit is UTF-16 units, not graphemes; overlong text stays visible, with count, in the textarea (no maxlength or beforeinput filter). Core does not trim or normalize input.

Textarea/raw source is `.value` on input; retain it exactly, never `.valueAsNumber`, never rewrite on blur. Native textarea line endings may normalize CR/CRLF to LF; that platform behavior must be disclosed, while direct core string tests preserve their supplied characters. Recognized whitespace is exactly HT/LF/FF/CR/SPACE (`\u0009,000A,000C,000D,0020`); it contributes no score except serving as descendant combinator. No locale-dependent whitespace or identifier normalization. Input names preserve case; pseudo names are ASCII-case-insensitive and normalize to lowercase in AST only. Inputs are never rewritten to normalized selectors. There is no canonical selector output, only the retained raw input plus canonical numeric triples.

### Complete supported grammar
The following grammar is normative; `ws` is zero or more recognized whitespace characters, `ws1` one or more. `ident` is `[A-Za-z_][A-Za-z0-9_-]*`, so an initial hyphen, escaped or non-ASCII CSS identifier is outside the subset. An ident may be arbitrary for type/class/id/attribute, but pseudo names use the closed lists. Keyword and string comparison is case-sensitive except pseudo names.

```
input       := ws complex ws EOF
complex     := compound (explicit compound | descendant compound)*
explicit    := ws ('>' | '+' | '~') ws
 descendant := ws1                 # only when not part of explicit/trailing ws
compound    := (ident | '*') simple* pseudoElement?
             | simple+ pseudoElement?
simple      := '#' ident | '.' ident | '[' ws ident ws ']'
             | ':' ordinary | ':' function '(' ws list ws ')'
ordinary    := hover|focus|focus-visible|focus-within|active|checked|disabled
             |enabled|root|empty|first-child|last-child|only-child
function    := is|not|where
list        := complex (ws ',' ws complex)*
pseudoElement := '::' (before|after|first-line|first-letter)
```
No whitespace between `:` and name, between name and `(`, or between `.`/`#` and identifier. Type/universal may appear only first in a compound; `div*` and `.x*` are syntax errors. A pseudo-element is allowed only at the end of the final compound of a top-level complex selector, never within any function argument, never before a further combinator/simple selector. A compound can be just `::before`? **No**: the grammar requires a type/universal or one simple before a pseudo-element; use `*::before`. This is a deliberate subset exclusion, not a claim about CSS validity. Top-level comma, empty function list/branch and leading combinator are unsupported/syntax errors as classified below. Nested functions count active function calls: first call depth1, maximum4 inclusive; each function list allows1–8 branches. Multiple type names cannot form one compound without a combinator.

### Parser/error contract
Parse with a hand-written bounded scanner/recursive-descent parser, not a regex that attempts nested syntax and not CSSOM/querySelector. Each error has `{field:'left'|'right'|null,code,offset:number|null}`. Offset is zero-based UTF-16 unit in the original raw string; EOF offset=raw.length. No numeric score on error.

Codes and priority (after schema/length):
- `UNSUPPORTED_CHAR`: scan whole raw left-to-right first and report earliest character outside ASCII letters/digits/underscore/hyphen, recognized whitespace and `#.*[]:(),>+~`. This includes backslash, slash/comments, quotes, equals, pipe, ampersand, semicolon, braces, non-ASCII or NUL. This classification means unsupported, not necessarily invalid CSS.
- `EMPTY`: after that scan, all-whitespace field; offset=0, including empty string.
- Remaining structural scan left-to-right reports the first encountered failure. `UNSUPPORTED_NAME` for a colon-name not in its correct allowlist, or an allowlisted ordinary pseudo followed immediately by `(`; offset at that colon. Single-colon `before` etc is unsupported. `UNSUPPORTED_CONTEXT` for a top-level comma, bare leading pseudo-element, a pseudo-element inside a function or any token after a completed pseudo-element except trailing top-level whitespace/EOF; offset at offending comma/colon/token. A pseudo-element followed by trailing explicit combinator points to the combinator.
- `DEPTH` on attempting function depth5, offset at its colon. `BRANCH_LIMIT` on the comma that would introduce branch9, regardless of later contents.
- `SYNTAX` for all other missing/extra/misordered tokens; offset at the first token that cannot fulfill the grammar or EOF when a required token is absent. An identifier starting digit/hyphen in a required ident position is `SYNTAX` at that character; the page must describe subset grammar rather than browser-invalid CSS. Unknown pseudo name is determined before expecting function parentheses. For recognized `is/not/where` without immediate `(`, `SYNTAX` points to the next character (including whitespace), or EOF.

Operational disambiguation: consume optional whitespace after a compound; if next token is `>+~`, take explicit combinator and require a compound; otherwise if next is EOF/closing')'/comma, whitespace is trailing; otherwise whitespace introduces a descendant and requires a compound. Without whitespace/combinator, any token not belonging to the current compound is a structural error. Within function lists commas are separators; trailing comma requires another complex and errors at `)` or EOF. A closing `)` at top level errors there. Missing `]` errors at the next unexpected character/EOF; no forward recovery to a later bracket. After an ordinary pseudo-name, a subsequent colon/simple selector is allowed, not part of its name. Depth/branch checks occur only if earlier grammar is valid; no later cap overrides an earlier syntax error. Neither :is nor :where silently ignores bad or unsupported arguments. The explanatory error summary links to the failing field, shows a safely escaped short context and unit offset, and preserves the entire raw text.

Examples of exact errors: empty→EMPTY0; ` div/`→UNSUPPORTED_CHAR4; `.1x`→SYNTAX1; `div,span`→UNSUPPORTED_CONTEXT3; `:foo`→UNSUPPORTED_NAME0; `:is (.a)`→SYNTAX3; `:is(.a,)`→SYNTAX7; `:is()`→SYNTAX4; `[a`→SYNTAX2; `div >`→SYNTAX5; `div*`→SYNTAX3; `::before`→UNSUPPORTED_CONTEXT0; `.a::before:hover`→UNSUPPORTED_CONTEXT10; `:not(*::before)`→UNSUPPORTED_CONTEXT6. Length1025 wins before any unsupported character scan. `:is(.a,/bad)` reports slash offset7 even if another earlier structural error existed, because character scan precedes parsing. Full SPEC accepts the conservative parser behavior, not CSS forgiving lists.

### Structured results
Success `{ok:true,left:Analysis,right:Analysis,comparison:'left'|'right'|'equal',firstDifference:'A'|'B'|'C'|null}`. Failure `{ok:false,errors:[Error...]}`; no partial analyses. Analysis contains `raw`, `specificity:[A,B,C]`, `tree`. All keys and array ordering are stable. A tree node contains exactly `{kind,start,end,specificity,children}`; `end` exclusive; integer spans reference original UTF-16 raw. Kinds: selector, compound, type, universal, id, class, attribute, pseudo-class, pseudo-element, is, not, where. Root selector excludes outer whitespace. Function node span includes colon through close-parenthesis; its children are branch selector nodes in source order. Compound children follow source order. Simple leaf nodes include sigils and enclosing attribute brackets where applicable. Combinators have no node; relationship is visible from the intervening raw span. Function contribution uses child scores as described below; a where node and its descendants' local contributions are both shown, with an explicit “children ignored by :where” annotation so displayed leaf contributions cannot be mistaken for direct root addends. The interface may render this as a semantic nested list or table; all nodes and all three components must be inspectable without truncation. No HTML serialization of raw input.

Readonly summary template, LF separated, no final LF:
`L: (A,B,C)` / `R: (A,B,C)` / `comparison: left|right|equal` / `firstDifference: A|B|C|none`.
Numbers are unsigned decimal without grouping or leading zeros. This technical summary is language-invariant. Display localized explanatory prose separately. Equal firstDifference=null maps to `none`. Summary is a readonly textarea without clipboard access.

## 4. Algorithm and author examples
Each leaf contributes ID=(1,0,0); class/attribute/ordinary pseudo=(0,1,0); type/pseudo-element=(0,0,1); universal=(0,0,0). Compound sums children; selector sums compounds. is/not take the lexicographically greatest branch vector, not a componentwise maximum; tied branches do not multiply it. where contributes zero regardless of children, but all children must parse and their own scores remain in the tree. Comparison inspects A first, then B, then C. Components never carry into the next component. Under1024 units each component≤1024 and all arithmetic is exact safe integer. Parser advances monotonically, recursion depth≤4; AST/node/output size is O(input length), bound≤2049 nodes per field including structural wrappers; implementation may assert a conservative4096-node cap but must never reject a valid bounded grammar input for that cap. No repeated substring reparsing/exponential branch expansion. Retain spans, not repeated nested raw copies.
