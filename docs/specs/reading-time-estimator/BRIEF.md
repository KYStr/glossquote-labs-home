# 閱讀時間估算 / Reading Time Estimator — BRIEF

**文件草案，產品檢查 NOT_RUN** · `spec-reading-time-estimator-20261109`

Podcaster、部落客或電子報作者在錄音或發布前貼上一段中英混寫的稿子，要先知道：這篇讀者靜讀要多久（決定要不要標「X 分鐘讀完」）、自己朗讀錄音又要多久（決定節目或影片長度）。現在只能憑感覺猜，或用只會切英文空格、把中文整段當一個詞的線上計數器。

MVP 範圍。貼上本文（上限 100,000 個 UTF-16 單位），依釘版規則計數：漢字逐字計（四個表意文字區段）、英文以空白分詞且 token 含 ASCII 字母或數字才算 1 詞，兩邊相加；再以四個可調速度（中文靜讀 400 字/分、中文朗讀 240 字/分、英文靜讀 200 詞/分、英文朗讀 150 詞/分，均為預設）換成靜讀與朗讀秒數，總秒數只捨入一次並格式化顯示。非目標為逐詞頻率與排名（`word-frequency` 的工作）、實際語音播放（`text-to-speech-reader` 的工作）、中文分詞、可讀性評分、檔案上傳與保存本文。

首個可觀察案例。純中文短文的計數與兩種捨入（`zh-basic`）。字面資料與預期見 [fixtures.json](fixtures.json)，契約以 [SPEC.md](SPEC.md) 為準。

先完成核心／狀態測試，再交雙語靜態頁、匯出、build/check、同一候選的九面向證據。目標 `tools/reading-time-estimator/`，固定分支與 PR 交驗。
