# Decision Wheel Random Picker — preparatory BRIEF v0.1

Specification documentation only; no product claim, readiness event or implementation. Full normative contract is SPEC.md.

## 1. Goal
"What should we have for lunch?", "whose turn is it?", "which idea do we try first?" — groups stall on trivial choices, and any person who picks is suspected of bias. A decision wheel settles it visibly and fairly: every option gets an equal slice, a cryptographically strong uniform draw picks one, and nobody can argue with the method because the method is printed on the page. Success: the user enters 2–50 options (one per line), spins, and gets one uniformly random pick; with elimination mode on, each picked option leaves the wheel so a whole group can be ordered or narrowed down fairly, pick by pick, until one remains. The draw uses crypto.getRandomValues with rejection sampling (never Math.random, never modulo-biased raw draws), and the result is decided by the draw before the wheel animation plays — the animation shows the outcome, it does not create it. No account, no saved lists, no sharing: the page picks and forgets.

## 2. Scope and functional distinction
Pinned in the SPEC: entries are the non-empty lines of a textarea, trimmed, at most 60 characters each, 2–50 entries; duplicate lines are kept as separate slices and the page states plainly that a repeated option therefore has proportionally more chances — deduplication is never silent. The pick: draw one uniform index over the active entries by rejection sampling from a 32-bit crypto source (accept only values below ⌊2³²/n⌋×n, index = value mod n), so every active entry has exactly equal probability. The wheel renders equal slices; the spin animation (3–5 s, disabled to an instant result under prefers-reduced-motion) rotates to the already-drawn slice. Elimination mode removes each pick from the active list, keeps an ordered pick history, and names the last remaining entry "final remaining" rather than a pick; a reset restores the full list. Excluded: weighted/probability-adjusted slices, multiple simultaneous winners, saving or sharing lists, rigged or seeded "fun" modes, and any use for gambling (stated on the page).

Existing tools: Random Groups assigns every person into groups — nobody is singled out and chance is over partitions, not one winner from a list. Decision Matrix scores options against weighted criteria deterministically — the opposite of a random pick. The Dice Sum Distribution specification computes exact probabilities of dice totals; it never picks anything. No catalog entry, reserved specification or registry task picks one option at random from a user list; fresh registry/path/draft check remains mandatory before admission. All deterministic fixtures — the parsing of a sample list with blank lines and padded entries, the rejection-sampling index mapping (for n = 3 the single rejected value 4294967295 and 4294967294 → index 2; for n = 6 the four rejected top values), and a scripted elimination sequence over four options ending in a named final remaining entry — are re-derived by script during drafting.
