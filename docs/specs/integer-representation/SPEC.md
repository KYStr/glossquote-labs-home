## 1. Goal
A learner or developer needs to distinguish an integer's mathematical value from the fixed-width bit pattern that encodes it. Enter a signed or unsigned bounded integer in base2/8/10/16; choose8/16/32/64-bit signedness; obtain canonical mathematical representations, exact bits, hexadecimal byte groups and the same bits interpreted as signed and unsigned. Success: explain why decimal-1 in signed8 has bits11111111 and unsigned interpretation255, without incorrectly calling `-ff` its two's-complement hex representation. No user-research claim.

## 4. Closed input/output contract
Enums: base exactly2/8/10/16; width exactly8/16/32/64; signedness exactlysigned/unsigned. Core accepts primitive raw string and own plain fixed configuration; reject unknown keys/missing fields/types, inherited/accessor fields if externally callable. No JSON UI/import. Text raw cap80 UTF-16 units before trimming ASCII space/tab/CR/LF at ends. No maxlength silent truncation. Trim only ASCII; otherwise reject.

Optional leading `-` followed by at least one digit. No leading+,base prefixes,decimal points,separators,whitespace inside,exponent notation or suffix n. Valid digits by selected base:2:[01],8:[0-7],10:[0-9],16:[0-9a-fA-F]. Leading zeros and -0 accepted; canonical zero has no sign. `1e2` invalid in bases2/8/10 but valid hex value482 in base16 (lexical meaning depends on selected base); help/test must not falsely reject e as exponent in hex. `0b10` invalid binary but valid hex value2832; prefixes are not specially parsed. `0x10` invalid in EVERY base because x is never a valid digit. Signedness controls value range, not whether lexical minus exists: unsigned-0 is valid zero; unsigned-1 is range error.

Validation order: enum/schema; raw type/length; trim/empty; sign/digit grammar for selected base; bounded parse; numeric range. Parse magnitude digit-by-digit as BigInt accumulator n=n*base+digit; no Number conversion, eval, parseInt or floating intermediate. Max80raw characters caps worst-case magnitude to320bits. Apply minus only afterward; normalize0. w-bit unsigned range[0,2^w-1]; signed[-2^(w-1),2^(w-1)-1]. Reject overflow/underflow, no modulo input acceptance. All large decimal constants remain strings/BigInt, never JSON numeric fields.

For accepted mathematical integer n, modulus M=2^w and unsigned bit value u=n when n>=0 else M+n. Binary output is u in base2 padded with0 to exactlyw digits. Fixed hex is u base16 uppercase padded to w/4 digits, grouped into pairs separated by single ASCII spaces, most significant pair first. Signed reinterpretation s=u if u<2^(w-1) else u-M. Unsigned reinterpretation u. Numeric outputs use exact base10 strings. Mathematical base outputs use abs(n) digits with a leading minus if n<0, lowercase a..f in hex, no prefixes or leadingzeroes except0; this is not the fixed bit-pattern row. Labels must distinguish `mathematical hex` from `fixed-width hexadecimal bytes`.

Bit visualization shows exactlyw semantic cells ordered indexw-1 down to0, each with its index, bit0/1 and weight. Signed highest position has weight-2^(w-1), other positions weight2^i; unsigned all weights positive. Label chosen interpretation, while table gives both interpretations. Weight strings exact decimal. At64bits allow local horizontal scrolling of bit strip and provide a vertically reflowing table (four columns:index,bit,unsigned weight,signed weight) with all64rows. Bit strip is supplemental; no interactive toggles. No color-only sign bit; textual MSB/sign-bit marker and index. Significant input digits are not confused with fixed-width padding.

Result summary is REQUIRED readonly plaintext textarea, deterministic LF with terminal LF, exact key order: `width: W`, `input-mode: signed|unsigned`, `decimal: N`, `binary: signed-magnitude-base2`, `octal: signed-magnitude-base8`, `hex: signed-magnitude-lowercase-base16`, `bits: fixed-width-01`, `bytes-msb-first: uppercase-pairs`, `as-signed: S`, `as-unsigned: U`. Every line is key,colon,one ASCII space,value. ASCII key names stable across languages; native UI explanatory labels translated. No user text is inserted into key labels. Source base is intentionally omitted since representations fully specify n; changing base with same n yields same output. Never imply this text is machine ABI/file format.
