# Password Generator and Strength Checker — preparatory BRIEF v0.1

Specification documentation only; no product claim, readiness event or implementation. Full normative contract is SPEC.md.

## 1. Goal
A user creating a new account or rotating a weak password needs a strong, unique password generated on the spot and an honest read on a password they already use — without sending either to a remote generator or a breach-lookup service. Success: generate passwords with a cryptographically secure local random source at chosen length and character sets, see the exact entropy in bits computed from the stated model, generate pronounceable-free passphrases from a bundled wordlist with a stated wordlist size, and check an existing password's estimated strength with the same entropy model plus basic pattern warnings — all offline, with nothing typed or generated ever leaving the page or being stored.

## 2. Scope and functional distinction
Random password mode: length 8–128, toggles for lowercase/uppercase/digits/symbols (a fixed, documented symbol set), exclude-ambiguous option, guarantee at least one character from each enabled set, generation via `crypto.getRandomValues` with rejection sampling (no modulo bias), batch of up to 10 at once. Passphrase mode: 3–10 words from a bundled fixed wordlist whose exact size and selection entropy are stated, configurable separator and optional capitalisation/digit suffix, words drawn with the same unbiased method. Strength check mode: entropy estimate under an explicit model (character-pool estimate plus dictionary/pattern penalties itemised on screen), a plain-language verdict scale tied to the bit ranges, and warnings for repeats, sequences, keyboard walks, years and words from the bundled list; the checked password is never echoed into history, URL, title or any list. Copy buttons act per generated item via user gesture; a clear button wipes generated items and the check field. No breach-database lookup (that needs network and sends hashes), no password saving, no vault, no manager features, no auto-fill, no strength "score" presented as a percentage of safety.

Existing tools: Text Redactor masks chosen strings in text; Text Workbench counts characters; Random Groups samples list partitions for people, not credentials with an entropy contract. None generates secrets, models entropy, or handles the "never persist, never transmit" lifecycle this tool is defined by. Initial catalog/spec/task scope contains no password or passphrase tool; fresh registry/path/draft check remains mandatory before admission. The SPEC must state plainly that strength estimation is a heuristic model, not a guarantee, and that generated passwords should be stored in a reputable password manager — the tool itself stores nothing.
