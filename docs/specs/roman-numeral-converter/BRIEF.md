# Roman Numeral Converter — preparatory BRIEF v0.1

Specification documentation only; no product claim, readiness event or implementation. Full normative contract is SPEC.md.

## 1. Goal
Students, teachers, crossword and inscription readers, watch and monument spotters, and anyone copy-editing dates or chapter numbers constantly meet Roman numerals and need two things most online converters do badly: a conversion that is guaranteed canonical, and a validator that honestly rejects the near-miss forms people actually write (`IIII` on clock faces, `IC` for 99, `IL` for 49). Success: the user enters an integer 1–3999 or a Roman string in either field and immediately gets the other form — canonical subtractive notation by construction — plus a place-value breakdown showing exactly which symbol groups sum to the value. A non-canonical Roman input is never silently "understood": it is an error that names the problem and shows the canonical form of the value it would have meant. No account, no upload: nothing leaves the page.

## 2. Scope and functional distinction
The system is closed and normative: symbols I V X L C D M with values 1, 5, 10, 50, 100, 500, 1000; the canonical form is produced by one greedy table (M, CM, D, CD, C, XC, L, XL, X, IX, V, IV, I) and nothing else. Validity is defined exactly, not by a list of regex folklore: a Roman string is valid if and only if its loose subtract-or-add value lies in 1–3999 and re-encoding that value with the greedy table reproduces the string character for character. That single rule rejects every non-canonical form — IIII, IC, IL, VX, VV, LL, DD, XM, IXIX, IIV — and the SPEC pins twenty conversion fixtures plus sixteen invalid strings, all re-derived by script during drafting, plus an exhaustive round-trip requirement over all 3,999 values for the production test suite. Input rules are pinned: integer field accepts ASCII digits only, 1–3999, no sign, no decimal point, no grouping commas; Roman field is case-insensitive (normalised to uppercase), maximum 15 characters (the longest canonical form, 3888 = MMMDCCCLXXXVIII). The breakdown table decomposes the value by the greedy groups actually used (1994 → M 1000 + CM 900 + XC 90 + IV 4). Excluded: zero and negative numbers (Roman has no zero — stated in the UI, not faked as an empty result), values ≥4000 and vinculum/overline notation, apostrophus notation, lowercase-as-different-meaning, fractions, date or clock-face special modes, and persistence.

Existing tools: the consumed Integer Representation Inspector specification covers positional bases — binary, octal, decimal, hexadecimal, fixed-width two's complement and byte views of integers >2^53. Roman numerals are a non-positional, subtractive symbol system with no zero and no width; the two tools share only the word "integer" at the input field and never an algorithm, a table or a use case (base learning and bit inspection versus reading inscriptions, dates and chapter numbers). The Date Calculator adds and subtracts calendar days and does not read numeral systems. Initial catalog/spec/task scope contains no Roman numeral converter; fresh registry/path/draft check remains mandatory before admission.
