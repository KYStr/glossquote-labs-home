## 驗算中發現並更正之處

- 河牌圈手算分組初稿錯誤：把「對手一張 A＋一張 K」算成兩對 A、K（對手勝）。實際上公共牌無 A，單張 A 配不成一對 A；A＋K 只是對 K、A 踢腳，hero 的一對 A 勝。初稿合計勝 798／平 33／敗 159；兩套枚舉程式皆得 884／1／105，迫使重算分組，更正後分組（見上）與程式一致。fixture 採用更正後數字。
- Node 版 mulberry32 初稿漏寫第二步的 `t +` 項（寫成 `t ^ imul(...)`），蒙地卡羅得勝 84946／平 553／敗 14501（權益 85.22%），與 Python 版 84737／574／14689（85.02%）不符。按標準 mulberry32 補回 `(t + imul(...)) ^ t` 後，兩版全部欄位 0 差異。
- 評估器三對邊界 bug：6 張牌出現三對時，兩對的踢腳取「不在對子內的點數」會取空集合而崩潰；已修正為可用第三對的點數作踢腳（兩對＋第三對一張為最佳 5 張）。在算 `two-pair-flop` 時發現。
- `quads-turn` 初稿公共牌只寫 3 張（實為翻牌圈），對手可在補牌湊出方塊同花順（372 種敗局），四條並非近乎無敵；已改公共牌為 7c 7d Kd 2h（轉牌圈），敗局只剩手算的 3 種。
