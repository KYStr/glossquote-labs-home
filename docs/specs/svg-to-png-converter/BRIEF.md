# SVG to PNG Converter — preparatory BRIEF v0.1

Specification documentation only; no product claim, readiness event or implementation. Full normative contract is SPEC.md.

## 1. Goal
Designers, developers, teachers and small sellers constantly hold an SVG — a logo, an icon, a diagram — and need a PNG of it at an exact size: an app store upload, a slide, a marketplace listing, a document that cannot embed vector files. Success: the user pastes SVG markup or drops an .svg file, sees a preview of exactly what will be rasterised, chooses the output size by width, height or scale percentage, optionally picks a background (transparent by default), and downloads a PNG of exactly the stated pixel dimensions — all locally, with the artwork never uploaded. Because pasted SVG is untrusted markup, the tool sanitises it under a closed, auditable rule set before anything renders, and reports every item it removed, so "my SVG came out different" is always explainable from the page. No account, no watermark, no server.

## 2. Scope and functional distinction
Normative pieces, all pinned in the SPEC: input by paste (≤200,000 characters) or file (≤2,000,000 bytes, .svg); XML parsing with three distinct error classes (not XML, root not `<svg>`, size undeterminable); intrinsic-size resolution in four rules (width+height attributes; width or height alone with viewBox deriving the other; viewBox alone at 1 unit = 1 px; neither → error), where only unitless or px lengths count as stated sizes and other units make that attribute absent. The sanitiser is a closed contract: a named banned-element list (script, foreignObject, iframe, embed, object and eleven more), removal of every `on*` attribute, an href allowlist (`#fragment` and raster `data:image/` only), and stripping of external `url()`/`@import` from style content — with each removal counted and the total shown before download. Output: three mutually exclusive sizing modes (width 16–8192 px, height 16–8192 px, scale 10–1000%), the free dimension rounded half away from zero with a 1 px floor, hard caps of 8192 px per side and 33,554,432 total pixels checked before rendering, background transparent / white / one custom hex colour, rasterisation from a blob URL of the sanitised serialisation only (never the raw input), download named `svg-converted-<W>x<H>.png`. A permanent honest note states that SVG rendered as an image cannot use page or web fonts, so text in the artwork falls back to locally available fonts. Excluded: PNG/JPEG/WebP input (a different tool, below), SVG editing or optimisation (no path rewriting, no minification beyond sanitisation), batch conversion, JPEG/WebP output, animation (the first frame state only, stated), and persistence.

Existing tools: Image Resizer takes raster input (PNG/JPEG/WebP) and scales an existing pixel grid — it never parses markup, never sanitises, and its output size is a factor of its input pixels; this tool takes vector markup as its only input, so output resolution is chosen freely and the sanitisation contract is the product's core. The consumed SVG Dash Cycle spec explores stroke-dasharray animation values visually; it does not convert files. Print Size computes physical print dimensions of images. Initial catalog/spec/task scope contains no SVG rasteriser; fresh registry/path/draft check remains mandatory before admission. Sizing fixtures (five, including a 3×2 → width 100 → height 67 rounding case) and the sanitisation counting fixture are re-derived during drafting.
