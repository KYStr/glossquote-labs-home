# 洗烘兩機接續表 / Laundry Machine Handoff 製作簡報

預案 `spec-laundry-machine-handoff-20261109` · 文件待獨立審查

共用洗衣間的使用者已知當天一台洗衣機、一台烘衣機的不可用時段，要照自己指定的批次次序排到兩機，並限制每批洗完後在籃內等待的分鐘數。

在共用排班旁輸入兩台機器已占時段和各批實際週期，對照兩條時間軌，找出最早可用的一組轉接時間。

在洗衣間用手機查某批洗完及入烘時間。結果列可一眼比較洗機、等待、烘機三個時間段。

主要操作「排出洗烘接續 / Plan washer-to-dryer slots」。工作區採 Product App。頁面中優先呈現以下工作物。

```text
寬畫面
作業窗口／兩機保留區間   |   兩條時間軌及逐批轉接表

窄畫面（由上而下）
窗口 → 機器時段 → 批次 → 排出接續 → 洗／等／烘
```

首個貫通案例用 `laundry-machine-handoff.delayed-wash`。洗機被占到 08:20，烘機被占到 09:10。30 分洗、40 分烘且最多等 10 分時，首批改從 08:30 洗，09:10 進烘。

單日、兩台指定機器、固定批序、立即卸洗衣機到籃，兩機可並行。用整分鐘排出可行前綴與首個無法排入的批次。

產品界線與輸入、算法、九面向、測試、交接以 [規格](SPEC.md) 為準。起手先將 [字面案例](fixtures.json) 固定在 Node 24 離線測試，再接兩語操作。完成後固定 `tools/laundry-machine-handoff/` 候選及 open PR head，將真實檢查結果交主責。這份簡報的產品、瀏覽器、正式站 gate 全為 `NOT_RUN`。
