# Offline QR Code Maker — full preparatory specification v0.1

Specification documentation only; no product claim, readiness event or implementation. This document is the normative contract a future production task must satisfy exactly; where it says MUST, a differing behaviour is a defect, not a variation.

## 1. Goal
Primary audience: small-shop owners, market-stall and event staff, teachers, office workers and community organisers in Taiwan and elsewhere who print QR codes on signs, menus, slides and handouts. The recurring problem: online QR generators require uploading the payload to a third-party server, add watermarks or expiring "dynamic" redirects, and give no capacity warning until generation fails. Success is observable: the user types or pastes content (or fills the Wi-Fi form), sees a QR symbol that updates deterministically, is told the exact version and remaining capacity, and downloads a PNG or SVG that any mainstream reader decodes back to the exact input. Non-goals: scanning/decoding, logo embedding, batch generation, URL shortening, analytics, accounts, cloud saving, payment-amount validation for specific banks/wallets, and guaranteeing that a given reader app joins a Wi-Fi network (the tool formats the payload; joining is the reader's behaviour).

Assumptions: a modern desktop browser with Canvas 2D and SVG DOM support; content is user-supplied text only; no network at runtime. The tool MUST state on the page, in both languages, that a QR code is a printed copy of the content — anyone who can see it can read it — so users do not encode secrets they would not print.

## 2. Scope and functional distinction
Included: (a) free-text payload mode; (b) Wi-Fi payload builder with SSID, security type (WPA/WPA2, WEP, nopass), password and hidden-network flag, producing the conventional `WIFI:` string with exact escaping; (c) smallest-version selection across QR versions 1–40 at the chosen error-correction level (L, M, Q, H); (d) quiet-zone margin control (0–8 modules, default 4) and foreground/background colour pickers with a scannability contrast warning; (e) downloads: PNG raster at a chosen output size (256–4096 px, square, nearest-module rendering) and SVG vector with one path per the module matrix; (f) live capacity readout: current byte length, selected version, bytes remaining at the chosen level; (g) copy of the exact payload string as text (system clipboard via user gesture only).

Excluded: camera or image decoding; vCard/MeCard builders (a later specification may add them; free text can carry them meanwhile); geo/sms/mailto structured builders; logo or image centre overlay; colour gradients; batch/CSV; history or persistence across reloads; remote APIs of any kind; "dynamic QR" redirection. Exclusion is normative: a candidate adding an excluded feature is out of scope even if it works.

Distinction from existing work: Label Printer (labs-31 family) composes printable label sheets from list data and does not encode machine-readable symbols. Images to PDF and the image resizer transform supplied images; they synthesize no symbol. URL Inspector displays a parsed URL; it emits no graphic encoding. The UTF-8 Base64 Text Codec converts text to a text encoding for copy/paste; it produces no printable symbol and no binary download. No catalog entry, reserved specification or task in the registry at admission time encodes QR or any 2D barcode; the admission check MUST be re-run against the fresh registry before production, and a collision stops the task for coordinator decision rather than a rename.

Normative basis: ISO/IEC 18004 QR Code symbology, byte mode (mode indicator `0100`), character-count field widths per version group (8 bits for versions 1–9, 16 bits for 10–26, 16 bits for 27–40 in byte mode), Reed–Solomon error correction over GF(256) with primitive polynomial 0x11D, mask patterns 0–7 selected by the standard penalty rules, and format/version information BCH encodings. Wi-Fi payload syntax follows the de facto `WIFI:T:<sec>;S:<ssid>;P:<pass>;H:<hidden>;;` convention popularised by ZXing; characters `\ ; , : "` inside field values MUST be backslash-escaped.

## 3. User flow and lifecycle
Initial state: text mode selected, empty content, EC level M, margin 4, size 1024 px, default colours (black on white). The symbol area shows a neutral placeholder ("Enter content to generate") — never a QR encoding placeholder text.
Typing or pasting updates the symbol after a short debounce (≤150 ms) with no flicker of an intermediate wrong symbol: the render is computed fully, then swapped. If content becomes invalid (over capacity), the previous valid symbol is replaced by the error state — an outdated symbol MUST NOT remain displayed next to a capacity error, because a user could download the wrong code.
Wi-Fi mode: switching modes preserves each mode's field values during the session; the payload preview shows the exact `WIFI:` string before generation so the user can verify escaping. Choosing `nopass` disables and ignores the password field.
Colour change: if the contrast ratio between foreground and background is below 3:1, or the foreground is lighter than the background (inverted), a warning appears ("may not scan reliably"); generation is still allowed — the warning is advisory, never blocking, and is repeated on the download row.
Download: PNG and SVG buttons act on the currently displayed symbol only; the click creates a Blob, an object URL, and a programmatic anchor download, then revokes the URL. Downloading MUST NOT regenerate with different parameters.
Clear: a Clear button empties the current mode's fields and returns to the placeholder state. Leaving or reloading discards everything; nothing is stored in localStorage, cookies or any network location. Repeated operations are idempotent: same input ⇒ identical module matrix, identical SVG bytes, identical PNG bytes at the same size (PNG encoder metadata MUST NOT embed timestamps).

## 4. Input, encoding rules and exact output
Input domain: Unicode text, encoded as UTF-8 bytes for byte mode. Maximum input is bounded by version 40 capacity at the selected EC level: L 2,953 bytes; M 2,331; Q 1,663; H 1,273. The UI counts UTF-8 bytes (not UTF-16 code units) and MUST label the count as bytes. A single character that pushes the total past capacity triggers the capacity error naming the limit and the current size; no truncation is ever applied silently.
Segmentation: exactly one byte-mode segment for the whole payload in this version (no ECI, no Kanji mode, no mixed segments), so output is a pure function of (payload bytes, EC level). Version selection: the smallest version whose data capacity fits the terminated bitstream at the chosen level. Terminator, byte alignment and pad bytes follow ISO/IEC 18004 (`11101100`, `00010001` alternating).
Error correction and interleaving: per the standard block tables for the selected version/level; mask chosen by minimum total penalty (rules N1–N4) with ties resolved to the lowest mask index — this tie-break is normative so independent implementations agree bit-for-bit.
Format information and version information (version ≥7) MUST be placed per standard. The module matrix is the single source of truth: screen preview, PNG and SVG all render from the same matrix, never from re-encoded data.
PNG output: square canvas, module size = floor(size / (modules + 2×margin)), centred with the remainder distributed to the bottom/right as background; no anti-aliasing (each module a solid rectangle). Filename: `qr-<yyyymmdd>-<hhmmss>.png` in local time, or `qr-code.png` if the clock is unavailable — the filename contains no payload content. SVG output: XML with `viewBox="0 0 <w> <h>"`, background rect, one `<path>` of module rectangles (M/h/v/z commands), no embedded raster, no external references; filename `qr-code.svg`. Deterministic: identical inputs produce byte-identical SVG.
Wi-Fi payload grammar (exact): `WIFI:` then fields in order T, S, P (omitted when nopass), H (only when hidden is true, value `true`), each `KEY:value;`, and a final extra `;` — i.e. the string ends with `;;`. Escaping: in S and P values, each of `\`, `;`, `,`, `:`, `"` is prefixed with `\`. Security values: `WPA` for WPA/WPA2/WPA3 transition networks, `WEP`, `nopass`. Empty SSID is an error in Wi-Fi mode ("SSID is required"); empty password is allowed only for nopass.
Worked examples (normative fixtures): `HELLO` at level M MUST select version 1 and produce a 21×21 matrix. A 2,954-byte ASCII payload at level L MUST produce the capacity error (limit 2,953). Wi-Fi input SSID `A;B`, password `p:ss`, WPA, not hidden MUST yield exactly `WIFI:T:WPA;S:A\;B;P:p\:ss;;`.

## 5. Implementation and safety
Architecture (future production): a pure core module (payload builders, UTF-8 byte counting, QR matrix encoder, SVG string builder, filename helper) with zero DOM access; a controller binding inputs to the core; a thin DOM layer for preview canvas and downloads. The QR encoder MUST be either implemented in-repo from ISO/IEC 18004 or vendored as a single pinned file with its licence and source URL recorded in a `THIRD-PARTY.md`; runtime dependencies: none; no CDN, no network calls, no remote fonts.
Security/privacy: payload text is data, never markup — payload MUST NOT be inserted via innerHTML anywhere (including the payload preview, which uses textContent). SVG is generated from numeric matrix data only, so no payload string reaches the SVG. Colour values are validated as `#rrggbb` before use. The page makes zero network requests after load.
Bilingual and accessibility: full zh-TW (default) and English UI with identical control sets; the language toggle switches all strings including errors and the capacity readout. All controls are native inputs with visible labels; the symbol preview has a text alternative announcing "QR code for: <first 40 characters of payload>" to assistive technology without exposing more than the user typed; keyboard-only operation reaches every control and download; focus is never moved by rendering updates; the capacity error is announced via an `aria-live="polite"` region. Contrast warning logic uses relative luminance per WCAG.
Performance bounds: encoding at most 2,953 bytes is trivially fast; re-render on input MUST complete within 100 ms on a mid-range laptop for the maximum payload; no web worker is required or permitted in this version.
Toolchain: Node 24, zero npm dependencies, same house layout as sibling tools (public/, public/en/, core modules, node:test suites, build/check/serve scripts). Offline: the built page runs from file:// or any static host with no network.

## 6. Independent nine-aspect product rubric
Each aspect is scored 0–100 by a reviewer who is not the author, against the same fixed candidate commit; every aspect MUST reach ≥90 with all mandatory checks complete, otherwise the verdict is revision. Unrun checks stay NOT_RUN and block acceptance.
- functionality: both languages; text and Wi-Fi flows end-to-end; downloads decode back to the exact payload with an independent reader; version/EC/margin/size controls behave as specified.
- boundaries: capacity endpoints at all four levels (exact-fit and +1 byte), empty input, SSID escaping set, multibyte UTF-8 counting, oversized paste, repeated download.
- privacy: zero network requests after load (verified in devtools/network log), no storage writes, payload absent from filenames, URLs and page title.
- security: payload never reaches innerHTML or SVG text; colour validation; Blob URL revoked; no external resources.
- usability: first-time user completes a printable code without instructions; error states never leave a stale symbol; payload preview resolves Wi-Fi escaping surprises before printing.
- accessibility: full keyboard path, labelled controls, aria-live error announcement, preview text alternative, warning not conveyed by colour alone.
- localization-seo: zh-TW and en pages complete and equivalent; correct lang attributes, titles, descriptions and cross-links to the Labs home in the same language.
- toolchain-provenance: zero-dependency build reproduces byte-identical output from a clean checkout; vendored encoder (if any) pinned with licence file; scripts run on Node 24.
- compatibility: current Chrome/Edge/Firefox/Safari desktop; PNG opens in standard viewers; SVG validates as XML and renders identically in browser and a vector editor.

## 7. Required tests and timing
Core unit tests with independently derived expectations (not values copied from the implementation): (a) matrix fixtures — `HELLO` at L/M/Q/H compared module-by-module against matrices computed by an independent QR library during test authoring and then frozen as literal fixtures, with the library itself not a runtime or test dependency at verification time; (b) capacity table endpoints for versions 1, 10, 27, 40 and each EC level; (c) Wi-Fi grammar: field order, omission rules, the five-character escaping set, empty-SSID error; (d) UTF-8 byte counting for CJK and emoji inputs; (e) SVG byte-determinism across two runs and PNG module-rectangle sampling at three sizes; (f) filename format with a frozen clock.
GUI/evidence tests (desktop, real browser): type–preview–download–decode round trip using an independent decoder on synthetic payloads; contrast-warning appearance at a 2.9:1 pair and absence at 3.1:1; stale-symbol replacement on capacity error; keyboard-only completion; both languages screenshotted. Timing: full core suite under 60 seconds; no test may access the network.
Explicitly NOT_RUN at specification stage: all product tests above; this document claims document completeness only.
