# 交換禮物配對 / Gift Exchange Match 製作簡報

預案 `spec-gift-exchange-match-20261109` · 文件待獨立審查

小型交換禮物主辦人要讓每人送出一份、收到一份，同時避開自送與指定方向的禁配。產生一份固定解後可在同一台裝置逐張顯示受贈代號。

桌面主持人用參加者短名檢查方向性限制，按穩定順序得到配對。配對可用相同輸入重現。

遞手機看指定送禮者的單張卡，顯示區先隱藏，交接下一人前按關閉。主辦人可控制整台裝置並查閱配對，卡片僅減少同時曝光。

主要操作「建立交換配對 / Match gift exchanges」。工作區採 Product App。頁面中優先呈現以下工作物。

```text
寬畫面
短名表／方向禁配   |   送禮者清單＋單張揭示區

窄畫面（由上而下）
參加者 → 禁配 → 建立配對 → 選送禮者 → 揭示或關閉
```

首個貫通案例用 `gift-exchange-match.three`。A、B、C 無禁配時固定出現 A→B、B→C、C→A。從 A 卡切換到 B 卡後，A 的受贈者立即遮住。

3–16 個參加者，逐方向填禁配。一人一送一收，互送允許。結果按輸入次序給第一個可行解，提供單張揭示及收起。

產品界線與輸入、算法、九面向、測試、交接以 [規格](SPEC.md) 為準。起手先將 [字面案例](fixtures.json) 固定在 Node 24 離線測試，再接兩語操作。完成後固定 `tools/gift-exchange-match/` 候選及 open PR head，將真實檢查結果交主責。這份簡報的產品、瀏覽器、正式站 gate 全為 `NOT_RUN`。
