## 雙推導記錄

每個數字先手算（方法一：錨點＋日數手算，見下），再用第二種方法獨立重算（方法二：Python `datetime`／`zoneinfo` 腳本，僅用標準函式庫，從 fixture 的 input 重新推導 expected，逐項比對 fixtures.json；成功案例 9/9 一致，0 失敗）。兩種推導一致才定稿。

手算錨點（方法一）：2024-01-01T00:00:00Z = 1,704,067,200。推導：1970→2024 共 54 年，54×365 = 19,710 日；閏日 1972、1976、1980、1984、1988、1992、1996、2000、2004、2008、2012、2016、2020 共 13 日；合計 19,723 日 × 86,400 = 1,704,067,200。方法二以 `datetime(2024,1,1,tzinfo=utc).timestamp()` 得同一值。

## 來源核對（概念筆記與外部事實）

- 閏秒：概念筆記稱「閏秒要釘版」，未給數字。查核後釘版：POSIX 每日固定 86,400 秒、不計閏秒；IERS 公告 1972–2016 年共插入 27 次正閏秒，最近一次 2016-12-31 23:59:60；該閏秒與 2017-01-01T00:00:00Z 共用 1483228800（來源：IERS Bulletin C／NIST 閏秒表，經公開檢索核實；SPEC 內已寫明，不依賴概念筆記的未註明數字）。
- DST 規則：2026 年美國東部夏令開始 03-08、結束 11-01（3 月第二個、11 月第一個星期日），以 Python `zoneinfo`（IANA 資料庫）roundtrip 驗證，非憑印象。
- 概念筆記第 29 條稱「支援時區選擇（UTC／Asia/Taipei 等）」且「顯示 UTC 與 Asia/Taipei」：SPEC 採兩者並存——結果恆顯示 UTC＋Asia/Taipei，另加一個自選時區（9 個固定值），無衝突。
- `date-difference`／`days-until` 在概念筆記中以「若存在」為條件；本 checkout 查無，SPEC scope 節已如實寫明查無，並寫下日後出現時的區分規則。
