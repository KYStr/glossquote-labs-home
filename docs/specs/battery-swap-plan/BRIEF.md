# 活動備用電池替換表 / Event Battery Swap Plan 製作簡報

預案 `spec-battery-swap-plan-20261109` · 文件待獨立審查

活動工作人員為同規格電池組的相機或裝飾設備備料，手上已有各設備的實測可用分鐘及開機區間。想先排何時需要新一組，以及現有滿電組會在哪時用完。

桌面將各設備使用時段和實測續航填在同一工作表，讀全場按時序的裝入與替換清單。

現場手機查下一次替換屬於哪台設備，以及那一刻是否有預留電池組。

主要操作「排出裝入與替換 / Plan battery swaps」。工作區採 Product App。頁面中優先呈現以下工作物。

```text
寬畫面
電池實點／設備及開機段   |   時序裝入／替換及缺口

窄畫面（由上而下）
組數 → 各設備與時段 → 排出替換 → 第一缺口／時序表
```

首個貫通案例用 `battery-swap-plan.gaps-and-shortage`。三組電池，A 的 30 分鐘續航跨兩個時段。A 在第 50 分需要第 4 組，此時缺一組。

1–8 台、每台 1–16 個單日工作段、同款已滿電組。設備關閉間隔保持剩餘可用分鐘。電池使用後不跨裝置重用、不在活動內充電。依時間與設備輸入序分配。

產品界線與輸入、算法、九面向、測試、交接以 [規格](SPEC.md) 為準。起手先將 [字面案例](fixtures.json) 固定在 Node 24 離線測試，再接兩語操作。完成後固定 `tools/battery-swap-plan/` 候選及 open PR head，將真實檢查結果交主責。這份簡報的產品、瀏覽器、正式站 gate 全為 `NOT_RUN`。
