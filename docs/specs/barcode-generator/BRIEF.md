# Barcode Generator (1D: Code 128 / EAN-13 / UPC-A) — preparatory BRIEF v0.1

Specification documentation only; no product claim, readiness event or implementation. Full normative contract is SPEC.md.

## 1. Goal
Shop staff, warehouse helpers, librarians, market sellers and small manufacturers constantly need a few honest barcodes: a shelf label, a box code, a library card number, an internal SKU. Success: the user picks one of three symbologies (Code 128 for free-form internal codes, EAN-13 and UPC-A for retail-style numbers), types the payload, sees a correct scannable barcode rendered from stated rules — with the check digit computed (or validated) openly, the exact module count and physical size at the chosen module width shown — and downloads PNG or SVG at a stated scale for printing. No account, no watermark, no upload: the payload never leaves the page.

## 2. Scope and functional distinction
Code 128 subset is normative and closed: Code sets B and C only (Code A control characters excluded, stated), printable ASCII 32–126 in B, digit-pair packing in C under one deterministic auto-switch rule (digit runs ≥4 use C; an odd-length run donates its first digit to B), start/stop and mod-103 checksum per ISO/IEC 15417. EAN-13: 12 digits → check digit computed and appended; 13 digits → check validated, a wrong one is an error that shows the correct digit. UPC-A: the same contract over 11/12 digits. Encoding tables (Code 128 width patterns for values 0–106; EAN L patterns with G = reverse of R and R = complement of L; first-digit parity table) ship as auditable data files in the repository — a hand-typed partial table is a defect, and fixtures in the SPEC pin checksums, parity selection and two complete 95-module strings. Options: module width X in mm (0.25–1.00 in 0.01 steps, default 0.33), bar height in mm, human-readable text under the bars (on/off; EAN/UPC text split around the guard bars in the usual layout), PNG export at an integer pixels-per-module scale, SVG export in module units. Excluded: QR and other 2D codes (a different tool, below), Code 39 / ITF / Codabar (a later scope decision, not silent additions), barcode *reading*/scanning, sequential/batch number generation, label-sheet layout printing, logos, and saving payloads.

Existing tools: my own Offline QR Code Maker specification covers 2D QR payloads — a barcode generator is its 1D counterpart, disjoint in symbology, mathematics (check digits and code-set switching instead of Reed–Solomon and masking) and use (print labels instead of screen sharing). Label Printer lays out text labels and does not encode symbologies; Print Size concerns image dimensions. Initial catalog/spec/task scope contains no 1D barcode encoder; fresh registry/path/draft check remains mandatory before admission. Fixtures are computed in the SPEC and re-derived during drafting (the EAN-13 and UPC-A examples are the long-published reference codes 5901234123457 and 036000291452).
