# Taiwan Uniform Invoice Prize Check — preparatory BRIEF v0.1

Specification documentation only; no product claim, readiness event or implementation. Full normative contract is SPEC.md.

## 1. Goal
Every two months, people in Taiwan hold stacks of uniform invoices (統一發票) and must compare each 8-digit number against the winning numbers by eye — slow, error-prone, and usually done on ad or lottery-content sites that demand attention and sometimes the numbers themselves. Success: the user pastes the official winning numbers once (special prize, grand prize, first-prize set, and any additional sixth-prize 3-digit sets), then types or pastes their own invoice numbers one by one or as a list; each number is classified instantly and deterministically — exact tier, prize amount per the stated standard table, or no win — with the matching rule shown (e.g. "last 5 digits match first-prize number 2"). Everything is local; invoice numbers never leave the device.

## 2. Scope and functional distinction
Winning-number setup for one bimonthly period: special prize 特別獎 (one 8-digit), grand prize 特獎 (one 8-digit), first prize 頭獎 (one to five 8-digit numbers), optional additional sixth-prize 增開六獎 3-digit sets (zero to four). Checking in two modes: full 8-digit check with exact tier resolution — special/grand exact match; first-prize family by longest matching suffix (8=頭獎, 7=二獎, 6=三獎, 5=四獎, 4=五獎, 3=六獎）; sixth prize also by matching any 增開六獎 3-digit set or the last 3 digits of any first-prize number — and a quick mode accepting only the last 3 digits that reports "possible, needs full number" versus "cannot win" honestly instead of a fake verdict. Batch list input (one number per line) with a summary count by tier and total prize amount using the standard statutory amounts stated in the SPEC, labelled as standard amounts with the official announcement governing. No fetching of winning numbers from any website or API, no cloud invoice (載具） account connection, no barcode/QR scanning, no storage of checked numbers, no prize-claim instructions beyond a link-free note to check official rules.

Existing tools: Random Groups partitions lists; List Compare diffs two lists set-wise; Work Hours totals typed figures. None implements the Taiwan uniform-invoice suffix-tier rule set, the special/grand exact-match precedence, or the additional-sixth-prize convention; the domain rules, the two honesty modes and the tier summary are distinct. All example numbers in fixtures are synthetic and must not reproduce a real announced winning set as "current". Initial catalog/spec/task scope contains no invoice or lottery checker; fresh registry/path/draft check remains mandatory before admission.
