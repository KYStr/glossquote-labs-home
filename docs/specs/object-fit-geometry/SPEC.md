# Object-fit Geometry Explorer — specification v0.2 (sanitized candidate)

Document preparation, 2026-10-31. This candidate has not been published or formally registered; it is not a claim, ready stock or implemented product. Proposed eventual document directory: `docs/specs/object-fit-geometry/`. The author cannot independently approve this document.

## 1. Goal, audience and scope

Help a frontend author predict which part of an image remains visible in a fixed CSS content box, distinguish contain letterboxing from cover cropping, and obtain a small reproducible CSS rule. Users enter intrinsic image dimensions, content-box dimensions and two alignment percentages; the tool explains fitted size, offset, unused margins and visible source rectangle. It uses a schematic, never the user's actual image. This avoids asking for sensitive photographs merely to understand layout.

Known-source comparison on 2026-10-31: default registry376, catalog56, PR2–11, the 61 original tool responsibilities, subsequent Option Matrix/Gradient/Box Shadow/Grid/Cubic and the Fluid Typography/Elliptical Corners specification directions. No matching dedicated contain/cover visible-source geometry tool was found. Image Resizer actually decodes and downsizes a user file; Print Size estimates physical print size/PPI; Contact Sheet lays out multiple thumbnails; Image Overlay compares actual pixels; Box Fit concerns 3D packing; Grid positions page items. This proposal performs none of those workflows or modifications. It also neither edits fonts nor corners. Unpublished local content remains UNKNOWN, not absent or zero. Repeat current collision checks before any official registration; a matching owner stops admission rather than releasing their work.

Included: one virtual raster with positive integer intrinsic dimensions; one positive integer content box; contain or cover; physical horizontal/vertical alignment 0–100 percent; exact rational geometry; fixed decimal explanations; schematic clipped content; deterministic CSS; Traditional Chinese and English; explicit generation and manual text selection. Excluded: files/URLs, EXIF/rotation, image decoding, actual pixel preview, SVG natural sizing, fill/none/scale-down, outside-range positions, keyword/length positions, responsive srcset, density descriptors, aspect-ratio/layout inference, auto sizes, borders/padding, free-form CSS, arbitrary selectors, drag controls, animation, clipboard API, downloads, saving, accounts, remote APIs and deployment.

The mathematical model assumes the supplied source dimensions already describe an oriented raster's intrinsic ratio in consistent units; it is not a guarantee of browser naturalWidth for arbitrary image metadata. Box dimensions are CSS content-box px, not device pixels or surrounding layout measurements. Applying CSS elsewhere requires a real img with the same ratio and no overriding rules. Visible source coordinates are continuous geometric coordinates, not instructions for exact integer pixel cropping.

Semantic reference: [W3C CSS Images 3, dated 2023-12-18, sections 4.3.2, 4.5 and 4.6](https://www.w3.org/TR/2023/CRD-css-images-3-20231218/). Contain preserves ratio within the box; cover preserves ratio while covering it. Position aligns corresponding percentages of the object and its positioning area. This document's bounded schema, arithmetic precision, UI, serialization and evidence requirements are product choices, not quoted standard requirements.

## 2. User flow and interaction

Initial raw defaults: source width Sw=800, source height Sh=600, box width Cw=300, box height Ch=200, mode=cover, horizontal P=50, vertical Q=50. Initial state has no computed output; a labeled example explains that no photograph is requested. Field order is Sw, Sh, Cw, Ch, mode, P, Q. Use text inputs with inputmode=numeric for the six numbers and a native radio group for mode. Field labels always include units and ranges. P=0 is physical left; P=100 right; Q=0 top; Q=100 bottom. These meanings do not flip with language.

Generate validates the complete snapshot. List all invalid fields in visual order, attach their error IDs with aria-describedby, set aria-invalid, and focus the first invalid control. Unknown/tampered mode gets a mode-group error and first radio focus. Valid generation displays one result region: explanatory mode sentence, schematic, all numeric outputs, and readonly CSS textarea. On success do not programmatically move focus: a keyboard/button invocation already focused on Generate remains there, while Enter submission from a numeric input stays in that input. Pointer activation preserves the browser's resulting focus rather than forcing button focus. Announce a short polite result message, not every number. Enter in a numeric field submits; radio Space/arrow behavior remains native. Event is ignored while an IME composition is active; compositionend itself does not generate.

Any input/change/compositionstart immediately invalidates the result: clear diagram, numbers and CSS, disable Select CSS, remove old success announcement and show 'Inputs changed; generate again'. Raw fields stay as edited. Do not retain a hidden stale-result copy usable by an export control. Revising back to previous text does not resurrect output; Generate is required. Repeated Generate replaces the single result, never appends sections or listeners. There is no pending async calculation and no delayed clipboard success.

Select CSS, enabled only for current valid output, focuses and selects the readonly textarea with a visible instruction to use the operating system's normal Copy command. Never claim a copy occurred. The textarea itself remains keyboard-selectable. Failure to set a selection produces the instruction to select manually, with output intact. It does not read/write the clipboard and creates no permission prompt. Generation after selection clears the old selection as part of replacing the result.

Clear has no confirmation dialog because nothing is saved: set all six numeric inputs empty, mode=cover, remove all result/errors/status, disable selection, focus Sw. Defaults is a separately labeled button, sets the seven default values and invalidates results but does not generate; focus stays on Defaults. Both buttons are explicit and cannot submit. Example buttons are unnecessary.

Visibility hidden invalidates generated results but retains raw fields; returning visible leaves a 'generate again' notice. pagehide invalidates results and clears all raw numeric fields, mode=cover. pageshow with persisted=true repeats that clearing to avoid a stale BFCache result. Initial nonpersisted pageshow keeps fresh-load defaults. Reload/new document starts defaults, with no storage/URL restoration. Browser/OS memory erasure and history snapshots are outside the privacy promise. Same behavior in both languages. Language links are real document navigation, not a silent input translation: visible warning says unsaved values are not transferred; link includes no input in URL. No unload dialog, popup or history interception.

## 3. Inputs, outputs and exact numerical contract

Each raw numeric string is at most 16 UTF-16 code units before trimming. Trim ASCII U+0020/U+0009/U+000A/U+000D at both ends only. Remaining text must full-match ASCII [0-9]{1,4}; leading zeros accepted, signs/decimal/exponent/commas/Unicode digits/embedded whitespace rejected. Convert validated digits to an integer without parseFloat. Dimension range Sw,Sh,Cw,Ch is 1–4096 inclusive; P,Q range is 0–100 inclusive. A four-digit restriction applies even to harmless leading zeros. Empty strings are errors, never coerced to zero. Validate raw length, syntax, then numerical range per field; mode only exact contain/cover. Result is absent if any field invalid. Native maxlength is not the only defense; pure parser rechecks programmatic inputs. Canonical output uses minimal ASCII integer digits (0001→1,0000→0).

Let p=P/100 and q=Q/100 as exact rationals. For contain, s=min(Cw/Sw,Ch/Sh); for cover, s=max(Cw/Sw,Ch/Sh). Equal ratios are a single exact fit. Set rendered width Rw=Sw*s, height Rh=Sh*s, offset X=(Cw-Rw)*p, Y=(Ch-Rh)*q. X/Y are positions of the rendered image's top-left relative to the content-box top-left; cover offsets are nonpositive on cropped axes, contain nonnegative on letterboxed axes.

Intersection edges in box coordinates: L=max(0,X), T=max(0,Y), R=min(Cw,X+Rw), B=min(Ch,Y+Rh). In this bounded domain R>L and B>T. Visible source rectangle uses x0=(L-X)/s, y0=(T-Y)/s, x1=(R-X)/s, y1=(B-Y)/s. Source origin is physical top-left; x1/y1 are exclusive geometric edges, not last included integer pixels. Output x0,y0,x1,y1 and visible width Vw=x1-x0, height Vh=y1-y0. Crop amounts in source units are left=x0, top=y0, right=Sw-x1, bottom=Sh-y1. Box unused margins in CSS px are left=L, top=T, right=Cw-R, bottom=Ch-B. With these two modes there is no simultaneous crop and letterbox on the same output; exact fit has all zero. Visible source area percentage A=100*Vw*Vh/(Sw*Sh). This is geometric area retained, not a perceptual quality score.

All intermediate comparisons/operations must be exact integer/rational (BigInt numerator/positive denominator, gcd normalization). Never round s before computing offsets or source geometry. Rationals may exceed Number safe limits during area products; do not silently convert them to Number. Conversion to a finite Number is permitted only at the diagram rendering boundary after all exact results exist. The domain is fixed and finite; no iterative solver or network call is needed.

Text formatting: s fixed 6 decimal places; every length/coordinate and A fixed 2 decimal places; round nearest with exact half-away-from-zero, then pad trailing zeros. Suppress negative zero to 0.00 or 0.000000. Decimal dot and ASCII digits are identical in both languages. For an exact rational n/d, determine rounding by integer quotient/remainder of abs(n)*10^digits/d; increment iff 2*remainder>=d, then restore sign unless rounded magnitude is zero. Geometry/percent classifications use exact values, never displayed rounded values. Explanatory line warns displayed values are rounded and may not sum exactly. Domain examples: s=1/128→0.007813; s=1/3→0.333333; a negative offset -0.125→-0.13; an exact zero→0.00. Nonzero crop that rounds to0.00 still has 'cropped' classification with an exact-value tooltip/fraction detail in the numerical table. Provide reduced fraction text for every numeric output on expanding one native details element; no hidden precision mystery.

Display all seven canonical input values, rendered size, scale, signed X/Y, source rectangle and visible size, four source crop amounts, four CSS-box margins, and A with explicit units. The classification is 'exact fit' iff Rw=Cw and Rh=Ch; otherwise 'letterboxed' for contain, 'cropped' for cover. Upscaling label shown iff s>1, with no misleading promise of sharper images. Contain allows upscaling; it is not scale-down.

CSS is a fixed selector and fixed declaration order, UTF-8 without BOM, LF only, 2-space indentation, one final newline:

```css
.fit-image {
  display: block;
  box-sizing: content-box;
  width: 300px;
  height: 200px;
  padding: 0;
  border: 0;
  object-fit: cover;
  object-position: 50% 50%;
}
```

Substitute only canonical Cw,Ch, exact enum mode,P,Q. Sw/Sh never appear as CSS dimensions; they describe the source, not the element. No comments, HTML, URL or user selector. Copy instruction explains applying class to an img of the supplied ratio and checking existing max-width/min-size/important/container rules; exported declarations are not a page-layout reset or image crop file. Same valid snapshot must produce byte-identical CSS in both languages.

## 4. Visual model and accessibility behavior

The result is labeled 'Geometry schematic — not a photo or native image rendering'. Use inline SVG with viewBox 0 0 Cw Ch; a fixed clipPath bounds the image rectangle to the box. Draw a background showing letterbox area, the computed image rectangle at X,Y of size Rw,Rh, and a small fixed pattern of center/quarter guide lines transformed with the image. No text is embedded inside the diagram: all values/labels live in HTML. Keep the clipPath ID constant per page (one diagram only), not user-derived. Diagram is aria-hidden=true because the full labeled table supplies the same information. A surrounding static legend identifies box background and source region without relying solely on color; pattern and boundary styles distinguish them.

On screen, scale uniformly to fit an available stage no larger than 480×320 CSS px; stage uses a minimum visible outline for extreme ratios but never silently changes underlying geometry. Specifically set displayed width D=min(480, available content width), displayed height limit320 and k=min(D/Cw,320/Ch); SVG CSS width=Cw*k and height=Ch*k. Keep a separate enclosing focusable explanatory panel if needed, not an enlarged geometric shape. If either displayed dimension<2 CSS px, retain the proportional SVG and show a prominent 'Very thin schematic; use the numeric table' notice. Preview outline belongs to the outer wrapper, not the mathematical content box. No 16-million-pixel bitmap or huge unscaled element. At narrow widths, table rows wrap as label/value pairs; CSS textarea scrolls locally, never forces whole-page horizontal scroll.

All inputs have visible labels and persistent range/help text. Error styling includes text, not only red. Keyboard order follows visual order, then Generate/Defaults/Clear, fraction details, Select CSS and output. Native controls only; no modal, drag gesture or mouse-only operation. Focus must remain visible and not be covered by sticky panels (none required). Result updates cannot steal focus except first-error behavior. Status uses one polite live region and no repeated announcement loop.

Finite contrast requirement for the application UI: opaque sRGB theme, all functional text at least4.5:1 against its actual background (also applies to large text as a stricter local design choice); enabled input/button boundaries and focus indicators at least3:1 against each directly adjacent color; informative legend marks at least3:1 plus pattern/text equivalent. Measure normal, hover, keyboard-focus, invalid and generated states in the actual desktop browser using computed colors and unrounded ratios. Disabled buttons remain labeled and their unavailability is stated in text; disabled styling and UA selection highlight are excluded from these numerical pair checks, not from basic readability. The diagram itself is a supplementary illustration, not a contrast checker. Do not claim full WCAG certification from this finite list.

Required desktop checks are actual keyboard travel, semantic names/descriptions, 200% browser zoom and a320 CSS px viewport in one available desktop Chromium. Screen-reader and other-engine/mobile observations can be added but are not new hard gates when unavailable; record NOT_RUN, never invent PASS. No animation or motion dependency exists; reduced-motion setting therefore does not remove content or change geometry.
