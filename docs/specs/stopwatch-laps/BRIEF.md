# Stopwatch with Laps — preparatory BRIEF v0.1

Specification documentation only; no product claim, readiness event or implementation. Full normative contract is SPEC.md.

## 1. Goal
Anyone timing repeated efforts — a runner doing intervals, a swimmer's coach, a teacher timing lab rotations, a speedcuber — needs more than a running clock: they need each lap's own duration, the cumulative split at each lap, and a quick answer to "which lap was fastest, which slowest". A plain stopwatch shows a total and forgets; a phone timer counts down to zero. This tool runs up from zero on one monotonic time base, records laps (each lap duration is derived, never independently timed, so the laps always sum exactly to the last split), marks the fastest and slowest laps, and exports the whole table as CSV for a training log. Success: start, lap several times, pause and resume, and the table, the statistics and the exported file all agree to the millisecond because they are all computed from the same stored split list. No account, no saved history, nothing leaves the page.

## 2. Scope and functional distinction
Pinned in the SPEC: states idle / running / paused driven by an injected monotonic clock (performance.now in production, fake clock in tests); elapsed accumulates only while running, so paused wall time never counts. Start/pause/resume/reset; Lap is accepted only while running, up to 500 laps, the 501st refused with a visible message. Each lap stores its split (elapsed at the lap press, whole milliseconds); lap duration = split_n − split_(n−1) with split_0 = 0, so Σ lap durations = last split exactly. Display format: under one hour `MM:SS.cc`, at or over one hour `H:MM:SS.cc`, centiseconds by truncation (floor), never rounding — a reading of 59.999 s displays 00:59.99 and only becomes 01:00.00 at exactly 60,000 ms. Statistics, shown once at least one lap exists: fastest lap, slowest lap (ties for both go to the earliest lap number), and average lap = last split ÷ lap count, computed in exact milliseconds and displayed under the same truncation rule; the in-progress lap (elapsed − last split) is displayed separately and never contaminates the completed-lap statistics. CSV export of the lap table: header `Lap,Lap Time (s),Split Time (s)` and one row per lap with times in seconds at exactly three decimal places derived from the integer milliseconds. Excluded: countdown or alarms, audio cues, saved sessions, accounts, GPS or sensor input, and multi-athlete timing.

Existing tools: Focus Timer is a countdown (time remaining toward a target, pomodoro-style) — this tool counts up from zero and derives lap structure, the opposite direction with different state. Metronome schedules audio clicks at a tempo; it shares only the words "time" and "monotonic". Meeting Cost Calculator's timer mode prices elapsed time against a roster and forbids per-tick accumulation of money, but it records no laps and computes no per-lap statistics. Typing Speed Test measures one fixed-duration attempt. No catalog entry, reserved specification or registry task provides a lap stopwatch; fresh registry/path/draft check remains mandatory before admission. All fixtures — splits at 30,000 / 75,450 / 120,000 ms giving laps 30,000 / 45,450 / 44,550 ms, fastest lap 1, slowest lap 2, average exactly 40,000 ms; display cases 0 → 00:00.00, 61,234 → 01:01.23, 3,723,456 → 1:02:03.45, 59,999 → 00:59.99; a pause case (10 s run, 60 s paused, 5 s run → elapsed 15,000 ms); and the tie case (two 20,000 ms laps → fastest and slowest both lap 1) — are re-derived by script during drafting.
