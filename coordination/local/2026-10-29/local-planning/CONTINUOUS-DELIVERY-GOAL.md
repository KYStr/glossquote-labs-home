## 可直接設定的目標全文

主對話負責選題、需求、架構、完整 Markdown 規格、任務拆解、跨專案協調、獨立驗收、發布整合及狀態總表。每款工具先在 tool-projects/<編號>-<slug>/ 建立可獨立交接的資料夾與必要資料，再實際建立以功能名稱命名的新對話，明確指定 gpt-6.1-sol 與 max。已有工具沿用原功能對話，不開重複對話；修正需求由主對話實際傳回原對話執行，不能只給使用者轉貼提示詞，也不能默默改由主對話內的子代理取代。主代理預設維持 gpt-6-astra / max；區分設定請求與可驗證的實際模型，不宣稱文字提示能切換模型。

每個功能對話的有界目標是：按規格完成可用產品與測試、繁體中文及英文獨立靜態頁面、完整 SEO 和隱私/安全設計；完成必要檢查後，推送至 KYStr/glossquote-labs-<slug> 的獨立公開 GitHub repository，經主對話驗收與發布整合，部署到免費的 <subdomain>.glossquote.com，驗證正式網址並加入雙語首頁。主對話控制共用首頁與正式部署操作，功能對話交付完整發布配置、產物及證據；不能讓功能對話為了這個目標自行取得或擴張憑證權限。不得把 source-only 或 localhost 當成已上線。

## 每個資料夾必備的交接內容

2026-10-18 使用者補充：測試不得控制電腦或干擾使用者工作。只用瀏覽器工具及任務專屬隔離／隱藏分頁進行 UI 驗證，不操作桌面、原生應用程式或 OS 滑鼠鍵盤、不搶焦點、不改使用者既有分頁或剪貼簿。不得觸發原生列印、系統檔案選擇／儲存等 OS 視窗；相關項目逐項保留 NOT_RUN／人工待驗。瀏覽器工具直接支援且不依賴 OS 視窗的檔案操作及背景 CLI 檢查仍可執行。每次新對話或返工委派必須一併傳達。

沿用 AUTHORING-CONTRACT.md 的自包含原則，至少包含：

- README.md / START-HERE.md：用途、開工順序、執行與驗證命令、真實狀態。
- PRODUCT.md：需求編號、具體工作情境、預設值、輸入輸出/上限、錯誤、資料生命週期、非目標。
- TECHNICAL.md：檔案結構、演算法與模組介面、狀態/取消/資源清理、依賴和授權。
- UX-SEO.md：兩語介面與內容、鍵盤/行動裝置、正式 canonical、hreflang 含 x-default、robots、sitemap、符合可見內容的結構化資料，以及首頁互連。預覽保持 noindex；正式索引以真實 URL 和驗證為準。
- ACCEPTANCE.md：需求對照、可重現輸入、預期結果、測試命令、瀏覽器/設備要求、必要 gate 和可保留人工項的界線。
- TASKS.md / TASK-ENTRY.md：有界里程碑、任務 ID、相關檔案、允許修改範圍、不可破壞行為、驗收及停止條件。

功能對話建立時必須把完整目標、背景、所屬資料夾、模型請求與責任邊界一起交付。該對話若可用 Goals，請它為自己的有界交付建立目標，包含外部回報後的修正；目標工具不可用或有舊目標不能替換時如實記錄，不編造設定成功。
