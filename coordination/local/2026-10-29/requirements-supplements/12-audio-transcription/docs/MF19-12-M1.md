## 第一方數值收據

`phase` 僅固定 `read-receipt`；Worker message 的 `type` 僅固定 `u19-memory-phase`，其餘欄位為數值。每 realm 上限 512 筆加一筆 overflow，overflow 使診斷不完整。helper 只保留數值，不保留 Response、reader、signal、PCM、逐字稿、response body 或任意錯誤文字。

| 欄位 | 意義 |
|---|---|
| scopeCode／ordinal／readId | 1=模型、2=Page；固定檔案次序；realm 內遞增讀取識別 |
| expectedBytes／receivedBytes | 配置大小或上限；實際成功複製到有界 buffer 的 bytes，超限 chunk 不計入 |
| eof | 是否真的讀到 `done: true` |
| hashChecked／hashOk | 原有 SHA-256 操作是否完成及比對結果，不輸出 digest 或內容 |
| readerLocked／lockObserved | 該事件觀察到的 `response.body.locked`；0=這次未重新觀察時，保留值不可解讀為當下狀態 |
| hasSignal／signalAborted | 該 fetch 是否有 AbortSignal 及當時狀態；Page 原本無 signal，因此均為 0 |
| outcomeCode | 0=未結束、1=該階段成功、2=失敗 |
| wallTimeMs／monotonicMs | Date.now／performance.now；monotonic 只在各自 realm 比較，不跨程序直接相減 |

事件碼：1 START、2 READER_ACQUIRED、3 EOF、4 HASH_RESULT、5 CANCEL_CALLED、6 ABORT_SIGNALLED、7 ERROR、8 FINISH。

原因碼：0 NONE、1 CALLER_SIGNAL、2 TIMEOUT、3 HEADER_LENGTH、4 SIZE_CAP、5 SHORT_READ、6 HASH_MISMATCH、7 READ_ERROR、8 LOAD_ERROR、9 RESPONSE_REJECTED。原因碼是本程式分支，不能當作 Chromium 的取消發起者證明。CANCEL_CALLED 在原本 cancel 呼叫之前記錄，表示已嘗試呼叫，不表示已收到網路取消確認。

模型 ordinal 1–19 對應固定 manifest 順序；成功 FINISH 包含 EOF、精確 bytes 和 hashOk。Page ordinal 1=manifest、2=quality-speech metadata，兩者 expectedBytes 是 65536 上限，沒有新增 SHA；ordinal 3–15 是原 13 個假語音。Page FINISH 代表有界讀取結束，fixture HASH_RESULT 在其後由原驗證位置記錄。JSON 未 hash 不能宣稱 hash 通過。

## Server 收據的證據界線

明示啟用後，`server-receipt` 分開記錄 eventCode 1 received、2 finish、3 close；finish 和 close 都保留。記錄 requestId、固定 pathOrdinal、數值時間、statusCode（received 為 0）、declaredBodyBytes、bodyBytesSubmitted、writableFinished、writableEnded、requestAborted。

`declaredBodyBytes` 來自 Content-Length；`bodyBytesSubmitted` 只計向原 response.write/end 提交的 bytes，含排隊的 bytes，**不是 client 收到、不是 wire bytes，也不是 client ACK**。`requestAborted` 是 incoming request 狀態。正常 finish／close 不證明瀏覽器成功完成請求。logger 不記 body／header／任意 URL，固定路徑對照另存 `server-read-ordinals.json`；未知路徑為 0。

client readId、server requestId、Playwright requestId、原生 CDP requestId 屬於不同命名空間；主代理須用目標、URL、固定 ordinal、時間及唯一性關聯，不得直接視為同一個數字。失敗請求的 Playwright sizes 可能退回 Content-Length，不能當成獨立 wire-byte 證據。

## 上游線索：僅是假說

[Playwright issue 42742](https://github.com/microsoft/playwright/issues/42742) 的開放報告描述 no-store 串流讀到 EOF，原生仍報 ERR_ABORTED；公開最小範例已有 releaseLock。這支持繼續核對原生串流生命週期，不能證明本產品根因或修正。[Chromium CL 6716020](https://chromium-review.googlesource.com/c/chromium/src/+/6716020) 與 [issue 568852319](https://issues.chromium.org/issues/568852319) 是主代理提供的線索；本次讀取工具無法取得兩者內容，未宣稱已合併或已修正。

本產品已知同樣使用 server Cache-Control: no-store、fetch cache:no-store、有界 getReader 迴圈，靜態檔案透過 createReadStream.pipe 寫入；實際分塊／終止次序仍待 native CDP 與本收據核對。保留 no-store、串流 API、完整性檢查及所有原驗收門檻。
