## A：全本地單一免安裝檔

### 第一次與再次使用

第一次：網站清楚顯示適用系統、檔案大小／版本與「在你的電腦處理」→ 使用者下載單一檔案並明確開啟 → 程式自行準備工作環境及介面 → 貼連結、選影片或音訊、明確開始 → 保存結果。OS 若要求執行確認或阻擋，由使用者依組織政策決定；不教停用防護。程式開啟後的介面準備不再要求使用者選路徑、啟動額外命令或安裝 Node／FFmpeg。

再次使用：使用者開啟保留的同一主程式 → 直接進工作區。主程式保留重用是此候選的預設，不代表常駐、服務或開機啟動；正常下載流程不要求用完刪掉它。若使用者將來要移除主程式，可自行刪除那一個檔案，這不是每次使用的必要步驟，也不承諾主程式退出後自刪。

### 產品可以自動承擔什麼

候選方式是把必要 runtime 與已核准引擎固定在同一發布檔內；若執行時必須展開內部元件，程式只展開到自己可辨識且受限的 session 目錄，檢查完整性、磁碟與啟動結果，並顯示實際「準備中」階段。這不等於技術已打包成功，也不是下載任意最新遠端元件、偷偷更新或永久安裝服務的授權。若不能合法且可靠地內含必要元件，須回報可行性缺口，不把安裝負擔轉給使用者並宣稱驗收通過。

完成、取消與正常退出時，停止自己的工作、確認停止後清自己的 partial／中間檔及不用的展開元件；最終媒體先驗證並保存到獨立位置。清理失敗應有介面內可重試的動作，不要求使用者找資料夾。當機或斷電時無法保證退出程式碼執行，可於下一次開啟辨識並處理自己的未完成 session；在沒有再次開啟前，不宣稱殘留已全清。不得掃描刪除整個 Temp／Downloads。

### 資料流、成本與不可先承諾的事

媒體網址與內容由本機向來源平台／CDN取得，媒體不經 GlossQuote 處理服務；平台仍可看到 IP 與請求。公開網站只提供介紹與版本入口，不自動探測 localhost、不夾帶媒體網址啟動助手。助手明確開啟後，候選本機頁及 API 採同 origin、loopback 與既有權限邊界。

主要成本在打包、版本維護、分發流量、供應鏈／license 與跨系統驗證；是否需要付費簽章等須另確認，不在此授權支出。單檔不保證 OS 信任提示消失，也不保證受管電腦允許執行。既有八平台 URL 認識不能證明引擎能下載；登入、DRM、付費、私密、直播與播放清單仍不在首版範圍。

### 選定 A 後的最小可觀察里程碑：單檔啟動、保存與清理垂直切片

交付必須是**可實際開啟的單一 Windows 候選檔**，含版本與 SHA；不能交原始碼 ZIP、要求預裝 Node 的腳本，或只有新的 pure core。新增 native／打包依賴需先給固定版本、hash、license 與允許執行範圍。

在主代理核准的隔離測試環境、未預裝產品 runtime／引擎的使用者情境下，實測「取得檔案 → 明確開啟 → 產品自行準備 → 使用標示清楚的受控合成媒體來源 → 保存可驗證影片／音訊 → 取消另一次工作 → 正常退出」。受控來源只是測試來源，不能假扮真平台相容；測試 transport 不能藉此放寬正式管線的內網拒絕規則。

可驗收證據包括：使用者不手動解壓／配置／清暫存；必要元件實際可用；輸出有真 bytes、容器／音軌／時長驗證；停止 ACK 前不誤稱取消；自身工作及展開檔清理前後清單、重名不覆寫、磁碟不足／被 OS 阻擋／清理失敗的可操作狀態。這一階段驗單檔體驗與真實檔案生命週期，**不是各平台下載支援通過**。目前尚無此候選檔，也未做以上執行測試。

## B：完整網頁、服務端協助

### 第一次與再次使用

第一次：開啟網站 → 在輸入區看見「網址與影音會送到服務端處理」的短說明 → 貼連結、選種類並明確開始 → 網站顯示真實階段 → 結果可下載時保存。再次使用走同一網站與相同操作，不需開啟本機助手。不得先送出網址，之後才揭露處理位置。

此候選採服務端取得媒體、處理並回傳結果，因此**網址與媒體內容都會經服務端**；不能沿用「全部在你的電腦處理」文案。使用者沒有因此授權讀帳號 cookies、登入憑證或私密內容，也不把服務端能力當作來源下載許可。

### 自動準備、清理與必要使用者步驟

引擎、格式預設、限額、工作排程、輸出驗證與暫存由服務營運端承擔。服務須事先固定每工作 bytes／時長、總併發／磁碟／費用預算、輸出保留期限、取消／連線中斷與到期清理規則。取消及逾時需停止真正的服務端工作，不能只關前端進度。使用者關頁不能當作唯一停止／清理觸發器。

完成後的服務端結果仍是受控的暫存副本：在明示的重試／保留窗到期後自動清除；清除服務端副本不影響使用者已下載的成果。傳輸結束也不代表使用者已確認保存，介面須區分「檔案可下載」與可證明的保存狀態。無法清除或未確認停止需如實顯示，不能讓一般人自行找雲端資料夾。

保存仍受瀏覽器下載設定與可用 API 約束；可能直接使用既有下載設定，也可能出現保存／下載確認。網站不能以 JS 取得任意本機路徑權限。[MDN 的 showSaveFilePicker 說明](https://developer.mozilla.org/en-US/docs/Web/API/Window/showSaveFilePicker)列出使用者互動、安全 context 與相容性條件；不支援時須有標準瀏覽器下載路徑，不能留下無效按鈕。

### 資料流、成本與不可先承諾的事

`使用者提交網址 → 服務端連來源／CDN → 服務端處理及短暫保存 → 瀏覽器下載`。需要重新訂出隱私、存取控制、留存／刪除、診斷不記原網址及內容、來源條件與維護責任。對外連線仍須逐跳處理 SSRF／redirect／DNS 目的檢查，不能讓使用者網址變成任意抓內網的服務。

這是架構推論：把抓取放到服務端，避免了「必須由瀏覽器 script 跨站讀取」這一前提；它不保證原站允許服務端下載、沒有驗證或永遠相容。來源下載、處理時間、結果回傳與儲存都有資源代價；不能假設免費 Cloudflare 靜態 hosting 可無限運行 native 引擎、轉碼或提供任意媒體流量。具體供應商、服務條件、資源上限與費用尚未選定，也未授權採購或部署。

### 選定 B 後的最小可觀察里程碑：網站一個受控來源的實際保存流程

先核定服務端資料流與預算，再交付**實際有後端的網站垂直切片**。在核准隔離／測試環境，以一個有權使用的合成媒體來源實際取回、處理、驗證及回傳檔案；使用者全程只用網站，不下載助手、不手動配置或清理。沒有營運環境授權時只能做有明確限制的測試原型，不能稱已上線服務。

驗收須涵蓋：提交前資料流說明、真實輸出 bytes／媒體驗證、瀏覽器保存及不支援保存 API 的路徑、取消 ACK、關頁／連線中斷仍有服務端限時停止及清理、保留期限清理、結果失效狀態、重試不重覆擴大工作、資源用量與上限拒絕。需有服務端清理前後證據、預算量測與不記錄原始媒體資料的檢查；不能只交有下載按鈕的靜態頁或 fake 成功畫面。此里程碑不代表真平台支援或可無限免費營運。

## C：純網頁、本地處理、縮小來源

### 第一次與再次使用

第一次：開啟網站 → 清楚看到支援來源範圍及「媒體在此瀏覽器處理」→ 貼一個支援連結、選種類、開始 → 產品取得可讀媒體並準備結果 → 由瀏覽器保存。再次使用重開網站即可；若來源不在支援範圍，解釋原因並提供原平台官方下載途徑，不暗中改走服務端或要求使用者關閉瀏覽器安全性。

來源應限於已驗證允許此網頁讀取、可取得必要媒體 bytes 的合作／自有來源或授權媒體連結；副檔名像 MP4 不代表可讀或真實格式安全。這會改變原本「多個大型平台作品頁」的產品覆蓋範圍，必須讓使用者接受縮小來源；M0 的八平台分類表不能直接成為此路線的下載支援清單。

### JS／Wasm 可以與不可以做什麼

JS／必要 Wasm 可在瀏覽器處理**已經合法取得且可讀**的 bytes，但不能替第三方回應加上 CORS 權限。這是由 [MDN CORS](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CORS) 的瀏覽器跨來源讀取規則推得的界線，不是只多加一個 JS 套件就能移除的限制。不能把 `no-cors`、播放器看得到畫面或網頁有登入狀態當作可任意讀取／輸出媒體的證據。

純 JS 不等於現有瀏覽器一定能編碼 MP3；若需 Wasm 編碼元件，必須先審核固定版本、hash、license、下載大小、記憶體與處理效能。候選的自動準備是網頁自行載入自己已審核的靜態元件、建立 worker、顯示真實準備階段；沒有 native 程式、外部安裝或 shell。尚未選定任何這類依賴，本輪也沒有下載。

### 清理、資料流與代價

`網站提供應用程式資產；來源／CDN → 使用者瀏覽器 → 本地處理 → 保存結果`。媒體內容不送到 GlossQuote 處理服務，但網站資產與來源下載仍用網路，原站仍可見請求；不能稱完全離線。

產品應釋放 worker、任務 buffer、暫時物件 URL，並管理任何自己建立的 session 儲存；不得把原媒體／歷史記錄永久留在 browser storage 作便利預設。完成輸出與瀏覽器暫存分開；取消需確認工作停止。異常關頁時不能保證 JS 最後清理程式一定執行，也不能宣稱已抹除瀏覽器／OS 快取。若採可持久暫存，須能在重開頁面時只識別並清除自己的過期工作；不要求使用者開開發者工具清資料。

瀏覽器保存同樣可能需要一次使用者操作或保存確認；不能保證跨瀏覽器記住任意資料夾權限。手機／低記憶體裝置、背景分頁、睡眠及儲存配額可能使大檔處理失敗；下載 JS／Wasm 也有準備時間和流量代價。首版上限須依實測縮小，不能把 M0 的 1 GiB／1 小時安全上限當作瀏覽器已能可靠處理的能力。必要功能不支援時顯示不可用原因，不能放仍可點擊的無效下載按鈕。

### 選定 C 後的最小可觀察里程碑：可讀來源到真實檔案的網頁切片

交付一個**可在核准隔離瀏覽器使用的真實網頁原型**，包含一個明列、授權可讀的合成媒體來源；實際取得 bytes、完成所宣稱的影片保存／音訊輸出並驗證結果。不下載或啟動助手，不要求手動解壓、設定或清暫存。

驗收須另設一個不允許跨來源讀取的來源，證明失敗時沒有假成功、隱藏代理或安全性繞過；測可用／不可用保存 API 的路徑、取消／重試、正常釋放資源、重開後自己殘留工作的處理、長內容及小裝置限制。量測載入大小、處理時間與記憶體／儲存預算，再公布較小的已測支援範圍。若做不到 MP3，只能回報該能力未過關，不用改副檔名冒充。此里程碑證明瀏覽器可讀來源的流程，不是大型平台頁面通用下載。

## 三路線共同的清理邊界

## 不另加「擴充套件就能免準備」的第四條路線

[Chrome Native messaging](https://developer.chrome.com/docs/extensions/develop/concepts/native-messaging)要求本機程式註冊 native host，供擴充通訊。由此推論，把助手藏在擴充後方仍需要額外準備與權限，不能當作普通網站可靜默執行本機程式的證明。本輪不新增擴充、native host、服務、OS 註冊或安裝流程；JS 語言的可用性也不提供這些權限。

## 選定後如何判定「真的省事」

下一個里程碑應產生所選路線的實際可操作產物，以及首次／再次使用紀錄、真實輸出與清理證據，不能再以 pure core 的測試數代替體驗。共同 PASS 要求是正常使用者不解壓、不配置 runtime／路徑、不跑命令、不找任務資料夾清理；必要的執行／保存授權被清楚解釋，沒有被掩蓋或偷跳過。

所有路線的真平台下載相容性、完整來源權限、品質／容器、bytes／時長／資源上限與故障恢復都須另有實際證據。選定 B 會改變本地處理與成本契約；選定 C 會改變來源範圍；選定 A 仍須證明單檔打包及生命週期。主代理須先將所選路線的新 scope、必要依賴／成本／權限及允許路徑具體化，才執行相依工作。
